# 16次元診断（喧嘩のときの動き方の診断）

恋人との喧嘩や気まずい場面での動き方を、8つの領域・16の傾向（各0〜100）で測り、
解釈パターン集（156本＋弱い版16本）から2〜4本を選んで人物像を示す診断ページです。
固定のタイプに分類せず、「両方強い」「どちらも弱い」も含めて読み取ります。

- デモ：https://kento20020.github.io/Seikakushindan/
- 判定はすべてブラウザ内の JavaScript で計算します。サーバーへの送信はありません（途中保存は端末の localStorage のみ）。
- ビルド不要。HTML＋ES モジュール＋CSS だけで動きます。外部依存は「設計」タブの Markdown 表示に使う marked（cdnjs、版固定）だけです。

## 画面

| タブ | 内容 |
| --- | --- |
| 診断 | 設問に答える。可変モード（「どちらでもない」が多い傾向は言い換えて追加で聞く）と表現A/Bを選べる。サンプル回答・P1〜P5・JSONの読み込みもここ |
| 結果 | 選ばれたパターン（主軸・補強・矛盾・地）、16傾向スコア（領域ごとに左右の棒）、回答品質・一貫性、追加で聞いた質問、AI統合用テキストのコピーと結果JSONの保存 |
| ロジック | 閾値、7状態の条件、発火した全パターン（部分条件ごとの余裕）、選択トレース（各ステップの候補・除外理由）、選択の制約 |
| 設問 | 72問＋対決16問の一覧（表現A/B・回答履歴・レビュー）、傾向→設問番号の対応、設問レビューの総評 |
| 設計 | `docs/design.md` を目次つきで表示 |

## 判定のしくみ

1. **16傾向スコア**：傾向ごとに基本4問（5件法）の平均を 0〜100 に換算する（(平均−1)÷4×100、6.25刻み）。
   一貫性8問はスコアに入れず、基本4問の平均との差（1.5以上で「不一致」）だけを報告する。
2. **対決**：Q73〜Q80 は同じ領域の2傾向の強制選択。(3−回答)×50 で +100（1側）〜−100（5側）。スコアには足さず、優勢の補完に使う。
3. **7状態**：領域ごとに A・B の水準と左右差で「明確に優勢／優勢だが他方も強い／両方強い／両方弱い／場面による」などを判定する。
4. **パターンの充足**：172本それぞれの条件について「余裕」（境目からの距離）を計算し、余裕≥0 なら発火。
   スコア＝重要度×充足度（充足度＝0.4＋0.6×min(1, 余裕÷尺度)）。
5. **選択**：スコアの高い順に、重なりを避ける制約つきで2〜4本を貪欲に選ぶ。
   形状は1本まで／同じ領域の基本解釈は1本／被覆領域の基本×0.5／包含除外／重なり×0.8／混雑×0.6／
   矛盾枠2本まで・2本目×0.7／4本目は矛盾を優先／採用下限＝0.35×最上位。
   役割は、主軸＝最上位の矛盾でないパターン、矛盾枠は「矛盾」、形状は「地（形状）」、残りは「補強」。

主な閾値（`js/engine.js` の `TH`）：

| 名前 | 値 | 意味 |
| --- | --- | --- |
| high | 67 | 「高」（4問平均3.75以上で実効） |
| low | 39 | 「低」（4問平均2.5以下で実効） |
| diff | 15 | 優勢に必要な左右差（実効18.75） |
| domMin | 50 | クロス・特殊の「優勢」に必要な最低値 |
| duelMax | 10 | 対決だけで補える優勢の余裕の上限（Likertと逆なら同じだけ減点） |
| shapeN | 12 | 形状判定に必要な傾向数（回答品質NGなら保留） |
| floorRatio | 0.35 | 採用下限の比率 |
| maxContra | 2 | 矛盾枠の上限 |

回答品質：基本64問の同じ回答の割合≤75% かつ SD≥0.75 で OK。NG のときは形状パターン（全体の形）を判定しない。

## 可変質問（アダプティブ）

5件法だと「3 どちらともいえない」に座り続けられるため、回答に合わせて質問を足します（`js/adaptive.js`）。

| 段階 | 内容 |
| --- | --- |
| 1 基本 | 72問（基本64＋一貫性8）を番号順に。開始時に選んだ表現（A：気持ち／B：行動）で出し、「別の言い方で聞く」でもう一方に切り替えられる。どちらの表現で答えたかを記録する |
| 2 追加 | 段階1のあとに計算。傾向ごとに基本4問の「はっきりした回答（3以外）」が3問未満なら、3（または未回答）だった設問を**まだ見せていない表現**で聞き直す。1傾向2問まで・全体16問まで。暫定スコアの左右差<15（優勢が未決）の領域の傾向を優先し、同じ優先度の中では1傾向1問ずつ配る。両方の表現を見せ済みの設問（と表現A/Bが同文の設問）は聞き直さない |
| 3 対決 | Q73〜Q80 の8問。「別の言い方で聞く」で variants[1] に切り替え（表現B開始なら variants[1] から） |
| 4 追加対決 | 段階1・2の暫定スコアで左右差<15、かつ対決が「どちらとも」か「やや」（回答が2〜4。未回答も含む）だった領域だけ、追加の対決場面 D1x〜D8x を聞く。最初の対決と平均する |

採点：基本4問の各枠は「はっきりした回答の最新 → なければ最新の回答（3）→ なければ未回答」。
追加の回答がはっきりしていれば枠の値を置き換え、また3なら3のまま。回答品質は段階1の基本64問だけで計算します。

可変モードをオフにすると固定80問（段階1＋段階3）になります（比較用）。
戻る・言い換え・回答の修正はすべて履歴（log）に残り、段階1を答え直すと追加質問は計画し直されます。

## ローカルで動かす

ES モジュールと `fetch` を使うため、ファイルを直接開かずに HTTP サーバー経由で開きます。

```sh
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```

## テスト

```sh
node tests/engine.test.mjs     # エンジンが Python 参照実装（tests/expected_v2.json）と一致するか
node tests/patterns.test.mjs   # 172本すべてに本文があり、docs/design.md と一致するか
node tests/adaptive.test.mjs   # 可変質問票（サンプル再現・追加質問の上限・言い換えの記録・固定80問）
```

## パターン本文を直すには

本文の原典は `docs/design.md` です。`js/data/patterns_text_*.js` はそこから自動生成したもの（生成スクリプト `tools/build_patterns.py`。`python3 tools/build_patterns.py` で再生成）なので、
直接書き換えずに次の順で直します。

1. `docs/design.md` の該当パターン（`### X12-1 …` など）の本文を直す
2. 生成スクリプトで `js/data/patterns_text_*.js` を作り直す
3. `node tests/patterns.test.mjs` で design.md と本文が一致することを確認する

見出し・条件・重要度など判定に使う構造は `js/data/patterns_meta.js` 側にあります。
閾値や選択ルールを変えたら `node tests/engine.test.mjs` が参照実装との差分を示します。

## GitHub Pages で公開する

1. このリポジトリを GitHub に push する（`main` ブランチ）
2. リポジトリの Settings → Pages を開く
3. Source を「Deploy from a branch」、Branch を `main`・フォルダを `/ (root)` にして Save
4. 数分後に https://kento20020.github.io/Seikakushindan/ で公開される

パスはすべて相対（`./js/app.js` など）なので、サブパスでもそのまま動きます。`.nojekyll` は Jekyll の処理を止めるために置いています。
