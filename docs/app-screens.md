## 4. 画面ごとの中身

### 4.1 ホーム（画像1・2）
- 上：小さな英字「HOME」を細い横線ではさむ。見出し「今日はこちらから」。3行の文「心が少し軽くなる、／あなたのための診断と相談。／いつでも、ここにいます。」。右に大きな絵（仮：傾向の絵。背景になじむよう縁をぼかす）
- **相談の欄（上）**：見出し「｜相談」、右に小さく「今の気持ちを整理する」。カード1枚（絵＋「今の気持ちを自由に書いて／アドバイスをもらえます。」＋丸い → ボタン）。押すと `#consult`
- **診断の欄（下）**。状態で中身を変える
  - 診断前：見出し「｜診断」。カード（絵＋小さな印「まだ診断していません」＋大きく「診断をはじめる」＋「8〜10分」＋ →）。押すと `#diagnose`
  - 途中（1問以上答えた）：「途中まで答えています（n問）」＋「続きから答える」→ 質問へ。小さく「最初からやり直す」
  - 診断後（画像2）：見出し「｜診断結果」、右に「もっとあなたを見る ›」（→ `#result`）。カード：小さく「あなたの主軸」、大きく**主軸の見出し**（パターンの headline）、その下に1〜2行（パターンの one）、区切り線、「主な傾向」と点つきの3行（強く出ている傾向。点の色は A 側＝くすんだ赤、B 側＝灰青）、丸い → ボタン（結果へ）。カードの下に「⟳ もう一度診断する ›」の行（画像1の形）
  - **相性の丸は出さない**（相手の診断が無いと出せない。決定 U29 の4）
- 下のタブ：ホーム（家）／履歴（紙）／マイページ（人）。いまの画面は、くすんだ赤の塗りの家と赤い文字

### 4.2 診断の開始画面（画像なし）
- 上：「←」と、中央に細い横線ではさんだ題「診断」
- 見出しと説明は今の開始画面の文（「左か、右か。迷ったら問題を変える」、2つの文から自分に近い方を選ぶ、問題を変えるは1問につき2回まで、64〜80問・8〜10分ほど）
- 主ボタン「診断をはじめる →」。途中の回答があれば「続きから答える」と「最初からやり直す」
- 可変モード（決めきれないところだけ追加で聞く）は、いつもオン。設問は既定の v3

### 4.3 診断の質問（画像3）
- 上：「←」（ホームへ。回答は保存されたまま）、中央に「診断」、右に「40 / 64」（答えた数 / 今の予定の数。追加の質問で予定の数は最大80まで増える）
- 細い進み具合の棒（くすんだ赤、残りは薄いベージュ）
- 小さな灰色の文：W の問は「この場面で」、X の問は「別々の場面の行動を比べて」
- 大きな明朝：W は場面の文（stem）＋その下に「取りやすいのはどちら？」（prompt）、X は「より自分らしいのはどちら？」など prompt
- 回答2枚を縦に並べる（PC でも縦）
  - 上＝左の回答：左にくすんだ赤の丸「←」、縦の細い線、文
  - 下＝右の回答：文、縦の細い線、右に灰青の丸「→」
- スワイプは **C「触った回答だけ」**（U28）：つかんだ回答だけが、その側へだけ動く。回答の外から始めたら向きの側の回答が動く。上＝問題を変える（使い切ったら答えずに進む）、下＝戻る（この2つは問いと回答のまとまりごと動く）。タップでも答えられる。キーボードは ← → Space
- 下：手のアイコンと「← →」、「左右にスワイプするか、／タップで選んでください」。「または」の区切り線。枠だけの丸いボタン「⟳ 問題を変える｜残り2回」（使い切ったら「答えずに進む」）。下線つきの文字リンク「中断して最初の画面へ（回答は保存されています）」
- 練習カード（1問目の前・採点しない）も同じ形。小さく「練習・結果には入りません」
- 追加の質問のとき（W追加・X追加）・差し替えたときの短い案内は、今の画面と同じ文を小さく出す

### 4.4 診断結果（画像6）
- 上：「←」、中央に「診断結果」、右に枠だけの丸いボタン「シェア」（共有のアイコン）
- 見出し「あなたを表す解釈」
- パターンのカード（主軸1＋補強・矛盾・地、合わせて2〜4枚。今の結果と同じ選び方）
  - 左に墨色の太い帯（主軸）。補強などは細い帯や色を変える
  - 上：墨色の丸い印「主軸」と、薄い印「基本解釈・領域1」（パターンの種類と領域）
  - 大きな明朝の見出し（headline）、その下に灰色で領域の名前
  - 区切り線、太字の1〜2行（one）、本文（detail。ゴシック）
  - 薄い箱「👆 違うと思う文があればタップ（もう一度タップで取り消し）」。本文を文ごとに区切り、タップした文に「違う」の印（取り消し線など、色だけに頼らない）
  - 区切り線、「場面例は、自分にありそうかどうかを選んでください」、場面例ごとに「ありそう」「なさそう」の丸い枠のボタン（押した方が塗られる。もう一度で取り消し）
  - 主軸以外のカードは、最初は見出しと1行だけ見せ、「詳しく」で開く
- 下に「8つの軸」：8領域それぞれの向き（A／B／両方／はっきりしない）を短く一覧（今の結果の値を使う）。傾向の絵がある傾向は小さく絵も
- 「違う」の印・ありそう／なさそうは、**端末の中だけ**に保存（§6.3）。どこにも送らない
- シェア：`navigator.share` で「主軸の見出し」と `app/` のリンクを送る。使えない端末ではリンクをコピーして「リンクをコピーしました」と出す（結果ごとのページはまだ無い）
- 結果が出たら、履歴に1件足す（§6.3）
- いちばん下に「もう一度診断する」「診断結果の一覧」（→ `#types`。§16）「診断結果の絵の一覧」（→ `#images`。§14）「ホームへ戻る」

## 11. 相談の続き（往復）（2026-10-18。決定 U30）

### 11.1 方針
- 定義書（Website `docs/22-consult-ux-flow.md` §3-6・§3-7、決定 0171）の「続き」の形を、**AI を使わず規則だけ**で作る（持ち主が案A を選んだ）
- **一手は今の判定（`js/consult/` の judge）で決め直す**（決定 U21：一手は判定表、AI は文章）。往復のたびに「状況の項目」を書き換えて判定をやり直し、**一手が変わったときだけ新しいカード**を出す。変わらないときは吹き出しで短く返す
- 文はすべて決まった文。自由に書いた文への返事は、AI の答えより硬くなる（AI をつなぐのは本番の Website のアプリ）
- 1回の相談は **10往復まで**（定義書のサブスクの上限。往復＝下の3つのボタンのどれかで1回）。上限に来たら「この相談はここまでです」と［新しく相談する］。安全の案内はいつでも出す

### 11.2 画面
```
（上）「いまの状況」の帯：状況の項目を3行で（たたむと1行）。［ちがうところがある］で直せる（直すと判定をやり直す）
（中）やりとり：最初のカード → 吹き出し（自分＝右、アプリ＝左）→ 一手が変わったときだけ新しいカード（前のカードはたたむ）
（下）3つのボタン：［相手の返事を貼る］［送った］［もう少し話したい］＋ 小さく「あと n 回」・「相談を終える」
```

### 11.3 状況の項目（今の判定の材料。`js/consult/needed.js` の ASKABLE）
| 項目 | 中身 |
| --- | --- |
| lastSender | 最後に送ったのはどちらか（自分・相手・どちらも送っていない） |
| partnerLast | 相手の最後の言葉の種類（無し・普通の話題・説明や言い返し・責める言葉・話し合いの提案・謝り・距離を置きたい・別れ話） |
| elapsed | どれくらい前か（3時間未満・3〜12時間・半日〜2日・3日以上） |
| selfLast | 自分の最後の送り方（無し・保留・謝り・仲直りの言葉・責める・説明） |
| ongoing・intent・selfTemp・goal・cause・repeat | 言い合いの最中か・自分がしたいこと・自分の熱さ・目指すこと・原因・くり返しか（書いた文と答えから。往復では基本そのまま） |

### 11.4 ボタンごとの動き

**［送った］**（AI を呼ばない。定義書のとおり「どうなった？」を聞くだけ）
1. 吹き出し「送ったんですね。どうなった？」と［返事が来た］［まだ来ない］［もう少し話したい］
2. 状況を書き換える：lastSender＝自分、elapsed＝3時間未満、partnerLast＝無し、selfLast＝今の一手から（下の表）。送った時刻を覚える
3. ［返事が来た］→［相手の返事を貼る］へ。［まだ来ない］→ 送った時刻から今までの時間で elapsed を自動で入れ、「送ってから◯時間ほどですね」と出して判定をやり直す（違えば4つから選び直せる）

| 今の一手 | 送ったあとの selfLast |
| --- | --- |
| 謝る（apology_partial・apology_full） | 謝り |
| 受け止める・短く気持ちを伝える・謝りを受け取る・普段に戻す・気持ちを聞く・電話や話す日の提案（acknowledge・short_feeling・accept_apology・restore_routine・ask_feeling・propose_call・propose_talk_plan） | 仲直りの言葉 |
| いったん止める・距離の受け止め・距離のお願い（pause_with_time・accept_space・request_space） | 保留 |
| 待つ一手（wait_until・self_calm・prepare_points） | 変えない（待つ一手で「送った」を押したときは、それでも送ったものとして「保留」） |

**［相手の返事を貼る］**
1. 貼る欄（相手から来た文をそのまま）。送る前に安全の言葉を毎回見る（相手の「死ぬ」などがあれば、最初と同じ安全の確認へ。決定 U22）
2. 貼った文を今の読み取り（`readText`）で読む。読みやすいよう `相手から「（貼った文）」と返事が来た` の形にして渡す。相手の言葉の種類（partnerLast）が読めなければ、1問だけ「相手の返事はどれに近い？」（今の足りない問と同じ選択肢）
3. **答え合わせの1行**（数字なし・「当たる」と言わない）。最初のカードの「相手はたぶん」と比べる

| 返ってきた種類 | 答え合わせの1行 |
| --- | --- |
| 普通の話題・説明・話し合いの提案・謝り（落ち着いた返事） | 「予想に近い返事です。」（ただし一手が「距離の受け止め」のときも同じ） |
| 責める言葉・距離を置きたい・別れ話（強い返事） | 「予想とはちがう返事でした。ここから一緒に考え直します。」。一手が「距離の受け止め」（accept_space）で距離・別れ話が来たときは「予想に近い返事です。」 |

4. 状況を書き換える：lastSender＝相手、partnerLast＝読めた種類、elapsed＝3時間未満、言い合いの最中ではない。［送った］を押していたら selfLast はそのまま
5. 判定をやり直す。**一手が変わったら新しいカード**、変わらなければ吹き出し「一手はこのままで大丈夫です。」と、今のカードの「送るならこの1通」への短い案内

**［もう少し話したい］**
1. 自由に書く欄。安全の言葉を毎回見る
2. 書いた文を読み、読めた項目だけ状況に重ねる（例「やっぱり謝りたい」→ したいこと＝謝る）
3. 吹き出しで短く受け止める（今の受け止めの決まった文のうち、気持ちの部分だけ。読めなければ「話してくれて、ありがとうございます。」）
4. **1つだけ聞く**：今の足りない問の仕組み（`nextQuestion`）で、一手が変わる項目があれば1問だけ。無ければ聞かない
5. 判定をやり直す。一手が変わったら新しいカード、変わらなければ「一手はこのままで大丈夫です。」

**「いまの状況」の帯**
- 状況の項目を3行で（今の「受け止めと状況の整理」の項目の言葉を使う）。［ちがうところがある］で項目ごとに直せる。直したら判定をやり直し、一手が変わればカード

**「相談を終える」**（定義書 §3-7）
- 「どうなった？」［仲直りできた］［まだ］［こじれた］（答えなくてもよい）。履歴に残す。［こじれた］のときは［新しく相談する］と「危ないときは」を出す

**次に開いたとき**
- 続きの相談が残っていれば、相談の入力の画面の上に「前の続き：（書いた文の冒頭）」［続きから］［新しく相談する］

### 11.5 記録（端末の中だけ）
- 1回の相談＝履歴の1件。やりとり（いつ・どのボタン・貼った文や書いた文・答え合わせ・その時の一手）と、今のカード、状況の項目を残す。読み込み直しても続きから
- 答え合わせの結果（近い・ちがう）も残す（定義書の「予想の当たりを記録」）
- 安全のカードは残さない（§10 のとおり）
- 履歴の詳細では、やりとりを吹き出しで読むだけの形で出す

### 11.6 作り
- 判定の書き換えは DOM の無い `app/js/consult_followup.js` にまとめ、最低限のテストを足す（答え合わせ・時間の区切り・状況の書き換え・一手が変わったか）
- 画面は `app/js/consult.js`・`app/js/consult_card.js`・`app/css/consult.css`。`js/`・`poc/` は直さない

### 11.7 作ってみて決めたこと（仕様からの違い）
- ［送った］で、自分のしたいこと（例：謝りたい）を「特になし」に、「言い合いの最中」を「止まっている」に戻す。戻さないと、謝る1通を送ったあとも「謝る」が出続ける
- 答え合わせは「今のカード」の一手（その「相手はたぶん」）と比べる（一手が変わったあとは、今のカードが予想の元になるため）
- 最初のカードの上の「読み取った内容」は「いまの状況」の帯に置き換えた（直す道を1つにする）
- 一手が変わらないときの吹き出しに時刻を書かない（あとで履歴を読んだときにずれないように）
- 往復の数え方：［送った］を押したとき、貼った返事・書いた文を送ったときに1回。［まだ来ない］・時間の選び直し・問への答え・状況の直し・カードの［ちがう］［もっと合わせる］は数えない
- 貼った返事に危ない言葉があれば最初と同じ安全の確認。「今、危ない」なら安全のカードを出し、その返事は記録しない
- 気づいたこと（判定表の動き。直していない）：「今の気持ち：まだ熱い」のまま［送った］を押すと、判定は「言い合いの最中」として扱い、「いったん止める」を送ったあとに「反論せず、まず受け取ったことだけ返す」が出る（3時間を過ぎると変わる）。判定表（`js/consult/`）を見直すかは別に決める

## 15. アプリとして使う（PWA。Android・iPhone）（2026-10-19。決定 U35・U37）

持ち主の依頼「PWA で使えるようにする。Android 用。どうしようもない箇所は言って」（U35）、続けて「今度はiPhoneでもPWAができるようにして。」（U37。iPhone の分は §15.10 にまとめた）。

### 15.1 何ができるか
- Android の Chrome で、新しい画面（`app/`）を**ホーム画面に追加（インストール）**できる。ホーム画面のアイコンから開くと、アドレスバーの無いアプリの形（standalone・縦向き）で開く。上の帯の色は地と同じ `#ECE6DE`
- アイコンを長押しすると「相談する」「診断」「診断結果」へ直に行ける（ショートカット。`./#consult`・`./#diagnose`・`./#result`）
- 一度開いた画面は端末に保存され、**つながらないときも開ける**（診断・結果・相談の判定は、もともと端末の中だけで動く）。開いたことのない画面は「インターネットにつながっていません」と出る（真っ白にはならない）
- 診断の結果・相談の履歴の保存は今までどおり端末の中（localStorage）。**Android では、ホーム画面のアプリと Chrome で同じ保存を使う**（どちらで答えても続きと結果が共通）

**iPhone でできること（U37）**
- Safari（と、iOS 16.4 からは Chrome・Edge・Firefox などのブラウザ）の共有ボタンから、**ホーム画面に追加**できる。アイコン（180×180）と名前「16次元診断」が出て、開くとアドレスバーの無いアプリの形で開く。マイページに手順を出す（§15.2・§15.3）
- 開くあいだの**起動画面**は、地の色 `#ECE6DE` に仮のアイコン（iPhone の縦向き12種の大きさ。§15.10）
- 上の帯は `default`（帯の文字は黒）
- service worker は Android と同じ（一度開いた画面はつながらないときも開ける）
- **ホーム画面のアプリと Safari で保存が別**（変えられない）。その代わり、マイページの「Safari とアプリのあいだで診断を移す」で、**引き継ぎのコード**（1行の文字列）をコピーして貼り付けると、診断（結果か途中の回答）と診断の記録・結果の印を移せる。**相談の履歴は移らない**

### 15.2 入れ方
**Android（Chrome）**
1. Chrome で https://kento20020.github.io/Seikakushindan/app/ を開く
2. 下のタブの「マイページ」→ 節「アプリとして使う」の［ホーム画面に追加する］を押す
   - ボタンが出ていないとき（Chrome がまだ「追加できる」と判断していない・一度断った など）は、Chrome のメニュー（︙）→「アプリをインストール」か「ホーム画面に追加」
3. 確かめの画面で「インストール」→ ホーム画面にアイコン「16次元診断」が出る
- LINE・Instagram などのアプリの中で開いたときは追加できない。右上のメニューから Chrome で開き直す

**iPhone（Safari）**（U37。iPhone には［ホーム画面に追加する］のボタンを出せないので、マイページには手順だけを出す）
1. Safari で https://kento20020.github.io/Seikakushindan/app/ を開く
2. 共有ボタン（四角に上向きの矢印）を押す
   - **iOS 26**：アドレスバーの「…」から「共有」に進むことがある
   - それより前：画面の下（または上）の共有ボタン
3. 一覧の「ホーム画面に追加」を押す（見当たらないときは、下にずらすか「さらに表示」）
4. **iOS 26**：「Webアプリとして開く」のスイッチ（既定でオン）をオンのまま「追加」。それより前の iPhone はスイッチが無く、そのまま「追加」
5. ホーム画面のアイコン「16次元診断」から開くと、アプリの形で開く
- 表示の名前（「…」「共有」「ホーム画面に追加」「Webアプリとして開く」「さらに表示」）は、英語の表示と出典からの推定を含む。**日本語の表示は実機で確かめる**（§15.8）

**iPhone（Chrome・Edge・Firefox など。iOS 16.4 から）**
1. そのブラウザで開く → 共有ボタン（Chrome はアドレスバーの右。見当たらなければメニューの「共有」）
2. 「ホーム画面に追加」→「追加」（iOS 26 では「Webアプリとして開く」はオンのまま）
- iOS 16.4 より前の iPhone では、Safari で開いて追加する

**iPhone の保存は Safari（ブラウザ）と別**：Safari で診断した結果は、ホーム画面のアプリには出ない。Safari のマイページで［引き継ぎのコードをコピーする］→ アプリのマイページで［Safari の診断を引き継ぐ］に貼り付けて［読み込む］（§15.3）

### 15.3 マイページの「アプリとして使う」（`app/js/mypage.js` の `appSection`）

| 状態 | いつ | 出す文 |
| --- | --- | --- |

| added | この画面から追加し終わった（このタブはブラウザのまま） | ホーム画面に追加しました。次からは、ホーム画面のアイコンから開けます。（右に「追加済み」） |
| prompt | Chrome が「追加できる」と知らせてきた（`beforeinstallprompt`） | ホーム画面に追加すると、アプリのように開けます。＋主ボタン［ホーム画面に追加する］。追加し終わったらトースト「ホーム画面に追加しました」 |
| line | LINE などアプリの中のブラウザ（UA に ` Line/`・Instagram・FBAN・TikTok・`; wv)` など。iPhone でも） | LINE などのアプリの中の画面からは追加できません。右上のメニューから Chrome（iPhone は Safari）で開き直してください。 |
| ios-other | iPhone・iPad の Safari 以外のブラウザ（iOS の UA に `CriOS`・`FxiOS`・`EdgiOS`・`OPiOS`。U37） | このブラウザの共有ボタンから、ホーム画面に追加できます。＋手順（下） |

| menu | それ以外（ボタンがまだ来ていない Android の Chrome・PC など） | Chrome のメニュー（︙）から『アプリをインストール』か『ホーム画面に追加』を選んでください。 |

- 状態は上から順に当てはめる：installed → added → prompt → line → ios-other → ios → menu。iPhone のホーム画面のアプリは installed
- **iPhone の手順（ios・ios-other。U37）**：番号つきの `<ol>`（`role="list"`）で3つ。共有ボタンは iOS の共有の形（四角に上向きの矢印）の小さな絵（`app/js/ui.js` の `icon("share-ios")`。読み上げは「四角に上向きの矢印の絵」）

  - ios-other：1 共有ボタン［絵］を押す（Chrome はアドレスバーの右。見当たらないときは、メニューの「共有」）／2・3 は Safari と同じ。注「iOS 16.4 より前の iPhone では、Safari で開いて追加してください。」
  - 手順の下に「ホーム画面のアイコン『16次元診断』から開くと、アプリの形で開きます。」
- **下の小さな注は端末で分ける**（`pwa.js` の `currentPlatform`／`isIos`）
  - iPhone・iPad：「iPhone では、ホーム画面のアプリと Safari で、診断の結果などの保存が別です。」（ios-other のときは「ホーム画面のアプリとブラウザ（Safari・Chrome など）で」）
  - それ以外（Android・PC）：今までどおり「Android では、ホーム画面のアプリと Chrome で、診断の結果などはこの端末の中で共有されます。」
- **Safari とアプリのあいだで診断を移す（U37）**：iPhone・iPad のときだけ、手順の下に小さなカード（`a-pwa-move`。ios-other の題は「ブラウザとアプリのあいだで診断を移す」）
  - ブラウザの側（ios・ios-other）：診断の結果か途中の回答か診断の記録があれば、［引き継ぎのコードをコピーする］。押すとクリップボードに書いてトースト「コピーしました。ホーム画面のアプリのマイページで貼り付けてください」。書けないときは、読むだけの欄にコードを出して選んだ状態にし、「コピーできませんでした。上の欄を長押しして『すべてを選択』→『コピー』を押してください。」。何も無いときは注「診断をすると、ここからアプリに移せます。」だけ
    - コードはマイページを開いたときに先に作っておく（押してからすぐクリップボードに書くため。Safari は、押したあと時間をおくと書かせないことがある）
  - ホーム画面のアプリの側（installed）：［Safari の診断を引き継ぐ］→ 欄（ラベル「引き継ぎのコード」）と［読み込む］。読めたら、この端末のアプリに診断（結果か途中）があるときだけ「この端末のアプリの診断を、貼り付けた診断に置き換えますか？」と確かめ、入れたらトースト「診断を引き継ぎました」→ 結果があれば `#result`、無ければ `#mypage`。読めないときはその場に「コードを読めませんでした。Safari でコピーし直して、もう一度貼り付けてください。」（貼り直すと消える。console.error は出さない）
  - どちらにも小さな注「コードには診断の回答が入っています。人に送らないでください。相談の履歴は移りません。」
  - 移す物と形は `app/js/transfer.js`（§15.10 の「引き継ぎのコード」）
- iPhone で line のとき（LINE の中）は、手順も引き継ぎも出さない（Safari で開き直してもらう）
- Android の振る舞い（prompt のボタン・added・トースト・節だけの描き直し・リスナーの片付け）は U37 で変えていない
- 状態が変わったら（ボタンが後から使えるようになった・追加し終わった・断った）この節だけ描き直す。マイページを離れたら知らせを受けない（render の片付けの関数でリスナーを外す）
- ホームには何も足さない（iPhone の案内も、引き継ぎもマイページだけ）
- added は仕様に無かった状態で、作ってみて足した（追加し終わってもブラウザのタブのままなので、menu の文に戻ると分かりにくいため）

### 15.5 service worker の方針（`app/sw.js`）
- **ネットにつながっていれば、いつも新しいもの（network-first）**。古い版が保存されたまま残って画面が壊れるのを防ぐため。つながらないときだけ保存した物を返す
  - 同じオリジンの GET（`app/` の HTML・CSS・JS、`../js/` の共有モジュール、`../img/` の絵など）：network-first。取れたら保存する
  - 画面の移動：network-first → 保存した同じページ → 保存した `./`（index.html。`app/` の入口への移動のときだけ）→ その場で作る「インターネットにつながっていません」の画面（くすんだ赤と生成り、［再読み込みする］）
  - Google Fonts：文字の形（fonts.gstatic.com）は保存した物を先に、CSS（fonts.googleapis.com）は保存した物をすぐ返して裏で新しくする。文字の形の保存は160件まで
  - それ以外のオリジン・GET 以外は触らない
- install のときに最低限の殻（`./`・index.html・マニフェスト・css の3つ・main.js・ui.js・pwa.js・home.js・アイコン 192）を先に保存する。1つ欠けても install は失敗させない
- 登録より前に読み込んだ物（`../js/` のモジュールなど）は service worker が見ていないので、`pwa.js` が「もう読み込んだ物の一覧」（ブラウザの読み込みの記録）を送り、service worker が保存する。これで最初に開いた直後から、つながらないときにも開ける
- 保存の名前に版の番号（`VERSION`）を入れ、新しい版が動き出すときに古い保存を消す。`skipWaiting()` と `clients.claim()` ですぐ入れ替わる。**`sw.js` の中身を変えたら `VERSION` を1つ上げる**
- 今の画面（`/#three` など）は範囲の外なので、service worker は効かない
- GitHub Pages は1つのファイルを10分ほどブラウザに置いておく設定なので、公開してから10分ほどは古いファイルが届くことがある（service worker が無いときと同じ）

### 15.6 止め方（不具合のとき）
1. `app/sw.js` の中身をすべて、`sw.js` の先頭のコメントにある数行（自分を登録解除して保存を消し、開いている画面を読み込み直す版）に差し替えて公開する。**ファイルの名前と場所は変えない**
2. ブラウザは `app/` を開くたびに `sw.js` の新しい版を確かめるので、利用者が次に開いたときに入れ替わり、そのあとは service worker なしのふつうのページとして動く
3. 止めたままにするなら、`app/js/pwa.js` の `register` の行も消す（残しても、止めた版が入るだけで害はない）
4. 直したら、新しい `sw.js`（`VERSION` を上げた物）に戻す

### 15.7 アイコンと名前（仮）の差し替え方
- **名前**：`app/manifest.webmanifest` の `name`・`short_name`（ホーム画面のアイコンの下に出るのは short_name。長いと切れるので、日本語なら6文字くらいまで）と、`app/index.html` の `apple-mobile-web-app-title`（iPhone）
- **アイコン**：`app/img/pwa/icon.svg`（any。そのまま見せる場所）と `icon-maskable.svg`（maskable。Android が丸・角丸に切り抜く。地は端まで塗り、大事な形は中央 80% の円の内側。iPhone のアイコンもこちらから作る）を差し替えて、リポジトリの根で
  ```sh
  NODE_PATH=$(npm root -g) node tools/make_pwa_icons.mjs
  ```
  （Playwright が要る。書き出したあと、maskable の絵が円の外にはみ出していないかを調べて知らせる）。そのあと `app/sw.js` の `VERSION` を1つ上げる
- **iPhone の起動画面**（U37）：アイコンの `icon.svg` を替えたら、起動画面も書き出し直す（引数なしで両方、`splash` で起動画面だけ、`icons` でアイコンだけ）
  ```sh
  NODE_PATH=$(npm root -g) node tools/make_pwa_icons.mjs splash
  ```
  道具が出す `<link rel="apple-touch-startup-image">` の行が `app/index.html` と同じかを見る（機種を足したときは道具の表 `SPLASH` と index.html の両方を直す。テストが本数・画素・重なりを確かめる）。iPhone は起動画面とアイコンを、ホーム画面に追加したときに取り込むので、**入れ終わった iPhone では、消して追加し直すまで古いまま**のことがある
- 入れ終わった端末のアイコンと名前は、Chrome がしばらくしてから（アプリを開いたときに確かめて）新しくする。すぐには変わらない
- マニフェストに `id` は書かない：Chrome は `id` をオリジンの根（`https://kento20020.github.io/`）から読むため、`"./"` と書くと kento20020.github.io 全体を指してしまう。書かなければ `start_url`（`/Seikakushindan/app/`）がそのまま id になる（Chromium で確かめた）。**入れたあとに `start_url` を変えると、別のアプリとして扱われる**

**iPhone の保存の事実**
- ホーム画面のアプリと Safari は、保存（localStorage・IndexedDB・service worker の保存など）が**別**。WebKit は仕様どおりの振る舞いとしている（出典3）。Safari 以外のブラウザから追加したアプリも同じく別
- Safari で開くサイトは、**Safari を使った日で数えて7日のあいだ、そのサイトを触らないと、スクリプトの保存（localStorage・IndexedDB・service worker の保存など）が消されることがある**。ホーム画面のアプリは Safari の外なので、アプリを使った日で別に数える（出典4）。つまり Safari だけで使っていると、しばらく開かないうちに診断の結果が消えることがある
- そのため、マイページに引き継ぎのコードを置いた（§15.3）。ログインで端末をまたいで保存するのは本番（Website のアプリ）の役目

**引き継ぎのコード（`app/js/transfer.js`）**
- 中身：`{ t: "seikaku16-move", v: 1, session, source, records, marks }`
  - `session`・`source`：今の診断（`js/ui/three_store.js` の保存 `seikaku16:three:v1` のうちこの2つだけ。1問以上答えたときだけ）
  - `records`：`app/js/local.js` の記録のうち kind が "diagnosis" のもの（日時 `at` は元のまま）
  - `marks`：その結果の key の印（「違う」の印・ありそう／なさそう）
  - **入れない物**：相談の記録・相談の下書き（`seikaku16:app:consult-draft` など。自由に書いた文なので）、テスト協力の記録（fb・fbMode）、5択版の保存（`seikaku16:v1`）
- 形：JSON → UTF-8 → 縮める（`CompressionStream("deflate")`。iOS 16.4 から）→ base64url → 頭に `S16Z-`。縮められない環境では縮めずに頭に `S16-`（どちらも読める）
  - 大きさ：ふつうの診断1回（80問）で、**縮めて約4,000字**（縮めないと約25,000字。2万字を超えるので縮めた）
  - `deflate-raw` ではなく `deflate`（zlib の形）にしたのは、確かめの数（Adler-32）が付いていて、途中の1文字が変わったコードも「読めない」にできるため（`deflate-raw` では、変わったまま読めてしまうことがあった）
- 読むとき：前後・途中の空白と改行を取り除き、頭の文字・base64url・縮めた物（戻すと 40万バイトを超えるなら止める）・JSON・中身の形（`Session3.fromJSON` で読めて結果まで作れる、記録は local.js の `validItem` を満たす診断の記録だけ、印は200字以下の key と中身）を確かめる。だめなら `{ ok: false }`（例外を外に出さない）。コードの長さの上限は 20万字
- 入れるとき：診断は置き換える（`adopt3`：テスト協力の記録と練習カードは消し、テスト協力モードとサブ画面はそのまま。設問の版は、URL の `?qv=` が無ければ移した診断の版に合わせる〔`restore3` と同じ決め方〕）。記録は結果の key が同じものを足さない（2回入れても増えない）。印はこの端末にまだ無い key だけ（ある印は上書きしない）
- コードはどこにも送らない（端末のクリップボードと画面の欄を通るだけ）。ただし中身は診断の回答なので、人に送らないよう注を出す
