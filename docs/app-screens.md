## 4. 画面ごとの中身

### 4.1 ホーム（画像1・2）
- 上：小さな英字「HOME」を細い横線ではさむ。見出し「今日はこちらから」。3行の文「心が少し軽くなる、／あなたのための診断と相談。／いつでも、ここにいます。」。右に大きな絵（仮：傾向の絵。背景になじむよう縁をぼかす）
- **相談の欄（上）**：見出し「｜相談」、右に小さく「今の気持ちを整理する」。カード1枚（絵＋「今の気持ちを自由に書いて／アドバイスをもらえます。」＋丸い → ボタン）。押すと `#consult`
- **診断の欄（下）**。状態で中身を変える
  - 診断前：見出し「｜診断」。カード（絵＋小さな印「まだ診断していません」＋大きく「診断をはじめる」＋「8〜10分」＋ →）。押すと `#diagnose`
  - 途中（1問以上答えた）：「途中まで答えています（n問）」＋「続きから答える」→ 質問へ。小さく「最初からやり直す」
  - 診断後（画像2）：見出し「｜診断結果」、右に「もっとあなたを見る ›」（→ `#result`）。カード：小さく「あなたの主軸」、大きく**主軸の見出し**（パターンの headline）、その下に1〜2行（パターンの one）、区切り線、「主な傾向」と点つきの3行（強く出ている傾向。点の色は A 側＝くすんだ赤、B 側＝灰青）、丸い → ボタン（結果へ）。カードの下に「⟳ もう一度診断する ›」の行（画像1の形）
  - **相性の丸は出さない**（相手の診断が無いと出せない。決定 U29 の4）
- 下のタブ：ホーム（家）／履歴（紙）／マイページ（人）。いまの画面は、くすんだ赤の塗りの家と赤い文字

### 4.2 診断の開始画面（画像なし）
- 上：「←」と、中央に細い横線ではさんだ題「診断」
- 見出しと説明は今の開始画面の文（「左か、右か。迷ったら問題を変える」、2つの文から自分に近い方を選ぶ、問題を変えるは1問につき2回まで、64〜80問・8〜10分ほど）
- 主ボタン「診断をはじめる →」。途中の回答があれば「続きから答える」と「最初からやり直す」
- 可変モード（決めきれないところだけ追加で聞く）は、いつもオン。設問は既定の v3

### 4.3 診断の質問（画像3）
- 上：「←」（ホームへ。回答は保存されたまま）、中央に「診断」、右に「40 / 64」（答えた数 / 今の予定の数。追加の質問で予定の数は最大80まで増える）
- 細い進み具合の棒（くすんだ赤、残りは薄いベージュ）
- 小さな灰色の文：W の問は「この場面で」、X の問は「別々の場面の行動を比べて」
- 大きな明朝：W は場面の文（stem）＋その下に「取りやすいのはどちら？」（prompt）、X は「より自分らしいのはどちら？」など prompt
- 回答2枚を縦に並べる（PC でも縦）
  - 上＝左の回答：左にくすんだ赤の丸「←」、縦の細い線、文
  - 下＝右の回答：文、縦の細い線、右に灰青の丸「→」
- スワイプは **C「触った回答だけ」**（U28）：つかんだ回答だけが、その側へだけ動く。回答の外から始めたら向きの側の回答が動く。上＝問題を変える（使い切ったら答えずに進む）、下＝戻る（この2つは問いと回答のまとまりごと動く）。タップでも答えられる。キーボードは ← → Space
- 下：手のアイコンと「← →」、「左右にスワイプするか、／タップで選んでください」。「または」の区切り線。枠だけの丸いボタン「⟳ 問題を変える｜残り2回」（使い切ったら「答えずに進む」）。下線つきの文字リンク「中断して最初の画面へ（回答は保存されています）」
- 練習カード（1問目の前・採点しない）も同じ形。小さく「練習・結果には入りません」
- 追加の質問のとき（W追加・X追加）・差し替えたときの短い案内は、今の画面と同じ文を小さく出す

### 4.4 診断結果（画像6）
- 上：「←」、中央に「診断結果」、右に枠だけの丸いボタン「シェア」（共有のアイコン）
- 見出し「あなたを表す解釈」
- パターンのカード（主軸1＋補強・矛盾・地、合わせて2〜4枚。今の結果と同じ選び方）
  - 左に墨色の太い帯（主軸）。補強などは細い帯や色を変える
  - 上：墨色の丸い印「主軸」と、薄い印「基本解釈・領域1」（パターンの種類と領域）
  - 大きな明朝の見出し（headline）、その下に灰色で領域の名前
  - 区切り線、太字の1〜2行（one）、本文（detail。ゴシック）
  - 薄い箱「👆 違うと思う文があればタップ（もう一度タップで取り消し）」。本文を文ごとに区切り、タップした文に「違う」の印（取り消し線など、色だけに頼らない）
  - 区切り線、「場面例は、自分にありそうかどうかを選んでください」、場面例ごとに「ありそう」「なさそう」の丸い枠のボタン（押した方が塗られる。もう一度で取り消し）

## 6. 作り（ファイルと決まり）

### 6.1 ファイル

```

app/js/main.js              ハッシュで画面を切り替える。各画面は render(root, route) を持ち、片付けの関数を返してよい
app/js/ui.js                小道具（h()、上の題、下のタブ、丸い矢印ボタン、トースト、アイコン）
app/js/local.js             端末の中の記録（§6.3）
app/js/home.js, account.js, history.js, mypage.js
```

### 6.2 使い回す仕組み（**中身の JS は直さない**）
- 診断：`js/ui/three_store.js`（`restore3`・`start3`・`answer3`・`swap3`・`skip3`・`back3`・`practice3`・`practicePending3`・`onChange3`・`store3`）。保存は今の画面と同じキー（`seikaku16:three:v1`）なので、どちらの画面で答えても続きと結果が共通
- スワイプ：`js/ui/swipe.js` の `attachSwipe`（`target`・`allow`）と `js/ui/swipe_variants.js` の `swipePart("c", …)`・`swipeAllows("c", …)`
- 結果の本文：`js/data/patterns*.js`（今の `three.js` の `patternCard` と同じ値）、`js/ui/labels.js`、`js/ui/result.js` の `byRole`、場面例 `js/data/scenes_v2.js`（`three_version.js` の `scenesFor`）
- 傾向の絵：`js/data/type_images.js`（`TYPE_IMAGES`・`isReady`・`heroTendency`・`domainTendencies3`）
- 相談：`poc/card/model.js`（DOM なし）と、その下の `js/consult/`。画面の流れは `poc/card/poc.js` を手本にする
- 理由：Website の試作は、このリポジトリの `js/` をそのまま写して使っている（Website の決定 0177）。中身を変えると、そちらにも影響する

### 6.3 端末の中の記録（`app/js/local.js`。キー `seikaku16:app:v1`）
- `loadRecords()` → `{ items: [...] }`（新しい順）
- `addRecord({ kind: "diagnosis"|"consult", at, title, sub, data })` → id。同じ診断結果は2回足さない
- `removeRecord(id)`、`clearRecords()`
- `getMarks(key)`・`setMarks(key, marks)`：結果の「違う」の印とありそう／なさそう（key は結果ごと）
- localStorage が使えないときも画面は動く（記録しないだけ）。どこにも送らない

## 11. 相談の続き（往復）（2026-10-18。決定 U30）

### 11.1 方針
- 定義書（Website `docs/22-consult-ux-flow.md` §3-6・§3-7、決定 0171）の「続き」の形を、**AI を使わず規則だけ**で作る（持ち主が案A を選んだ）
- **一手は今の判定（`js/consult/` の judge）で決め直す**（決定 U21：一手は判定表、AI は文章）。往復のたびに「状況の項目」を書き換えて判定をやり直し、**一手が変わったときだけ新しいカード**を出す。変わらないときは吹き出しで短く返す
- 文はすべて決まった文。自由に書いた文への返事は、AI の答えより硬くなる（AI をつなぐのは本番の Website のアプリ）
- 1回の相談は **10往復まで**（定義書のサブスクの上限。往復＝下の3つのボタンのどれかで1回）。上限に来たら「この相談はここまでです」と［新しく相談する］。安全の案内はいつでも出す

### 11.2 画面
```
（上）「いまの状況」の帯：状況の項目を3行で（たたむと1行）。［ちがうところがある］で直せる（直すと判定をやり直す）
（中）やりとり：最初のカード → 吹き出し（自分＝右、アプリ＝左）→ 一手が変わったときだけ新しいカード（前のカードはたたむ）
（下）3つのボタン：［相手の返事を貼る］［送った］［もう少し話したい］＋ 小さく「あと n 回」・「相談を終える」
```

### 11.3 状況の項目（今の判定の材料。`js/consult/needed.js` の ASKABLE）
| 項目 | 中身 |
| --- | --- |
| lastSender | 最後に送ったのはどちらか（自分・相手・どちらも送っていない） |
| partnerLast | 相手の最後の言葉の種類（無し・普通の話題・説明や言い返し・責める言葉・話し合いの提案・謝り・距離を置きたい・別れ話） |
| elapsed | どれくらい前か（3時間未満・3〜12時間・半日〜2日・3日以上） |
| selfLast | 自分の最後の送り方（無し・保留・謝り・仲直りの言葉・責める・説明） |
| ongoing・intent・selfTemp・goal・cause・repeat | 言い合いの最中か・自分がしたいこと・自分の熱さ・目指すこと・原因・くり返しか（書いた文と答えから。往復では基本そのまま） |

### 11.4 ボタンごとの動き

**［送った］**（AI を呼ばない。定義書のとおり「どうなった？」を聞くだけ）
1. 吹き出し「送ったんですね。どうなった？」と［返事が来た］［まだ来ない］［もう少し話したい］
2. 状況を書き換える：lastSender＝自分、elapsed＝3時間未満、partnerLast＝無し、selfLast＝今の一手から（下の表）。送った時刻を覚える
3. ［返事が来た］→［相手の返事を貼る］へ。［まだ来ない］→ 送った時刻から今までの時間で elapsed を自動で入れ、「送ってから◯時間ほどですね」と出して判定をやり直す（違えば4つから選び直せる）

| 今の一手 | 送ったあとの selfLast |
| --- | --- |
| 謝る（apology_partial・apology_full） | 謝り |
| 受け止める・短く気持ちを伝える・謝りを受け取る・普段に戻す・気持ちを聞く・電話や話す日の提案（acknowledge・short_feeling・accept_apology・restore_routine・ask_feeling・propose_call・propose_talk_plan） | 仲直りの言葉 |
| いったん止める・距離の受け止め・距離のお願い（pause_with_time・accept_space・request_space） | 保留 |
| 待つ一手（wait_until・self_calm・prepare_points） | 変えない（待つ一手で「送った」を押したときは、それでも送ったものとして「保留」） |

**［相手の返事を貼る］**
1. 貼る欄（相手から来た文をそのまま）。送る前に安全の言葉を毎回見る（相手の「死ぬ」などがあれば、最初と同じ安全の確認へ。決定 U22）
2. 貼った文を今の読み取り（`readText`）で読む。読みやすいよう `相手から「（貼った文）」と返事が来た` の形にして渡す。相手の言葉の種類（partnerLast）が読めなければ、1問だけ「相手の返事はどれに近い？」（今の足りない問と同じ選択肢）
3. **答え合わせの1行**（数字なし・「当たる」と言わない）。最初のカードの「相手はたぶん」と比べる

| 返ってきた種類 | 答え合わせの1行 |
| --- | --- |
| 普通の話題・説明・話し合いの提案・謝り（落ち着いた返事） | 「予想に近い返事です。」（ただし一手が「距離の受け止め」のときも同じ） |
| 責める言葉・距離を置きたい・別れ話（強い返事） | 「予想とはちがう返事でした。ここから一緒に考え直します。」。一手が「距離の受け止め」（accept_space）で距離・別れ話が来たときは「予想に近い返事です。」 |

4. 状況を書き換える：lastSender＝相手、partnerLast＝読めた種類、elapsed＝3時間未満、言い合いの最中ではない。［送った］を押していたら selfLast はそのまま
5. 判定をやり直す。**一手が変わったら新しいカード**、変わらなければ吹き出し「一手はこのままで大丈夫です。」と、今のカードの「送るならこの1通」への短い案内

**［もう少し話したい］**
1. 自由に書く欄。安全の言葉を毎回見る
2. 書いた文を読み、読めた項目だけ状況に重ねる（例「やっぱり謝りたい」→ したいこと＝謝る）
3. 吹き出しで短く受け止める（今の受け止めの決まった文のうち、気持ちの部分だけ。読めなければ「話してくれて、ありがとうございます。」）
4. **1つだけ聞く**：今の足りない問の仕組み（`nextQuestion`）で、一手が変わる項目があれば1問だけ。無ければ聞かない
5. 判定をやり直す。一手が変わったら新しいカード、変わらなければ「一手はこのままで大丈夫です。」

**「いまの状況」の帯**
- 状況の項目を3行で（今の「受け止めと状況の整理」の項目の言葉を使う）。［ちがうところがある］で項目ごとに直せる。直したら判定をやり直し、一手が変わればカード

**「相談を終える」**（定義書 §3-7）
- 「どうなった？」［仲直りできた］［まだ］［こじれた］（答えなくてもよい）。履歴に残す。［こじれた］のときは［新しく相談する］と「危ないときは」を出す

**次に開いたとき**
- 続きの相談が残っていれば、相談の入力の画面の上に「前の続き：（書いた文の冒頭）」［続きから］［新しく相談する］

### 11.5 記録（端末の中だけ）
- 1回の相談＝履歴の1件。やりとり（いつ・どのボタン・貼った文や書いた文・答え合わせ・その時の一手）と、今のカード、状況の項目を残す。読み込み直しても続きから
- 答え合わせの結果（近い・ちがう）も残す（定義書の「予想の当たりを記録」）
- 安全のカードは残さない（§10 のとおり）
- 履歴の詳細では、やりとりを吹き出しで読むだけの形で出す

### 11.6 作り
- 判定の書き換えは DOM の無い `app/js/consult_followup.js` にまとめ、最低限のテストを足す（答え合わせ・時間の区切り・状況の書き換え・一手が変わったか）
- 画面は `app/js/consult.js`・`app/js/consult_card.js`・`app/css/consult.css`。`js/`・`poc/` は直さない

### 11.7 作ってみて決めたこと（仕様からの違い）
- ［送った］で、自分のしたいこと（例：謝りたい）を「特になし」に、「言い合いの最中」を「止まっている」に戻す。戻さないと、謝る1通を送ったあとも「謝る」が出続ける
- 答え合わせは「今のカード」の一手（その「相手はたぶん」）と比べる（一手が変わったあとは、今のカードが予想の元になるため）
- 最初のカードの上の「読み取った内容」は「いまの状況」の帯に置き換えた（直す道を1つにする）
- 一手が変わらないときの吹き出しに時刻を書かない（あとで履歴を読んだときにずれないように）
- 往復の数え方：［送った］を押したとき、貼った返事・書いた文を送ったときに1回。［まだ来ない］・時間の選び直し・問への答え・状況の直し・カードの［ちがう］［もっと合わせる］は数えない
- 貼った返事に危ない言葉があれば最初と同じ安全の確認。「今、危ない」なら安全のカードを出し、その返事は記録しない
- 気づいたこと（判定表の動き。直していない）：「今の気持ち：まだ熱い」のまま［送った］を押すと、判定は「言い合いの最中」として扱い、「いったん止める」を送ったあとに「反論せず、まず受け取ったことだけ返す」が出る（3時間を過ぎると変わる）。判定表（`js/consult/`）を見直すかは別に決める
