# 相談モード（構想）

- 状態：構想（未実装）。2026-10-14 時点の検討メモ。行動と局面の表は同日に吟味（§3.8）
- 位置づけ：Phase 2（AI相談、ログインなし）で最初に出す機能。診断結果を加味して答えるが、診断なしでも使える
- 関連：AI に渡す情報の設計（3層キャッシュ、候補はコードが決める）は設計書 STEP5・STEP5-2、集客は [marketing-plan.md](marketing-plan.md)

## 0. コンセプト

「返信文を作る AI」ではなく、**「次の一手を決めるコーチ」**にする。

今の状況から「送る／待つ／話し合いを提案する」などの行動を1つ選んで理由を示し、送るなら文面、待つならいつまで待つかと待つ間にやることまで出す。

### 他のアプリとの違い

すでにある恋愛の返信支援アプリ（恋AI相談、モテリプなど。出典1・2）は、どれも「何と返すか」を出す道具で、必ず返信案を出す。喧嘩中に一番迷うのは「送るかどうか」と「いつ送るか」なので、

- **「今は送らないほうがいい」と言える**
- **その理由を、自分と相手の喧嘩タイプで説明できる**

ところを一番の違いにする。

## 1. 画面の流れ

| 段階 | 内容 |
| --- | --- |
| ① 入口 | 入り方は3つ：診断のあとに「この結果で相談する」／相談だけ／検索や場面ページから「この状況を相談する」 |
| ② 状況入力 | 自由に書く欄に加えて、タップで選べる項目：いつ喧嘩したか、最後に送ったのはどちらか、既読か未読か、相手の最後の一言、今の気持ち、**今回のゴール** |
| ③ 足りない情報だけ聞く | 判定に必要なのに分からない項目だけ、最大2問。例：「相手は喧嘩するとすぐ返すほう？ 時間を置くほう？」 |
| ④ 次の一手カード | おすすめの行動を1つ、理由、文面か待ち方、次にどうなったらどうするか |
| ⑤ 結果報告 | 「送った → 返事が来た／来ない」「待った → 相手から来た」を選ぶと、次の一手が出る。これを繰り返す |

### 今回のゴール

選択肢は4つ：

- 仲直りしたい
- 分かってほしい
- ちゃんと決着をつけたい
- 少し距離を置きたい

同じ状況でもゴールによって正しい一手が変わる。以前の構想にあった「主張を通す」も、ここで「分かってほしい」として扱える。

## 2. 次の一手カード

### 2.1 カードの例

> **おすすめ：今夜は送らない。明日の昼に短く1通**
>
> **理由（3行まで）**：状況、相手のタイプ、自分のタイプ
>
> **待つ間にやること**：送りたい文はここに「預ける」（明日見直す）
>
> **明日送るならこの文**：2〜3案（やわらかめ／まっすぐ）
>
> **避けたい言葉**：「なんで無視するの」「もういい」「既読ついてるよね」
>
> **その後**：返事が来たら → この順で／明日の夜まで来なければ → もう一度相談
>
> **確かさ**：相手のタイプが推定なので「仮」

### 2.2 行動の一覧（2026-10-14 吟味版）

カードに出す行動は、決まった選択肢の中から選ぶ。たたき台の10個から、分割・追加して16個にした（理由は §3.8）。

| ID | 行動 | 内容 | たたき台からの変更 |
| --- | --- | --- | --- |
| `wait_until` | 期限つきで待つ | 何も送らず、点検時刻まで待つ。**期限なしの「待つ」は出さない** | 旧 `wait`。期限を必須に |
| `pause_with_time` | 戻る時刻つきの保留宣言 | 「一回落ち着きたい。明日の夜に続きを話そう」。**戻る時刻を必ず入れ**、返事は求めない | 旧 `hold_message`。時刻を必須に |
| `self_calm` | 自分を落ち着かせる | 書き出す、下書きを預ける、寝る。相手には見えないので、単独では出さず `pause_with_time` か `wait_until` とセット | 単独で出さない条件を追加 |
| `acknowledge` | 受け止めて返す | 相手の言い分や気持ちを一文で受け取ってから、短く返す | 新規（旧「受け止めてから短く返す」を行動にした） |
| `ask_feeling` | 気持ちを聞く | 「さっきの件、どう感じてたか聞きたい」。問い詰めではなく1問だけ | 旧 `check_in` |
| `short_feeling` | 気持ちを短く伝える | 私を主語に1〜2行。「このままは嫌だな」 | そのまま |
| `apology_partial` | 部分的に謝る | 言い方や、傷つけたことだけを謝る。争点そのものは譲らない | 旧 `short_apology` を分割 |
| `apology_full` | きちんと謝る | 自分に非があるとき。何が悪かったか＋次どうするか | 旧 `short_apology` を分割 |
| `accept_apology` | 謝罪を受け取る | 受け取る＋気持ちを一言。まだ許せないなら「謝ってくれてありがとう。少し時間がほしい」 | 新規（旧「受け止める」を行動にした） |
| `restore_routine` | 普段のやりとりに戻す | 「おはよう」など。**相手が「関係を戻す」派で、原因が小さいときに限る** | 冷戦の「おすすめ」から「候補」に下げた |
| `propose_call` | 電話・対面を聞く形で提案 | 「電話していい？」と聞く。いきなりかけない。熱いうちは出さない | 条件を追加 |
| `propose_talk_plan` | 話し合いの段取りを提案 | いつ・どこで・何から（1つに絞る） | そのまま |
| `prepare_points` | 伝えることを整理する | 1つに絞る。私を主語に、出来事＋気持ち＋お願い | 新規（旧「下書きの整理」を行動にした） |
| `accept_space` | 距離の要求を受け入れる | 受け入れて、期限と連絡方法だけ確認する | 新規 |
| `request_space` | 期限つきで距離を求める | 「日曜の夜に連絡する。それまで考えさせて」 | 新規 |
| `safety` | 安全の確保と相談窓口 | 安全ゲート（§3.1）で出す | 局面から外し、ゲートに |

## 3. 判定の仕組み：行動を決めるのはプログラム、言葉にするのは AI

設計方針（キャッシュが効く、なるべく毎回同じ答え、診断結果が確実に反映される）に合わせて、3段階で動かす。

1. **状況の整理（AI）**：相談文を決まった項目に変換する。項目は §3.2 の「判定に使う項目」
2. **行動の判定（プログラム）**：まず安全ゲート、次に局面を決め、局面ごとの基本に、共通ルール・自分と相手のタイプ・ゴールで足し引きして、行動を1つ選ぶ。**同じ入力なら必ず同じ一手**になり、「なぜ待つのか」も説明できて、テストもできる
3. **言葉にする（AI、Claude Haiku 5.5）**：選ばれた行動の枠の中で、理由と文面を書く。AI が勝手に「とりあえず謝ろう」に流れることを防げる

### 3.1 安全ゲートと局面

**安全ゲート**は局面ではなく、どの局面でも最初に判定する。たたき台では8つの局面の1つ（`danger`）だったが、他の局面と同時に起こる（言い合いの最中に脅された、など）ので外に出した。

- サイン：暴力・物を壊す、脅し、監視（スマホの確認の強要、位置情報）、お金の支配、交友関係の制限、「別れるなら死ぬ」、本人の自傷の示唆
- 当てはまったら `safety` だけを出す。仲直りの助言は出さない。一人での直接対決や、別れ話の場の設定も勧めない

**局面**は9つ（たたき台の8つから `danger` を外し、分割・追加）。

| ID | 局面 | 判定の手がかり | たたき台との関係 |
| --- | --- | --- | --- |
| `heated` | 言い合いの最中 | やりとりが今続いている、対面で口論中、本人の温度が高い | そのまま |
| `waiting_partner` | 相手の返事待ち | 最後に送ったのは自分。半日未満 | 旧「返事が止まった直後」を「ボールがどちらにあるか」で定義し直した |
| `partner_msg` | 相手から連絡が来た（自分の番） | 最後に送ったのは相手で、まだ返していない。中身で4つ（a 普通の話題／b 説明・反論／c 責める・追撃／d 話し合いの提案） | 中身で分けた。自分が返していない場面もここに入る |
| `cold_war` | お互い止まっている | 半日以上どちらも送っていない、または自分が最後に送って半日以上返事がない | 期間（半日〜2日／3日以上）と「自分の和解の連絡が無視されているか」で分けた |
| `want_apologize` | 自分から謝りたい | 本人が謝りたいと言っている | 旧「謝りたい／謝られた」を分割 |
| `got_apology` | 相手から謝られた | 相手の最後のメッセージが謝罪 | 同上 |
| `space_or_breakup` | 距離を置く・別れ話が出た | 「距離を置きたい」「しばらく連絡しない」「別れる」（どちらから出たか） | 新規 |
| `before_talk` | 伝える前 | 不満を切り出したい、または話し合いの日が決まった | 定義を明確にした |
| `after_makeup` | 仲直り後のモヤモヤ | 喧嘩は終わっている。一回きり／同じ喧嘩の繰り返し | 2つに分けた |

### 3.2 局面の決め方（優先順）

局面どうしが重なるときは、上から順に最初に当てはまったものにする。

1. 安全ゲート
2. `space_or_breakup`（直近のやりとりに出ている）
3. `got_apology`（相手の最後が謝罪）
4. `heated`（やりとりが続いている、または本人の温度が高く、数時間以内）
5. 本人の意図が明確なとき：`want_apologize`、`before_talk`（ただし温度や時刻の共通ルールは引き継ぐ）
6. `partner_msg`（相手が最後で未返信。経過時間に関係なく）
7. `waiting_partner`（自分が最後、半日未満）／`cold_war`（それ以外で半日以上）
8. `after_makeup`

**判定に使う項目**（AI が相談文から抜き出す。分からなければ §1 ③で最大2問聞く）：

| 項目 | 値 |
| --- | --- |
| 最後に送ったのは | 自分／相手／どちらでもない（対面で終わった） |
| 経過時間 | 〜3時間／3時間〜半日／半日〜2日／3日以上 |
| 相手の最後のメッセージの種類 | 謝罪／普通の話題／説明・反論／責める・追撃／話し合いの提案／距離・別れ／なし |
| 自分の最後のメッセージの種類 | 保留宣言／謝罪／和解の連絡／責める・追撃／説明・反論 |
| 本人の温度 | 高い／落ち着いてきた／落ち着いている |
| 原因の自己評価 | 自分／相手／両方／分からない |
| 繰り返しか | 初めて／前にもあった |
| 場 | LINE などの文字／電話／対面・同居 |
| 時刻 | 深夜（0時〜6時）かどうか |
| ゴール | 仲直り／分かってほしい／決着／距離を置きたい |
| 危ないサイン | 有無と種類 |

### 3.4 共通ルール（どの局面にもかける）

| ID | ルール | 理由 |
| --- | --- | --- |
| R1 | **熱いうちは決着をつけない。** 本人か相手が熱いうちは、どのゴールでも先に冷やす。休憩は20分以上、遅くとも24時間以内に戻る | 気持ちが高ぶりすぎた状態（フラッディング）では話し合いが成り立ちにくい（Gottman） |
| R2 | **待つには期限。** `wait_until` は必ず点検時刻つき。相手が「追う」派なら、待つ前に保留宣言を1通 | 期限のない沈黙は、追う側の不安を強める |
| R3 | **黙って消えない。** 自分が返さない・離れるときは、戻る時刻を伝える。本人の温度が高いまま `partner_msg` になったら「ちゃんと返したいから、明日返すね」 | 黙り込み（ストーンウォーリング）は関係を壊しやすい4つの行動の1つ。戻る時刻を伝えると「拒絶ではない」と伝わる（Gottman） |
| R4 | **深夜ルール。** 0時〜6時は重い内容を送らない（短い保留やおやすみは可）。下書きを預けて朝に見直す | 夜は疲れていて感情的になりやすく、相手も受け止めにくい（経験則。お手本の相談で確かめる） |
| R5 | **1回に1つ。** 1通・1回の話し合いで扱う件は1つ | 話が広がると収拾がつかない（領域7） |
| R6 | **返事を求めない書き方を基本にする** | 相手の反応速度（領域2）を尊重する |
| R7 | **場の読み替え。** 対面・同居なら「送る」を「声をかける」に読み替える。同居の冷戦でも、挨拶など最低限の日常は保つ | たたき台は LINE だけを想定していた |
| R8 | **追うほど相手は離れる。** 自分が追う派・相手が距離を取る派のときは、連絡の回数を減らし、1通の質を上げる | 一方が詰め寄り、もう一方が引く「要求–撤退」のパターンは、関係の満足度の低さと結びつく |

### 3.5 避ける言葉（送る前チェックの判定 ID）

たたき台の「避ける」列は、行動と言葉が混ざっていたので分けた。言葉はプログラムで判定できる形にする。

| ID | 中身 | 例 | 関連 |
| --- | --- | --- | --- |
| `interrogate` | 問い詰め | 「なんで返さないの」「どうして〜しないの」 | — |
| `generalize` | 一般化 | 「いつも」「絶対」「普通は」 | 批判（Gottman） |
| `character` | 人格への批判 | 「あなたって〜な人」 | 批判（Gottman） |
| `past` | 過去の持ち出し | 「前も」「また」 | 領域7 |
| `ultimatum` | 最後通告 | 「もういい」「別れる」「勝手にして」 | — |
| `read_receipt` | 既読の指摘 | 「既読ついてるよね」 | — |
| `sarcasm` | 皮肉・見下し | 「さすがだね」「はいはい」 | 侮辱（Gottman） |
| `but_apology` | 「でも」付き・条件付きの謝罪 | 「ごめん、でも」「嫌な思いをしたならごめん」 | 防御（Gottman） |
| `long` | 長文 | 目安200字超（仮） | — |
| `multi` | 連投 | 返事が来る前の2通目以降 | 領域3 |
| `third_party` | 第三者の引用 | 「友達もおかしいって言ってた」 | — |

### 3.6 8領域が一手をどう変えるか

| 領域 | 判定への効き方 |
| --- | --- |
| 1 衝突への向き合い方（向き合う／距離を取る） | 相手が距離を取る派なら、話し合いは「日時を決めて後で」。向き合う派なら、長く黙ると「逃げた」と受け取られるので、保留宣言を早めに送る |
| 2 反応速度（即応／熟考） | 相手が熟考派なら、待つ時間を長めに見積もる（2時間返事がないのは普通）。自分が即応派なら、送る前に時間を置くチェックを強めにする |
| 3 不安時の確認行動（追う／待つ） | 自分が追う派なら、追いLINEを止める仕組み（§5）を出す。相手が追う派なら、こちらが黙ると相手の不安が増えるので、短くても返す |
| 4 感情表出（表に出す／内に置く） | 相手が内に置く派なら、「大丈夫」をそのまま信じず、話す場を作る。自分が表に出す派なら、文面のトーンを抑える |
| 5 納得の条件（理由・具体／気持ち・共感） | **文面の中身を決める。** 相手が理由派なら、何が悪かったかを具体的に。気持ち派なら、まず気持ちを受け止める |
| 6 話し合いの主導（主導する／調整する） | 相手が主導派なら、選択肢を渡して選んでもらう。調整派なら、こちらから日時の案を出す |
| 7 問題の広げ方（広げる／切り分ける） | 自分が広げる派なら、「今回の件だけ」に絞れているか確認する。相手が広げる派なら、過去の話に乗らずに今回の件に戻す |
| 8 修復の条件（解決する／関係を戻す） | 相手が解決派なら、再発防止の案を出す。関係を戻す派なら、普段のやりとりを先に戻す。`restore_routine` は相手が関係を戻す派のときだけ |

### 3.7 同じ状況でも相手のタイプで一手が変わる例

状況：夜23時、LINE で言い合いになり、相手の返事が既読のまま2時間止まっている。自分が最後に送った。自分は追う派で即応派。局面は `waiting_partner`。

| 相手のタイプ | 次の一手 |
| --- | --- |
| 熟考派で距離を取る派 | 今夜は追わない。「言いすぎたかも。明日の昼にちゃんと話したい」と1通だけ送り（戻る時刻を入れる）、返事は求めない。明日の昼まで待つ |
| 即応派で向き合う派 | この人が2時間黙るのは普段と違い、強く傷ついている可能性がある。今夜のうちに「さっきは言い方きつかった、ごめん。ちゃんと聞きたい」と短く送り、「電話していい？」と聞く |
| 分からない | 無難な保留宣言の1通（時刻入り）。そのうえで「相手がこっちのタイプなら」と2通りの一手を並べて見せる |

この違いが見えること自体が、診断を受ける理由になる。

### 3.8 吟味の記録：場面を当てはめた検証

たたき台と吟味版に、よくある12の場面を当てはめて比べた。

| # | 場面 | たたき台の結果 | 吟味版の結果 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 23時、LINE で言い合い。自分が最後に送り、相手（熟考・距離を取る）が2時間既読無視 | 保留宣言／待つ | `pause_with_time`（「明日の昼に話したい」と時刻入り） | △ 時刻がなかった |
| 2 | 相手が「もういい」と送ってきて、それきり | 当てはまる局面がない（「返事が止まった」は自分が待つ側の想定） | `partner_msg` c：気持ちを受け止める＋時刻つきの保留宣言 | × 分類できなかった |
| 3 | 翌朝、相手から「おはよう」だけ来た。自分は解決派 | 受け止めて短く返す | `partner_msg` a：応じる＋「夜ちゃんと話したい」 | △ 解決派の扱いがなかった |
| 4 | 3日間お互い無言。原因は自分の遅刻 | 普段のやりとりに戻す | `cold_war` 3日以上＋原因が自分 → `apology_full` ＋ `propose_talk_plan` | × 「なかったこと」にして悪化しうる |
| 5 | 相手から長文の謝罪。でも自分はまだ怒っている | 受け止める（許す前提） | `accept_apology`（「ありがとう。少し時間がほしい」）＋後日の話し合いを予約 | × 許すことを強いていた |
| 6 | 相手が「しばらく距離を置きたい」 | 当てはまる局面がない（冷戦扱いで電話の提案もありえた） | `space_or_breakup`：`accept_space`（期限と連絡方法だけ確認） | × 分類できず、逆効果の提案がありえた |
| 7 | 同棲中、口論のあと相手が部屋にこもった | 保留宣言を「送る」 | `heated` ＋ R7：声で「落ち着いたら夜ご飯のときに話そう」。ドアを叩き続けない | △ LINE しか想定していなかった |
| 8 | 自分が怒っていて、相手の LINE に返したくない | 当てはまる局面がない（利用者が黙る側の想定がない） | `partner_msg` ＋ R3：「ちゃんと返したいから、明日返すね」 | × 分類できなかった |
| 9 | 言い合いの最中、自分が明らかに言いすぎた | 落ち着く／保留宣言（候補に謝罪） | `apology_partial`（言い方だけ謝る）＋ `pause_with_time` | △ 謝る範囲があいまいだった |
| 10 | 毎月同じこと（連絡の頻度）で喧嘩になる | 話し合いの段取り | `after_makeup` 繰り返し：落ち着いた日にパターンの話。ふたりの診断結果（領域2・3）を材料にする | △ 繰り返しの扱いがなかった |
| 11 | 相手に「別れるなら死ぬ」と言われた | 危ない状況（検出できれば） | 安全ゲート：`safety` のみ。別れ話の進め方は指南しない | ○ 同じ（ゲートに移した） |
| 12 | 深夜2時、言いたいことを長文で書いた | 該当するルールがない | R4：下書きを預けて朝に見直し、`prepare_points` で1つに絞る | △ 時刻の考慮がなかった |

**結果**：たたき台は12場面中、分類できないものが3（#2・#6・#8）、逆効果になりうるものが2（#4・#5）、弱いものが6、問題なしが1（#11）。主な原因は次の4つ。

1. **局面の切り方の軸が混ざっていた**：時間（最中・直後・冷戦）、出来事（連絡が来た・謝罪）、段階（話し合いの前・仲直り後）、危険が同じ列に並び、重なりや抜けが出ていた → ボールの位置（最後に送ったのはどちらか）と経過時間で定義し直し、優先順を決めた。危険はゲートに出した
2. **利用者が「待たせる側」の場面がなかった**：相談するのは追う側とは限らない → `partner_msg` に自分が返していない場面を含め、R3 を追加
3. **行動が粗く、表の中に一覧にない行動があった**：「受け止める」「下書きの整理」が ID になっていなかった。謝罪が1種類だった → 16個に整理し、謝罪を部分／全体に分けた
4. **「避ける」に行動と言葉が混ざっていた** → 言葉は §3.5 の判定 ID にして、送る前チェックで機械的に判定できるようにした

**まだ残っていること**：半日・3日・200字・0時などの境目は仮。お手本の相談30〜50件（§8）で当てはめて調整する。

### 3.9 根拠にした知見

- **フラッディングと休憩**：高ぶりすぎた状態では話し合いが成り立ちにくい。休憩は「高ぶっている」と自分を主語にして伝え、20〜30分（長くても24時間）で戻る時刻を伝える。戻る時刻を伝えると、拒絶や見捨てるつもりではないと伝わる（出典3・4）→ R1・R3、`pause_with_time`
- **関係を壊しやすい4つの行動と、その代わり**：批判 → 穏やかな切り出し（私を主語に、具体的な行動とお願い）、侮辱 → 感謝と敬意、防御 → 一部でも責任を引き受ける、黙り込み → 休憩して落ち着く（出典4）→ §3.5、`apology_partial`、`prepare_points`
- **穏やかな切り出し**：最初の3分でその話し合いの行方がほぼ決まる（出典3）→ `before_talk`
- **要求–撤退のパターン**：一方が詰め寄り、もう一方が引くやりとりは、関係の満足度の低さと結びつく（出典5）→ R8。性別ではなく、領域3（追う／待つ）と領域1（向き合う／距離を取る）の組み合わせとして扱う

## 4. 相手のタイプの取り方

精度の高い順に3通り。

1. **相手も診断を受けている**：招待リンクで相手の結果を引き継ぐ（「相手に送る」機能とつながる）
2. **自分から見た相手を2択で答える**：判定に必要な領域だけを1タップで聞く。カードには「推定」と表示する
3. **分からない**：2通りの一手を出す。「相手のタイプを知ると一手が絞れます」と診断に誘う入口にもなる

**診断を受けていない人**も同じ考え方。相談の途中で、判定に効く領域だけ W 問題を2〜3問聞く。最後に「あと5問であなた向けの一手になります」と短い診断に誘導すれば、相談から診断へ人が流れる導線にもなる。

注意：三択の X 問題はその人の中での順位なので人と人では比べられない。相手との比較は W 側（8領域でどちら寄りか）で行う。

## 5. 「待つ」を支える機能（いちばんの差別化）

待つのが一番つらいのは、追う派と即応派の人。「待って」と言うだけでは実行されないので、待つための道具を付ける。

- **下書きを預ける**：送りたい文をここに書いて、送らずに預ける。翌朝 AI が読み直し、「この3行だけで十分」と短くした案を返す
- **待ち時間の表示とリマインド**：「明日12:00まで」と表示し、カレンダーに入れられるファイル（.ics）を作る。サーバーなしで作れる
- **送る前チェック**：自分で書いた文を貼ると、相手のタイプにどう届くかを予測する
  - 注意が必要な書き方：「いつも」「普通は」「もういい」、問い詰める疑問形、長文、過去の話を持ち出すこと
  - 短くした案を出す
  - 危ない言い回しはプログラムでも判定できるので、毎回同じ結果になる

## 6. 安全とプライバシー（必須）

- **危ないサインで安全モードに切り替える**：暴力、脅し、監視、お金の支配、「別れるなら死ぬ」などが出たら、仲直りのコツは出さない。安全の確保と相談窓口（DV相談ナビ #8008、DV相談＋ など）を表示する。設計資料 A-1〜A-3 の「安全シグナル一覧」を共通に使う
- **相手を操るテクニックは出さない**：罪悪感で動かす、無視で罰する、わざと不安にさせる、といった方法は出さない。「勝率」を前面に出すと関係を壊す方向の助言を求められやすく、口コミでの信頼にも響くので、見せ方は「**伝わる確率**」にする案
- **相手を断定しない**：「モラハラ」などと決めつけない
- **相談内容は保存しない**：初期はログインなしなので、端末の中だけに置く。改善のためにデータを集めるなら本人の同意を取る
- **相手の情報**：相談文には相手の情報が入る。スクショの読み込み（Phase 4）を入れるときには、未調査の「相手側の同意・削除要求」の方針が必要
- **18歳未満の扱い**：未決。安全モードの対応範囲と合わせて決める

## 8. 精度の上げ方

- **結果報告ボタン**：「やってみた → 良くなった／変わらない／悪化した」を残してもらう。これがそのまま判定表の改善データになる。テスト中は今のコピペで送る方式（[feedback-spec.md](feedback-spec.md)）を流用できる
- **お手本の相談30〜50件**：テスターの実際の状況を匿名化したものに、正解の一手を付ける。判定表やプロンプトを変えるたびに全件を流して確認する（毎回同じ答えが出る作りなので、この確認ができる）
- **「この一手、やる？」の評価**：正しさだけでなく、実際にやる気になるかを測る。待つ系の助言は正しくても実行されにくい
