# 相談モード（構想）

- 状態：構想（未実装）。2026-10-14 時点の検討メモ
- 位置づけ：Phase 2（AI相談、ログインなし）で最初に出す機能。診断結果を加味して答えるが、診断なしでも使える
- 関連：AI に渡す情報の設計（3層キャッシュ、候補はコードが決める）は設計書 STEP5・STEP5-2、集客は [marketing-plan.md](marketing-plan.md)

---

## 0. コンセプト

「返信文を作る AI」ではなく、**「次の一手を決めるコーチ」**にする。

今の状況から「送る／待つ／話し合いを提案する」などの行動を1つ選んで理由を示し、送るなら文面、待つならいつまで待つかと待つ間にやることまで出す。

### 他のアプリとの違い

すでにある恋愛の返信支援アプリ（恋AI相談、モテリプなど。出典1・2）は、どれも「何と返すか」を出す道具で、必ず返信案を出す。喧嘩中に一番迷うのは「送るかどうか」と「いつ送るか」なので、

- **「今は送らないほうがいい」と言える**
- **その理由を、自分と相手の喧嘩タイプで説明できる**

ところを一番の違いにする。

## 1. 画面の流れ

| 段階 | 内容 |
| --- | --- |
| ① 入口 | 入り方は3つ：診断のあとに「この結果で相談する」／相談だけ／検索や場面ページから「この状況を相談する」 |
| ② 状況入力 | 自由に書く欄に加えて、タップで選べる項目：いつ喧嘩したか、最後に送ったのはどちらか、既読か未読か、相手の最後の一言、今の気持ち、**今回のゴール** |
| ③ 足りない情報だけ聞く | 判定に必要なのに分からない項目だけ、最大2問。例：「相手は喧嘩するとすぐ返すほう？ 時間を置くほう？」 |
| ④ 次の一手カード | おすすめの行動を1つ、理由、文面か待ち方、次にどうなったらどうするか |
| ⑤ 結果報告 | 「送った → 返事が来た／来ない」「待った → 相手から来た」を選ぶと、次の一手が出る。これを繰り返す |

### 今回のゴール

選択肢は4つ：

- 仲直りしたい
- 分かってほしい
- ちゃんと決着をつけたい
- 少し距離を置きたい

同じ状況でもゴールによって正しい一手が変わる。以前の構想にあった「主張を通す」も、ここで「分かってほしい」として扱える。

## 2. 次の一手カード

### 2.1 カードの例

> **おすすめ：今夜は送らない。明日の昼に短く1通**
>
> **理由（3行まで）**：状況、相手のタイプ、自分のタイプ
>
> **待つ間にやること**：送りたい文はここに「預ける」（明日見直す）
>
> **明日送るならこの文**：2〜3案（やわらかめ／まっすぐ）
>
> **避けたい言葉**：「なんで無視するの」「もういい」「既読ついてるよね」
>
> **その後**：返事が来たら → この順で／明日の夜まで来なければ → もう一度相談
>
> **確かさ**：相手のタイプが推定なので「仮」

### 2.2 行動の一覧

カードに出す行動は、決まった選択肢の中から選ぶ。

| ID | 行動 | 内容 |
| --- | --- | --- |
| `wait` | 何もせず待つ | 期限つきで待つ |
| `hold_message` | 保留宣言だけ送る | 「落ち着いたら話したい」と送り、返事を求めない |
| `short_apology` | 短く謝る | 1〜2行 |
| `short_feeling` | 短く気持ちを伝える | 1〜2行 |
| `check_in` | 確認だけする | 「さっきの件、ちゃんと聞きたい」 |
| `propose_call` | 電話や会って話すのを提案する | 文字より声のほうがよいとき |
| `propose_talk_plan` | 話し合いの段取りを提案する | いつ、何から話すかを決める |
| `restore_routine` | 普段のやりとりに戻す | 「おはよう」などで日常を先に戻す |
| `self_calm` | 自分を落ち着かせる | 書き出す、寝る |
| `safety` | 安全の確保と相談窓口 | 危ないサインがあるとき（§6） |

## 3. 判定の仕組み：行動を決めるのはプログラム、言葉にするのは AI

設計方針（キャッシュが効く、なるべく毎回同じ答え、診断結果が確実に反映される）に合わせて、3段階で動かす。

1. **状況の整理（AI）**：相談文を決まった項目に変換する。項目は、今の局面、経過時間、最後に送ったのはどちらか、既読か、相手の最後の言葉の種類、何で揉めているか、ゴール、危ないサインの有無
2. **行動の判定（プログラム）**：局面ごとの基本点に、自分と相手のタイプとゴールで点数を足し引きして、行動を1つ選ぶ。**同じ入力なら必ず同じ一手**になり、「なぜ待つのか」も説明できて、テストもできる
3. **言葉にする（AI、Claude Haiku 5.5）**：選ばれた行動の枠の中で、理由と文面を書く。AI が勝手に「とりあえず謝ろう」に流れることを防げる

### 3.1 今の局面

| ID | 局面 |
| --- | --- |
| `heated` | 言い合いの最中 |
| `silence_after_fight` | 返事が止まった直後（〜数時間） |
| `cold_war` | 冷戦（半日〜数日） |
| `partner_reached_out` | 相手から連絡が来た |
| `apology` | 謝りたい、または謝られた |
| `before_talk` | 話し合いの前 |
| `after_makeup` | 仲直りしたけどモヤモヤしている |
| `danger` | 危ない状況 |

### 3.2 局面ごとの基本（たたき台・未検証）

| 局面 | 基本のおすすめ | 候補 | 避ける |
| --- | --- | --- | --- |
| 言い合いの最中 | `self_calm`、`hold_message` | `short_apology` | 長文、過去の話 |
| 返事が止まった直後 | `hold_message`、`wait` | `check_in` | 連投、問い詰め |
| 冷戦 | `restore_routine`、`short_feeling` | `propose_talk_plan`、`propose_call` | 既読の指摘、最後通告 |
| 相手から連絡が来た | 受け止めてから短く返す | `propose_talk_plan` | 放置、蒸し返し |
| 謝りたい／謝られた | `short_apology`／受け止める | `propose_talk_plan` | 「でも」付きの謝罪 |
| 話し合いの前 | `propose_talk_plan` | 下書きの整理 | 全部ぶつける |
| 仲直り後のモヤモヤ | `propose_talk_plan`（落ち着いたときに）、`self_calm` | `wait` | 蒸し返し |
| 危ない状況 | `safety` | — | 仲直りの助言 |

### 3.3 8領域が一手をどう変えるか

| 領域 | 判定への効き方 |
| --- | --- |
| 1 衝突への向き合い方（向き合う／距離を取る） | 相手が距離を取る派なら、話し合いは「日時を決めて後で」。向き合う派なら、長く黙ると「逃げた」と受け取られるので、保留宣言を早めに送る |
| 2 反応速度（即応／熟考） | 相手が熟考派なら、待つ時間を長めに見積もる（2時間返事がないのは普通）。自分が即応派なら、送る前に時間を置くチェックを強めにする |
| 3 不安時の確認行動（追う／待つ） | 自分が追う派なら、追いLINEを止める仕組み（§5）を出す。相手が追う派なら、こちらが黙ると相手の不安が増えるので、短くても返す |
| 4 感情表出（表に出す／内に置く） | 相手が内に置く派なら、「大丈夫」をそのまま信じず、話す場を作る。自分が表に出す派なら、文面のトーンを抑える |
| 5 納得の条件（理由・具体／気持ち・共感） | **文面の中身を決める。** 相手が理由派なら、何が悪かったかを具体的に。気持ち派なら、まず気持ちを受け止める |
| 6 話し合いの主導（主導する／調整する） | 相手が主導派なら、選択肢を渡して選んでもらう。調整派なら、こちらから日時の案を出す |
| 7 問題の広げ方（広げる／切り分ける） | 自分が広げる派なら、「今回の件だけ」に絞れているか確認する。相手が広げる派なら、過去の話に乗らずに今回の件に戻す |
| 8 修復の条件（解決する／関係を戻す） | 相手が解決派なら、再発防止の案を出す。関係を戻す派なら、普段のやりとりを先に戻す |

### 3.4 同じ状況でも相手のタイプで一手が変わる例

状況：夜23時、LINE で言い合いになり、相手の返事が既読のまま2時間止まっている。自分は追う派で即応派。

| 相手のタイプ | 次の一手 |
| --- | --- |
| 熟考派で距離を取る派 | 今夜は追わない。「言いすぎたかも。落ち着いたら明日話したい」と1通だけ送り、返事は求めない。明日の昼まで待つ |
| 即応派で向き合う派 | この人が2時間黙るのは普段と違い、強く傷ついている可能性がある。今夜のうちに「さっきはごめん、ちゃんと聞きたい」と短く送り、電話も提案する |
| 分からない | 無難な保留宣言の1通。そのうえで「相手がこっちのタイプなら」と2通りの一手を並べて見せる |

この違いが見えること自体が、診断を受ける理由になる。

## 4. 相手のタイプの取り方

精度の高い順に3通り。

1. **相手も診断を受けている**：招待リンクで相手の結果を引き継ぐ（「相手に送る」機能とつながる）
2. **自分から見た相手を2択で答える**：判定に必要な領域だけを1タップで聞く。カードには「推定」と表示する
3. **分からない**：2通りの一手を出す。「相手のタイプを知ると一手が絞れます」と診断に誘う入口にもなる

**診断を受けていない人**も同じ考え方。相談の途中で、判定に効く領域だけ W 問題を2〜3問聞く。最後に「あと5問であなた向けの一手になります」と短い診断に誘導すれば、相談から診断へ人が流れる導線にもなる。

注意：三択の X 問題はその人の中での順位なので人と人では比べられない。相手との比較は W 側（8領域でどちら寄りか）で行う。

## 5. 「待つ」を支える機能（いちばんの差別化）

待つのが一番つらいのは、追う派と即応派の人。「待って」と言うだけでは実行されないので、待つための道具を付ける。

- **下書きを預ける**：送りたい文をここに書いて、送らずに預ける。翌朝 AI が読み直し、「この3行だけで十分」と短くした案を返す
- **待ち時間の表示とリマインド**：「明日12:00まで」と表示し、カレンダーに入れられるファイル（.ics）を作る。サーバーなしで作れる
- **送る前チェック**：自分で書いた文を貼ると、相手のタイプにどう届くかを予測する
  - 注意が必要な書き方：「いつも」「普通は」「もういい」、問い詰める疑問形、長文、過去の話を持ち出すこと
  - 短くした案を出す
  - 危ない言い回しはプログラムでも判定できるので、毎回同じ結果になる

## 6. 安全とプライバシー（必須）

- **危ないサインで安全モードに切り替える**：暴力、脅し、監視、お金の支配、「別れるなら死ぬ」などが出たら、仲直りのコツは出さない。安全の確保と相談窓口（DV相談ナビ #8008、DV相談＋ など）を表示する。設計資料 A-1〜A-3 の「安全シグナル一覧」を共通に使う
- **相手を操るテクニックは出さない**：罪悪感で動かす、無視で罰する、わざと不安にさせる、といった方法は出さない。「勝率」を前面に出すと関係を壊す方向の助言を求められやすく、口コミでの信頼にも響くので、見せ方は「**伝わる確率**」にする案
- **相手を断定しない**：「モラハラ」などと決めつけない
- **相談内容は保存しない**：初期はログインなしなので、端末の中だけに置く。改善のためにデータを集めるなら本人の同意を取る
- **相手の情報**：相談文には相手の情報が入る。スクショの読み込み（Phase 4）を入れるときには、未調査の「相手側の同意・削除要求」の方針が必要
- **18歳未満の扱い**：未決。安全モードの対応範囲と合わせて決める

## 7. AI に出させる形式

行動、送る時刻、点検日時、確かさはプログラムが決め、AI は文章の部分だけを書く。

```json
{
  "phase": "silence_after_fight",
  "action": "hold_message",
  "timing": "now",
  "recheck_at": "明日 12:00",
  "reasons": ["…状況…", "…相手のタイプ…", "…自分のタイプ…"],
  "drafts": [{ "tone": "soft", "text": "…" }, { "tone": "direct", "text": "…" }],
  "avoid": ["なんで無視するの", "もういい"],
  "if_reply": "…",
  "if_no_reply": "…",
  "confidence": "provisional",
  "safety": null
}
```

## 8. 精度の上げ方

- **結果報告ボタン**：「やってみた → 良くなった／変わらない／悪化した」を残してもらう。これがそのまま判定表の改善データになる。テスト中は今のコピペで送る方式（[feedback-spec.md](feedback-spec.md)）を流用できる
- **お手本の相談30〜50件**：テスターの実際の状況を匿名化したものに、正解の一手を付ける。判定表やプロンプトを変えるたびに全件を流して確認する（毎回同じ答えが出る作りなので、この確認ができる）
- **「この一手、やる？」の評価**：正しさだけでなく、実際にやる気になるかを測る。待つ系の助言は正しくても実行されにくい

## 9. 最初に作る範囲（Phase 2、ログインなし）

### 最初に入れるもの

- 状況入力（自由文とタップ項目）
- 局面の判定と次の一手カード
- 文面案
- 送る前チェック
- 下書きを預ける機能
- 安全モード
- 診断結果の引き継ぎ（URL または localStorage）
- 相手のタイプの2択推定

### 後回しでよいもの

- スクショ読み込み（Phase 4）
- 履歴保存（Phase 3）
- 通知
- 相手招待との連動
- 音声（Phase 5）

### 技術面

- GitHub Pages には API キーを置けないので、Cloudflare Workers を中継に使い、回数制限をかける
- 判定表は画面側と Workers の両方で同じ JS を使う
- キャッシュは3層構造に当てはめる

| 層 | 入れるもの | 変わる頻度 |
| --- | --- | --- |
| 1層目 | 判定表、行動の一覧、16傾向の対応ガイド | ほぼ変わらない |
| 2層目 | 自分と相手の診断結果 | 人ごと |
| 3層目 | 今回の相談 | 毎回 |

## 10. 決めること

1. **ゴールの扱い**：仲直りを最優先にするか、「分かってほしい」「決着」まで同じ重みで扱うか（以前の「勝率」構想との関係）
2. **相手のタイプの取り方**：招待リンクを最初から入れるか、まずは2択推定だけで始めるか
3. **無料の範囲**：1回の相談で何往復まで無料にするか（収益モデル）
