## 2026-10-15：Fable の改善案を採用（[consult-answer-guide.md](consult-answer-guide.md) §1.4・§1.5）

| ID | 決めたこと | 理由 | 反映先 |
| --- | --- | --- | --- |
| D1 | **相手の情報に「出どころ」の段階を付ける。** 重みは、相手本人の診断（確度低の印なし）1.0、利用者の見立て（外から見える行動の2択）0.8、相手本人の診断で確度低 0.6、不明 0。本人の領域は、診断 1.0／確度低 0.6／本人が直した 1.0。**相手由来の補正は、重み1.0以外の部分の合計を ±30 までに抑える**（補正 ID `CAP`）。相手が「関係を戻す」派なら（見立てでも）、普段のやりとりに戻す行動の既定の減点 `RR` を外す | 見立てを 0.6 で扱うと、2択で聞いても一手がほとんど変わらず、聞く意味が薄い。一方で、当たりにくい情報が大きな補正を積み上げて一手を反転させるのは防ぎたい。**Fable の案は ±25 だったが**、±25 だと「見立てで関係を戻す派」でも冷戦で普段のやりとりに戻す行動が選ばれない（60 対 65）ので ±30 にし、`RR` を外した | [consult-scoring.md](consult-scoring.md) §1・§4・§9・§10・§12、`js/consult/` |
| D2 | **AI に渡す「人ごとの層」（2層目）を絞る。** 入れるのは、8領域の向き・確かさ・出どころ（確度低の理由）と、カップルの事実（相手が落ち着くまでの時間、電話と文字のどちらが話しやすいか、同居か、文体、相手の呼び方）。本人の主軸は、本人が「当たっている」と答えたときだけ見出しと注意点を1行ずつ。大きさは実測で、AI に渡す文字列が約500字（多いときで約630字）。**入れないもの**：X の数値、W の数、156パターンの本文、補強・矛盾・地のパターン、相手のパターン | 判定に使った情報と同じものだけを渡す。数字を渡すと AI が数字で語り、パターン本文を渡すと人物像で語り出す。主軸が自分の中心だと感じたテスターはいなかった | `js/consult/person_layer.js`、[consult-answer-guide.md](consult-answer-guide.md) §1.5 |
| D3 | **「勝率」「伝わる確率」の数字は出さない。** 出すなら、自分の文面の性質だけで決める「届きやすさ」3段階（届きやすい／ふつう／届きにくい）。見るのは、避ける言葉、長さ、戻る時刻の有無、返事の要求、第三者の引用、診断への言及、「勝率・論破・主導権・確率」の語。点数（数字）は出力しない | 相手に効く言い方の最適化（操る方向）に見えないようにする。点数は相手を測るものではなく、自分の書き方を点検するもの | `js/consult/draft_check.js`、[consult-mode.md](consult-mode.md) §6 |
| D4 | **相手の診断結果の使い方を決める。** (a) 一手と送り方を選ぶためだけに使い、文面に相手の結果は書かない（文面チェックで検出）、(b) 数字は出さない（D3）、(c) 相手の結果を招待で取り込むのは相手の同意があるときだけ。相手には「相談モードで使われる」と明示し、相手はいつでも外せる | 相手の同意なしに相手の結果が文面づくりに使われると、「相手を操るアプリ」になる | `js/consult/from_diagnosis.js`（同意がなければ取り込まない、外す）、`js/consult/draft_check.js`、[consult-mode.md](consult-mode.md) §6 |
| D5 | **本人が自分の結果を領域ごとに直せるようにする。** 「これは違う」で逆側にし、直した領域は重み 1.0（出どころ「本人の修正」）。今回は判定側の仕組みだけ作り、画面は相談モードの画面と一緒に作る | 自己評価との一致は厳しく数えて57%。外れた結果をそのまま相談に持ち込まない | `js/consult/from_diagnosis.js` |

## 2026-10-15：回答の層（[consult-ai.md](consult-ai.md)）

| ID | 決めたこと | 理由 | 反映先 |
| --- | --- | --- | --- |
| A1 | **今は AI を呼ばず、決まった文型でカードを作る。AI は設定（`aiEndpoint` か `?ai=`）だけでつながり、同じカードの形・同じ点検を通る。AI が失敗したら決まった文型に戻す。安全ゲートはいつも決まった文型** | 公開前に回答の質と安全を固定できる。AI の出力が崩れても利用者には必ずカードが出る。窓口の番号を AI に書かせない | `js/consult/respond.js`・`template_responder.js`・`ai_responder.js`・`card.js` |
| A2 | **決まった日本語は `texts.js` の1か所に置き、AI の1層目もここから作る。理由は補正 ID ごとの文型で作る**（guide 改善案8） | 決まった文型と AI の言い方がずれない。理由がぶれず点検できる | `js/consult/texts.js`・`prompt.js` |
| A3 | **判定の出力に `contributions`（一手の点の内訳）を足す。** 理由は「一手を押し上げた点」と「2位を押し下げた点」の大きいほうで選ぶ | `applied` には一手に関係しない補正も入るので、そのままでは理由を選べない | `js/consult/judge.js`、[consult-scoring.md](consult-scoring.md) §11 |
| A4 | **カードと文面では、夜中（0〜6時前）に当たる時刻を「明日の朝」と書く** | 23時の「3時間後」を「明日の2時ごろ」と相手に送らせない（R4 の考え方）。点検時刻の値そのものは変えない | `js/consult/timefmt.js` |
| A5 | **原因が分からないのに謝る一手（`confirm_cause`）は、文面を「きつかったと思うなら」の条件つきで出し、下の問いで確かめる** | 文面を出さないとカードが空になる。条件と問いがあれば、本人が思っていない謝罪を勧めない（guide §1.4 改善案3） | `js/consult/template_responder.js`・`context.js` |
| A6 | **`?ai=` は、`aiEndpointHosts` に載っているホスト（完全一致・https）だけ受け付ける。既定の一覧は空で、いまは `?ai=` を付けても無視する** | 細工したリンクを開かせるだけで、相談文が他人のサーバーに送られうる（以前は null なら https のどこでも通した）。サブドメインも別のホスト扱いにして、`workers.dev` のような共有ドメインを一覧に入れても全員分が通らないようにした。`aiEndpoint`（コードに書いた URL）は対象外 | `js/consult/config.js`、[consult-ai.md](consult-ai.md) §6・§9、`tests/consult_responder.test.mjs` |
| A7 | **相談（試作）画面 `#consult` を置く。** 危ないサインは1つでもあれば安全のカード。**相談文に自分を傷つける言葉（`SELF_HARM_RE`）があるときも、チェックがなくても安全のカードにする**（相手の脅しの言葉は誤検出が多いのでチェックのときだけ）。「一緒に住んでいる」はオンのときだけ渡し、オフは「していない」とは言い切らない。入力は `localStorage` の `consult-form-v1` だけに保存し、どこにも送らない | 本人が「死にたい」と書いたのに仲直りの文面を出すのは避けたい。誤って止まっても、安全のカードは落ち着いた作りで、入力を直せば戻る | `js/ui/consult*.js`・`css/consult.css`、[consult-ai.md](consult-ai.md)「画面」、`tests/consult_ui_state.test.mjs` |
