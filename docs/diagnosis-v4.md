# 24問版の診断（v4）

- 状態：**新しい画面（`app/`）の新しい診断の既定**（2026-10-20。決定 U42）。今の画面（`/#three`）は三択 v3 のまま
- もと：**持ち主の仕様書（2026-10-20）**。持ち主の言葉「質問は以下の24もんにする。80もんはすぐに治せるように置いておくが、こちらで実装。」
- この文書は、仕様書を実装の側から短くまとめたもの（仕様書の全文は写していない）。設問・選択肢・案内の文は仕様書のとおりで、正は `js/data/questions4.js`
- 精度を実測したものではない。24問にしたのは「1問で得られる情報を整理し、質問の重なりと比べる相手による影響を減らす」ため（仕様書の目的）。問いを減らした割合は精度の保ち具合を意味しない。画面にも「精度」「信頼度」「所要時間」は出さない

## 2. 8領域と A/B（変えない）

`js/data/questions.js` の `domains` のまま（例：領域1 衝突への向き合い方＝A 向き合う／B 距離を取る）。仕様書は D3 の A「追う」を「自分から確かめる」と表示してもよいとしているが、**表示も「追う」のまま**にした（ほかの画面〔#types・絵の一覧・ホーム〕とそろえるため。いちばん簡単な方）。

## 3. 問いと順番（`js/data/questions4.js`）

- R（個別評定）：`R1A`〜`R8B` の16問。文は1つずつ。選択肢は 0「まったく当てはまらない」／1「あまり当てはまらない」／2「ある程度当てはまる」／3「かなり当てはまる」／4「とても当てはまる」。2 は不明ではなく中くらい
- P（同じ場面での比較）：`P1`〜`P8` の8問。場面・A の文・B の文。共通の問い「この場面では、どちらが自分に近いですか？」。選択肢は「Aにかなり近い」（＋2）／「Aにやや近い」（＋1）／「どちらも同じくらい」（0）／「Bにやや近い」（−1）／「Bにかなり近い」（−2）。0 は優先の差が無いという答え（両方強い・両方弱いは R で分ける）
- どの問いにも別のボタン「判断できない（経験がない・思い浮かばない）」（保存は `null`）
- **出題順（固定）**：R1A, R2B, R3A, R4B, R5A, R6B, R7A, R8B, P1〜P8, R1B, R2A, R3B, R4A, R5B, R6A, R7B, R8A（同じ領域の A/B を続けて聞かない）
- A/B の表示の入れ替えはしない。答えるときに傾向の名前・点数・判定先は見せない
- 開始画面：題『24問で、ふたりのすれ違い方を整理する』、説明『普段の自分への16問と、場面ごとの8問です』、開始時の案内（今の恋人との最近の普段の自分を思い浮かべる・いなければ直近の交際・理想ではなく実際・途中で相手を変えない）。**時間は測っていないので分数は出さない**

## 4. 画面（`app/js/diagnose4.js`・`app/js/result4.js`。見た目は `app/css/diagnose.css` の `a-d4-`）

**質問**（`#diagnose/q`）

- 右上の数は「答えた数 / 24」（判断できないも答えに数える）。細い進み具合の棒
- R：小さく「普段の自分について」、大きく文、5つのボタン（ラベルは省かない）
- P：小さく「場面」、大きく場面、共通の問い、A・B の文（A・B の丸い印。読み上げは「A：」「B：」）、5つのボタン（A 側・B 側のボタンに薄い帯。文字にも A・B があるので色だけに頼らない）
- その下を点線で分けて「判断できない」（点線の枠・丸い形・「？」の印。5段階のボタンと形でも分かる。Tab で5段階の次に来る）
- 前に選んだ答えには「前に選んだ回答」の印（文字とチェック）
- 「前の質問に戻る」「中断してあとで続ける（回答は保存されています）」（→ 開始画面）
- 見た目の強さ：**問い（文・場面）がいちばん目立つ**（明朝・太字・大きく）→ 答えのボタン → 進み具合・戻る・中断・小見出しは薄い色（`--muted`。地の上で 4.85:1）。ボタンは高さ 52px（44px 以上）
- 描いた直後 0.28 秒は押し下げを受けない（同じ位置を2度押しして、次の問いまで答えてしまうのを防ぐ）

**結果**（`#result`）は §6。

## 5. 採点（`js/engine4.js`）

- 領域 d ごとに a・b・p を別々に持つ。**p を a・b に足さない**。全員の平均を 50 にそろえない。旧版の勝率・67/39・票の差・0.8 倍・confidence は持ち込まない
- 傾向の値 `traits[傾向].displayValue` は rating×25（0/25/50/75/100）の線形の表示で、確率・偏差値・百分位ではない
- 状態は仕様書のコードのまま（`classifyDomain`。上から順に最初に合うもの）：

| 条件（上から順） | 状態 |
| --- | --- |
| a・b・p のどれかが null（判断できない・未回答） | incomplete（埋め合わせない） |
| a ≤ 1 かつ b ≤ 1 | 6 |
| p×(a−b) < 0 かつ \|a−b\| ≥ 2（differentDirections） | 7 |
| a ≥ 3 かつ b ≥ 3 | p＞0 → 2、p＜0 → 4、p＝0 → 5 |
| p＞0 | a ≥ 3 なら（b ≤ 1 → 1、それ以外 → 2）、a＝2 → 1w、それ以外 → 7 |
| p＜0 | b ≥ 3 なら（a ≤ 1 → 3、それ以外 → 4）、b＝2 → 3w、それ以外 → 7 |
| p＝0 | 7 |

- differentDirections は「普段の傾向と特定の場面の選択がちがう」という表示用の印。不正・矛盾・精度の低さの意味ではない。追加の問い・減点はしない
- 評定の読み方（表示の区分）：0〜1＝少ない、2＝中くらい、3〜4＝多い

## 6. 結果の表示（`app/js/result4.js`）

- 題の下に主軸の領域の絵、見出し『今回の回答で目立つ傾向』と注記『今回の回答から見た傾向です。相手や状況によって変わることがあります。』
- **主軸と補足**：候補は状態 1・2・3・4・1w・3w の領域。選ばれた側の評定 → |p| → |a−b| の大きい順、同じなら領域の番号順。先頭が主軸、次の2つまでが補足（表示の並べ方で、統計的な重要度ではない）
  - 候補が無く状態5がある →『複数の傾向を持つ』（両方の当てはまりが多かった領域の名前を添える）
  - 完全に答えた領域はあるが候補も状態5も無い →『今回の回答では、片側に強く寄らない傾向』
  - 完全に答えた領域が0 → 総合の見出しを作らない。「判断できない項目があるため、領域ごとの傾向はまとめていません。分かっている回答だけを出しています。」と、相談への入口（［相談する］）。下の8つの領域で、答えた分の値を出す
- **状態の見出しと本文**（A・B は傾向の名前を「」で囲んで入れる）

| 状態 | 見出し | 本文 |
| --- | --- | --- |
| 1 | 「A」を選びやすい | 普段の回答では「A」の当てはまりが多く、今回の場面でも「A」を選ぶ傾向が見られます。 |
| 2 | 「A」を先に選び、「B」も持つ | 今回の場面では「A」寄りですが、普段の回答には「B」の傾向もあります。 |
| 3・4 | （1・2 の A と B を入れ替えた文） | |
| 5 | どちらの傾向もある | 普段の回答では、「A」と「B」の両方の当てはまりが多く、今回の場面では優先差がありませんでした。 |
| 6 | どちらも強くは当てはまらない | 今回の普段の自己申告では、「A」と「B」のどちらも当てはまりは少なめでした。 |
| 7 | 片側だけにはまとまらない | 今回の回答では、「A」か「B」のどちらか一方だけには整理しきれませんでした。（differentDirections のときだけ：普段の傾向と今回の場面で選んだ行動に違いがありました。一方だけに決めず、両方の回答を残しています。） |
| 1w・3w | 「A／B」をやや選びやすい | 場面の選択は「A／B」寄りですが、普段の当てはまりは中程度でした。 |
| incomplete | この領域はまだ分かりません | 判断できない項目があるため、この領域の組み合わせは判定していません。 |

- **8つの領域**：領域ごとに、状態の見出しと本文、**普段の当てはまり**（A と B を別々の行で。4つの目盛りの埋まった数＝0〜4 と、ラベル。判断できないは点線の目盛りと「判断できない」。片方からもう片方を引き算で描かない）、**場面での選び方**（両はしに A・B、5つの位置と●、下に「A寄り／ややA寄り／同程度／ややB寄り／B寄り」〔A・B は傾向の名前〕）
- **あわせて見られる傾向**（最大2）：既存の172パターンのうち basic 以外を、下の評価器で絞る。既存の文章（見出しも）は出さず「「X」「Y」と「Z」があわせて見られます。」の短い文と領域の名前だけ。重要度の大きい順・同じなら ID の順、同じ領域の集合は1件。主軸は上書きしない

| 既存の条件 | v4 での意味 |
| --- | --- |
| 優勢:t・cross の traits | 領域が完全、p が t の側、t の評定 3 以上かつ反対側以上、differentDirections でない（1w/3w は成り立たない） |
| 高:t／中:t／低:t | 評定 3〜4／2／0〜1。欠けた値の条件は成り立たない |
| specialA・specialB | すべての条件が成り立ち、関係する領域が完全（specialB の旧版の追加条件は引き継がない） |
| specialC | 上に加えて、関係する領域の p がすべて 0 |
| shape low・high・mid | 使わない |
| shape allA・allB | 8領域すべて完全で、すべてその側が優勢 |

- 構造上の ID（`result.patternIds`）：完全に答えた領域の `B{領域}-{状態}`（例 `B1-4`）と、組み合わせの ID
- **絵**（`app/js/axis_art.js` の対応のまま）：p＞0 で A寄り、p＜0 で B寄り、p＝0 でまんなかの絵。答えがそろわない領域は絵を出さない（番号の丸）。いちばん上の絵は主軸の領域の絵（主軸が無ければ出さない）
- 適合率・正確率・信頼度・パーセントは出さない。三択の結果と同じ物差しの時系列に混ぜない
- 下に［相談する］［もう一度診断する］［診断結果の一覧］［診断結果の絵の一覧］［ホームへ戻る］

## 7. 保存（`js/ui/four_store.js`。キー `seikaku16:four:v1`）

```json
{ "schemaVersion": 1, "diagnosisVersion": "v4", "questionBankVersion": "v4-24-2026-10-20",
  "questionOrder": ["R1A", "R2B", "…24個すべて"],
  "answers": { "R1A": { "status": "answered", "value": 3 }, "R2B": { "status": "unknown", "value": null } },
  "currentIndex": 0, "completed": false }
```

- 未回答＝answers にキーが無い。判断できない＝`status: "unknown"`・`value: null`。この2つを混ぜない
- 読むとき：NaN・範囲の外・整数でない・文字列の数・形の違う値は**未回答に戻す**（キーを消す）。版（schemaVersion・diagnosisVersion・questionBankVersion）が違えば読まない。completed は答えから決め直し、currentIndex は最初の未回答より先へ進めない
- 答えるたびに保存する。読み込み直すと同じ問いから続く
- 結果は保存しない。**読むたび・答えるたびに今の24問の答えから作り直す**（戻って答えを変えても古い結果を使わない）
- 結果の形：`traits`（傾向ごとの rating・displayValue）、`domains`（a・b・p・state・differentDirections・missing）、`primaryDomainId`、`supportingDomainIds`、`patternIds`、`diagnosisVersion`、`questionBankVersion`、`lead`、`combos`、`counts`。**confidence は作らない**
- v4 の保存が壊れていても、三択の保存（`seikaku16:three:v1`）や履歴（`seikaku16:app:v1`）は消さない（v4 の診断は無かったことにするだけ）
- 履歴（`app/js/local.js`）には今までどおり1件（題＝冒頭の見出し、key は `d4-` で始まる。`app/js/summary4.js`）
