# テスト協力モード（三択版）と集計ページ 仕様 v1（2026-10-09）

5人程度に三択版を受けてもらい、回答ログとフィードバックを「コピーして送ってもらう」だけで集める。サーバーは使わない。
受け取った側は集計ページ（`admin.html`）に全員分をまとめて貼り付けると、自動で集計・指摘が出る。

- 参加者側：三択タブの「テスト協力モード」（URL に `?fb=1` を付けると自動でON。例 `https://kento20020.github.io/Seikakushindan/?fb=1#three`）
- 集計側：`admin.html`（サイト内リンクは目立たせない。フッターに小さく）
- 受け渡し：本文テキスト（人が読める要約）＋機械用の1行（後述）。LINE・メール・ファイルのどれでもよい

## 1. 参加者の流れ（所要 本体10〜15分＋フィードバック5〜7分）

1. **開始**：同意の説明（回答は名前を伏せて扱う／パートナーのことは書かない／いつでもやめてよい）に同意チェック。参加者コード（ニックネーム可、1〜12文字。空なら英数4文字を自動生成し画面に表示）。再検査で同じコードを使ってもらう。
2. **診断**：通常の三択と同じ。テスト協力モードでは次を記録する。
   - 枠ごとの回答時間（カードが表示されてから回答まで。タブが裏に回っていた時間は除く）
   - 入力方法（swipe／tap／key）
   - カード下の小さな「一言」ボタン（答えにはならない）→ チップ4つ：`none` どちらも違う／`both` どちらも当てはまる／`scene` 場面が想像しにくい／`words` 言葉が分かりにくい。複数可。そのとき表示している設問に付く
   - 戻るの回数、全体の所要時間
3. **結果を見る前の質問（パート1）**：結果画面より先に出す（先に結果を見ると引っ張られるため）
   - **自己評価 self**：8領域それぞれ「A寄り／B寄り／両方強い／両方弱い／場面による」。コード `A` `B` `both` `neither` `depends`。各領域に下の説明文を添える
   - **実際の行動 act**：「最近の喧嘩や気まずくなった場面を1つ思い出してください」→ 8問、各「A／B／覚えていない・当てはまらない」。コード `A` `B` `na`
4. **ブラインド比較 blind**：自分の結果の上位3本（地＝形状は除く）の「見出し＋一言」と、比較用の別の結果（P1〜P5 のうち自分の選択と重なりが最も少ないもの）の上位3本を、名前を伏せて「A」「B」に並べる（順番はランダム）。「どちらがより自分に近い？」→ `own` / `decoy`
5. **結果＋カードごとの評価（パート2）**：通常の結果画面に、各パターンカードの下へ評価欄を足す
   - 当てはまり度 1〜5
   - 詳細説明の文（「。」で区切った各文）をタップして「違う」に印（複数可）
   - 場面例2つそれぞれ「ありそう／なさそう」→ `y` `n`
   - 主軸カードだけ「これはあなたの喧嘩の中心ですか」→ `yes` `partly` `no`
   - 結果の最後に自由記述「この結果に足りない、自分の特徴」
6. **振り返り（パート3）**
   - 迷った設問：自動で最大6問を選んで再表示（優先順：一言を付けた→差し替えた→回答時間が長い）。それぞれ理由チップ `none` `both` `scene` `words` `ok`（特に迷っていない）
   - 所要時間の体感 `short` `ok` `long`
   - スワイプの使いやすさ 1〜5（スワイプを1回も使っていなければ「使わなかった」`0` も選べる）
   - 自由記述（ひとこと）
7. **送信画面**：送信用テキストを表示し、ボタン3つ：「共有する」（`navigator.share` がある端末のみ）／「コピー」／「ファイルに保存（.txt）」。文字数を表示。送り先の案内文（「このテキストを全部、LINEかメールで送ってください」）。途中経過はすべて自動保存し、開始画面から「送信用テキストをもう一度表示」できる

### 自己評価に添える説明文（領域 → A／B）

| 領域 | A | B |
| --- | --- | --- |
| 1 衝突への向き合い方 | 向き合う：問題があれば、その場か早めに話して片付けたい | 距離を取る：熱くなったら一度離れて、落ち着いてから考えたい |
| 2 反応速度 | 即応：言われたらすぐ返す。考えながら話す | 熟考：一度持ち帰って、考えてから返す |
| 3 不安時の確認行動 | 追う：不安になったら連絡して確かめたい | 待つ：不安でも相手の反応を待つ |
| 4 感情表出 | 表に出す：嫌だった・傷ついたが顔や言葉に出る | 内に置く：その場では出さず、自分の中で整理する |
| 5 納得の条件 | 理由・具体：何が起きたか、なぜかが分かると納得できる | 気持ち・共感：気持ちを分かってもらえると納得できる |
| 6 話し合いの主導 | 主導する：進め方や結論を自分から出す | 調整する：相手に合わせて、落としどころを探す |
| 7 問題の広げ方 | 広げる：過去や関係全体の話につなげる | 切り分ける：今回の出来事だけに絞る |
| 8 修復の条件 | 解決する：原因と次からの対応が決まって終われる | 関係を戻す：普段どおりに戻れば終われる |

### 実際の行動の質問（act）

| 領域 | 質問 | A | B |
| --- | --- | --- | --- |
| 1 | その場面で、話し合いを切り出したのは？ | 自分から切り出した | 時間を置いた・自分からは切り出さなかった |
| 2 | 相手に何か言われたとき | その場で言い返した・答えた | すぐには答えず、あとで返した |
| 3 | 相手の反応が見えなくなったとき | 自分から連絡して確かめた | 連絡せず待った |
| 4 | 嫌だった・傷ついた気持ちは | 顔や言葉に出た | その場では出さなかった |
| 5 | 納得するために欲しかったのは | 何が起きたか・なぜかの説明 | 気持ちを分かってもらうこと |
| 6 | 話し合いの進め方は | 自分が仕切った・案を出した | 相手に合わせた |
| 7 | 話の範囲は | 過去の件や関係全体の話も出た | 今回の件だけを話した |
| 8 | 終わり方は | 次からどうするかを決めて終わった | 普段どおりに戻って終わった |

## 2. 送信用テキストの形式

```
【16次元診断 テスト協力】コード: ab12 ／ 2026-10-09 ／ 回答 72問 ／ 18分
主軸: X12-1「気づいたその場で、話を始める。」 ほか 3本
（ここから下の行も消さずに、全部送ってください）
16DFB1|1a2b3c4d|{...1行のJSON...}|END
```

- 機械用の行は `16DFB1|<crc32を8桁の16進>|<JSON>|END`。CRC は JSON 文字列（UTF-8）の CRC-32。
- 受け取り側は `/16DFB1\|([0-9a-f]{8})\|([\s\S]*?)\|END/g` で全件を拾い、JSON 部分の改行（`\r` `\n`）を取り除いてから CRC を検証し、`JSON.parse` する（メールの自動折り返し対策。JSON 自体は改行を `\n` にエスケープ済みなので、生の改行は全部ノイズ）。
- 実測で全96問の回答なら約4,900〜5,200文字、固定64問なら約3,700〜4,200文字（上限の目安 5,500）。LINE で送れない・途中で切れる場合は「ファイルに保存」した .txt を送ってもらう。

### JSON（v1）

```jsonc
{
  "v": 1,
  "app": "3choice-2026-10-08",      // QUESTIONS3.version
  "code": "ab12",
  "ts": "2026-10-09T12:34:56+09:00", // 診断の開始時刻
  "mode": "a",                        // "a" 可変 / "f" 固定64問
  "dur": 1080,                        // 全体の所要秒（裏に回っていた時間を除く）
  "back": 2,                          // 戻るの回数
  "ua": "m",                          // "m" スマホ（coarse pointer）/ "d" PC
  // 回答した枠（records() の順）。1枠1配列
  // [key, itemId, ans, lt, rt, pk, sw, ds, inp, flags, shown]
  //  key   : 枠の key（Session3 の step.key。例 WB-1-1 / XB-1-1 / WE-3-1 / XE-X5-1、末尾に + が付くことがある）
  //  itemId: 最後に表示した設問 id（W1-1, X1-0 など）
  //  ans   : "L" 左 / "R" 右 / "K" 答えずに進む
  //  lt,rt : 表示した左・右カードの傾向番号（QUESTIONS3.traitIndex の添字）
  //  pk    : 選んだ傾向の番号（K なら -1）
  //  sw    : その枠で使った差し替え回数
  //  ds    : 回答時間（0.1秒単位の整数）
  //  inp   : "s" スワイプ / "t" タップ / "k" キー / "x" 不明
  //  flags : 一言のコードを "+" で連結（無ければ ""）。差し替えた設問に付けた一言は shown 側に付ける
  //  shown : 差し替えた場合のみ。[[itemId, flags], ...]（差し替え前に表示した設問、古い順）。sw=0 なら省略
  "rec": [["WB-1-1", "W1-1", "L", 0, 1, 0, 0, 34, "s", ""], ...],
  // 結果（受け取り側で再計算もできるが、当時のロジックの結果として残す）
  "res": {
    "chosen": [["X12-1", "主軸"], ["X34-2", "補強"], ["X45-4", "矛盾"]],   // 役割順（主軸→補強→矛盾→地）。選ばれた順ではない
    "states": { "1": "1", "2": "3w", ... },     // 領域 → 状態コード（domainStates3）
    "lv": [75, 25, ...],                          // 16傾向の level（traitIndex 順、整数）
    "w": [[3, 1], [2, 2], ...]                    // 8領域の [a, b]
  },
  "fb": {
    "self": { "1": "A", "2": "depends", ... },
    "act":  { "1": "A", "2": "na", ... },
    "blind": { "pick": "own", "decoy": "P3", "order": "own-first" },
    // カード： [patternId, 当てはまり度1-5 or 0(未回答), [違うに印を付けた文の番号（0始まり。詳細説明を「。」で区切った順）...], [場面1, 場面2] ("y"/"n"/""), 主軸のみ "yes"/"partly"/"no" or ""]
    "cards": [["X12-1", 4, [2], ["y", "n"], "yes"], ...],
    "missing": "自由記述",
    "hard": [["W3-2", "scene"], ["X2-5", "ok"], ...],
    "time": "ok",
    "swipe": 4,
    "free": "自由記述"
  }
}
```

## 3. 集計ページ（admin.html）

受け取ったテキストをまとめて貼り付けると、次を表示する。すべてブラウザ内で処理（外部送信なし）。

1. **読み込み結果**：件数、CRC エラー・形式エラーの件数と該当箇所、重複（同じ code＋ts）は1件に。再検査は同じ code で ts が違うものとして組にする
2. **参加者一覧**：code／日時／モード／回答数／所要時間／戻る／差し替え／スキップ／左を選んだ割合（0.85以上か0.15以下は警告）／入力方法の内訳／主軸
3. **領域ごとの照合**（参加者×8領域）：診断の状態（`states`）と W の a:b、self、act を並べ、一致を色分け
   - 優勢の一致：状態 1・2・1w → A、3・4・3w → B、5・6・7 → 拮抗。self の A/B と act の A/B を比べる。self の `both`→状態5、`neither`→6、`depends`→7 と比べる
   - 集計：self との一致率、act との一致率（`na` は除外）を領域別・全体で
4. **ブラインド比較**：own を選んだ人数／全体
5. **カード評価**：パターンごとの当てはまり度、違うに印が付いた文（本文を表示して印の数を出す）、場面例の y/n、主軸の yes/partly/no、自由記述
6. **設問ごとの表**（W 48＋対決由来、X 全組）：表示回数、各側の選択数、差し替えられた回数、スキップ、平均・最大回答時間、一言のコード別件数、振り返りの理由。設問文も表示
7. **見直し候補（自動）**：次に当てはまる設問・領域を一覧化（5人規模の目安。疑う対象を探すためのもの）
   - 一言 `none`/`both`/`scene`/`words` が2人以上、または差し替えが2人以上、または振り返りで ok 以外が2人以上
   - 全員が同じ側を選んだ W（片側に偏った文の疑い）
   - 回答時間の中央値が全設問の中央値の2倍超
   - 領域で self と act の両方が診断と食い違った人が2人以上
   - 当てはまり度が平均3未満のパターン、違うに印が2人以上の文
8. **再採点**：`rec` から `scoreRecords3` → `select3`、`domainStates3` を現在のロジックで計算し、当時の結果（`res`）と違えば表示（閾値や設問を変えたあとの比較用）
9. **出力**：参加者×項目の CSV（コピー／保存）、設問ごとの CSV、「Claude に貼る用」Markdown 要約（上の2〜7を表と箇条書きで、本文の引用込み）をコピー

## 4. 実装時に決めたこと（2026-10-09）

- `dur` は質問画面が表示されていた時間だけを数える（裏に回っていた時間・パート1〜3は含まない）
- ブラインド比較のおとりは、参加者の上位3本（地を除く）と重なりが最も少ない P1〜P5。同数なら P1→P5 の順
- 振り返りの理由は必須なので `hard` の理由コードは空にならない
- 集計：実際の行動（act）の A/B は、診断が拮抗（状態5・6・7）の領域では「比べられない」として一致率から外す。自己評価（self）は spec どおり 5・6・7 と比べる
- 集計：再検査（同じコードで時刻が違う回答）は既定で集計から外し、1人1回として数える（切り替え可）。コードは大文字小文字・全角半角・空白を無視して照合
- `decodeAll` は次の開始タグをまたがない（途中で切れた1件が後ろの人の分を飲み込まない）
