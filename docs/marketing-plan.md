# 集客・マーケティング計画（構想）

- 状態：構想（未実装）。2026-10-14 時点の検討メモ
- 対象：16次元診断（三択版）と、今後の相談モード（[consult-mode.md](consult-mode.md)）
- 市場・プラットフォームの数字は 2026-10 時点で確認したもの（末尾の「出典」）。変わりやすいので、施策を始める前に見直す

---

## 0. 結論

SNS と Web検索という方向は正しい。ただ、この診断で一番効くのは、その2つの間にある「**結果がひとりでに広がる仕組み**」（結果カード、相手に送る、ふたり診断）。

| 優先 | 施策 | 効き始め | 理由 |
| --- | --- | --- | --- |
| ① | 診断の中に広がる仕組みを作る（結果カード、相手に送る、ふたり診断） | 公開直後 | 喧嘩には必ず相手がいる。自分が受けたら相手にも受けさせたくなるのは、普通の性格診断にない強み |
| ② | SNS（TikTok・Instagram 中心、Threads） | 1〜2か月 | あるあるで知ってもらう入口。手元のシーン文や質問がそのまま投稿の素材になる |
| ③ | Web検索（SEO と AI検索での引用） | 3〜6か月以降 | 「仲直り 方法」のような情報検索は AI の要約にクリックを取られている。狙うのは「診断」「タイプ名」「具体的な場面」の検索 |

SNS は火をつける役、検索は時間をかけて効いてくる土台、という分担にする。

---

## 1. 診断の中に広がる仕組み

### 1.1 診断が広がる理由

診断ポータルの運営会社が、累計1億回以上の利用データから、シェアされる診断の特徴を挙げている（出典4）。

- 自分を一言で表せる（例：「優しいというより、断れない人」）
- 自虐や弱みを含む（褒めるだけだと自慢に見えて広がりにくい）
- 結果が1枚の画像で分かり、スマホで崩れない
- 友達との会話が生まれる（1人で読んで終わる設計は広がりにくい）
- 質問が短く、短時間で終わる

### 1.2 喧嘩診断ならではの強み

「私は時間を置きたい派だった。あなたは？」と、相手に送る理由が最初からある。相手が受ければ、ふたりの組み合わせ結果が出る。この招待の連鎖が、利用者が育つ一番の源になる。

数字のイメージ（仮の数字）：完了した100人のうち30人が恋人や友達に送り、そのうち40%が受けると、新しい利用者は12人。この「1人が何人連れてくるか」（k）を 0.1 から 0.3 に上げるほうが、投稿数を倍にするより効くことが多い。

### 1.3 作るもの（サーバーなしで作れる）

| 項目 | 内容 | 補足 |
| --- | --- | --- |
| 結果カード画像 | ストーリーズ用の縦長（9:16）と、X・LINE 用の正方形（1:1）を、スマホの中で作って保存できるようにする | canvas で生成。キャラクター（パーツ式）を載せる |
| 相手に送るリンク | 結果を URL に入れて送る。相手が受けると、ふたりの組み合わせがスマホの中で表示される | GitHub Pages のまま作れる。比較は W 側（8領域でどちら寄りか）で行う（下の注意） |
| 結果ごとのリンクプレビュー | 今は `#three` のような切り替え方なので、X や LINE に貼るとどの結果も同じ見た目になる。主軸パターンごとに個別の静的ページ（専用の og:image 付き）を書き出す | ビルドスクリプトで生成 |
| 一言ラベル | 今の結果は2〜4パターンの組み合わせで、「一言で何タイプ？」に答えられない。シェアされるのは一言 | 保留中の「主軸の名前付け」と一緒に決める |
| シェアボタン | X（投稿画面を開く）、LINE（送る）、Instagram（画像保存からストーリーズへ） | — |

**比べ方の注意**：三択の X 問題（別の領域の文同士を比べる問題）は、その人の中での順位にすぎず、人と人では比べられない。ふたりの比較は、W 問題で出る「8領域それぞれでどちら寄りか」で行う。

## 2. SNS 運用

### 2.1 チャネルごとの評価

| チャネル | 評価 | 使い方 |
| --- | --- | --- |
| TikTok | ◎ | 国内の月間利用者 4,200万人（TikTok とTikTok Lite の重複を除く。2025-11 発表、出典3）。あるあるの短いドラマや文字だけの動画。「返信が止まったら：A 追いLINE、B 寝る」とコメント欄で投票させる形が、2択の質問と相性がよい |
| Instagram | ◎ | リールで知ってもらう、漫画のカルーセルで保存してもらう、ストーリーズで結果をシェアしてもらう。ストーリーズの2択アンケートは W 問題をそのまま使える |
| Threads | ○ | 国内の利用時間は前年比 +130%（2.3倍）。日本は文字だけの投稿の割合が世界平均より高く、表示の半分以上が返信から生まれている（日本はさらに高め）（2026-07 発表、出典5・6）。恋愛の悩みや喧嘩の愚痴は会話になりやすく、返信を次の投稿ネタにも使える |
| X | △ | 診断結果を投稿する文化があるので、シェアの受け皿としては必要。恋愛と男女の話題は炎上しやすいので、積極的な運用はしない |
| LINE | ○（後で） | 喧嘩の現場そのもの。キャラクターの「仲直りスタンプ」を出せば、喧嘩のたびにブランドが目に入る。スタンプは個人でも出せる |
| YouTube ショート | ○ | TikTok 用の動画を流用 |

**1人で回す場合**：同じ縦動画を TikTok と Instagram の両方に出し、文字だけで軽い Threads を加える。X は結果の受け皿だけにする。

### 2.2 手元にある素材の使い道

| 手元の素材 | ファイル | SNS での使い方 |
| --- | --- | --- |
| W 問題（同じ場面で A か B か） | `js/data/questions3_v2.js` | 「どっち派？」の投票や動画 |
| 書き直したシーン文（76場面） | `js/data/scenes_v2.js` | 短いドラマや漫画の台本 |
| 156パターンの解説 | `docs/design.md` | 「〇〇派の取扱説明書」のカルーセル |
| 16の傾向 | `js/data/questions.js` の domains | 16本のシリーズ企画 |
| パーツ式のキャラクター | （制作中） | 顔出しなしで見た目をそろえる |
| 回答の集計 | （利用者が増えてから） | 「◯人中◯人が B」というデータ投稿 |

### 2.3 投稿の5本柱と配分

1. あるあるへの共感
2. どっち派の投票
3. タイプ解説
4. ふたりの組み合わせ
5. 仲直りのコツ（保存されやすい）

配分の目安：拡散用の①②が6割、診断へ誘う③④が3割、信頼と保存用の⑤が1割。

### 2.4 週の型（例）

| 曜日 | 内容 | 主なチャネル |
| --- | --- | --- |
| 月 | あるある動画 | TikTok / リール |
| 火 | どっち派の投票 | Threads |
| 水 | 漫画カルーセル | Instagram |
| 木 | どっち派動画 | TikTok / リール |
| 金 | タイプ解説 | Instagram / Threads |
| 土 | 2択アンケート | Instagram ストーリーズ |
| 日 | 振り返り（数字を見る） | — |

### 2.5 最初の30本は実験

- 冒頭の一言だけを変えて比べる
- 見る数字：最初の2〜3秒で離れなかった割合、最後まで見た割合、保存、シェア、プロフィールへの移動
- 当たった型を見つけてから量産する

冒頭の一言の例：

- 「喧嘩した夜、返信が止まったら：すぐ電話する人／朝まで待つ人」
- 「『もういい』の本当の意味、タイプで違います」
- 「謝ってほしい人と説明してほしい人が喧嘩するとこうなる」
- 「話し合いを"今"したい人 vs "落ち着いてから"の人」

## 3. Web検索（SEO と AI検索）

### 3.1 今の状況

- 情報を調べる検索では、AI の概要が出ると1位のページのクリックが約58%減り、2位でも約51%減っている（Ahrefs が30万キーワードで 2025-12 と 2023-12 を比較。デスクトップ。出典1・2）
- 日本語でも Google の AI モードが 2025-09 から使える（出典7）
- 「彼氏 喧嘩 仲直り」のように文章で答えが済む検索は、上位を取ってもクリックが来にくい

### 3.2 狙う検索の種類

| 種類 | 例 | AI に取られにくいか |
| --- | --- | --- |
| 診断そのもの | 喧嘩タイプ 診断、恋愛 喧嘩 診断、カップル 喧嘩 相性 | ◎ 受けるにはサイトに来るしかない |
| タイプ名や診断名 | 「〇〇派 とは」「16次元診断」 | ◎ SNS で見た人が後から検索する |
| 具体的な場面 | 喧嘩 既読無視 何日、喧嘩 LINE 返信こない | △ AI も答えるが、「自分の場合は？」と知りたい人は診断や相談に来る |
| 一般的なやり方 | 仲直り 方法 | × AI の要約で終わりやすい |

### 3.3 作るページ

1. **診断の入口ページ**：何が分かるか、何分かかるか、結果のサンプル
2. **16の傾向ごとの解説ページ**：特徴、地雷、嬉しい言葉、ぶつかりやすい相手、最後に診断へ
3. **組み合わせページ**：よく検索されそうなものから少しずつ
4. **場面ページ**：既読無視、記念日、ドタキャンなど。最後に「あなたのタイプならこう動きがち」と診断・相談へつなげる
5. **集計データのページ**：数百〜1,000人を超えてから。独自のデータは AI や記事に引用されやすい

### 3.4 注意点

- **量産は危険**：156パターンから自動でページを大量に作ると、Google に中身の薄い量産ページとして扱われるおそれがある。1ページずつ実例や独自の視点を入れる
- **今のサイトは検索では1ページ扱い**：`#three` で画面を切り替える作りなので、解説ページは個別の HTML として書き出す
- **独自ドメインは早めに**：`github.io` のままだと、後で移すときに検索での評価を引き継ぐ手間がかかる。記事を書き始める前に独自ドメイン（年に数千円程度）を GitHub Pages に設定する
- **AI 検索に引用されやすくする**：「〇〇派とは、△△な人」のような定義の文、独自データ、運営者情報を載せる
- Search Console への登録とサイトマップの提出

## 4. 全体の流れと見る数字

| 段階 | 見る数字 | 今の課題 |
| --- | --- | --- |
| 知ってもらう | 表示回数、視聴、クリック | まだゼロから |
| 診断を始める | 開始率 | 入口ページがない |
| 最後まで答える | 完了率 | **ここが最大の課題** |
| 結果を見る | 納得度 | 一言ラベルがない |
| 広める | シェア率、相手に送る率、送られた人の受検率 | 機能がまだない |
| また来る | 再訪、相談モードの利用 | 相談モードは構想段階 |

### 4.1 完了率（最大の課題）

テストでは全員が「長い」と答え、v2 でも最大80問・約9分かかる。SNS から来る人はテスターより気軽な気持ちで来るので、9分ではかなりの人が途中でやめる。

対策は二段構え：

- 入口は2〜3分の「**クイック版**」（W 問題だけで16〜24問）
- 結果画面で「精密版で本当のタイプを見る」と誘う

クイック版でどれくらい当たるかは、手元のテスト回答で W だけを使って再計算すれば、作る前に確かめられる。

### 4.2 計測

- GitHub Pages でも無料の計測ツール（Google Analytics 4、Cloudflare Web Analytics など）を入れられる
- **回答の中身は送らない**。「開始」「完了」「シェア」「相手に送る」などの記録だけを取る
- 投稿ごとに目印付きのリンク（UTM）を使って、どの投稿から来たか分ける

## 5. 気をつけること

- **男女の対立**：「彼氏は〜」「女は〜」という形は炎上しやすい。性別ではなくタイプで語る（シーン文の「俺」を「こっち／自分」に直したのと同じ方針）
- **相手を責める道具にさせない**：「お前は〇〇型だから」と使われないよう、「違いを知る」というトーンをそろえる（評価しないバッジの方針と同じ）
- **喧嘩と DV・モラハラの違い**：喧嘩の相談には危険な関係にいる人も来る。解説ページと相談モードに「これは喧嘩ではなく支配かも」というチェックと相談窓口（DV相談ナビ #8008 など）を置く
- **科学的に見せすぎない**：「心理学で証明」とは書かず、「自分を知るための診断」と打ち出す
- **インフルエンサーに頼む場合**：2023-10 からのステマ規制により「PR」の表記が必要
- **10代の利用**：個人情報を取らない今の設計を続ける

## 6. 進め方

| 時期 | やること |
| --- | --- |
| 今〜2週間 | 独自ドメイン、計測、結果カードとシェアボタン、一言ラベル、クイック版の精度確認 |
| 1か月目 | TikTok・Instagram・Threads を開設して30本の実験投稿、入口ページと16傾向ページ |
| 2〜3か月 | 当たった型の量産、ふたり診断、場面ページ |
| 3〜6か月 | 集計データの公開、LINE スタンプ、相談モードへの導線 |

- 最初の SNS 投稿でテスター募集も兼ねると、精度を上げるための回答も集まる
- 今のコピペで送る方式（テスト協力モード）は大人数には重いので、その段階で軽い計測に切り替える
