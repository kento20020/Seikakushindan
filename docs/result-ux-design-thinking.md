## 0. 先に結論（忙しい人向け）

- 結果画面の仕事は4つ：①10分かけた人に「それ、自分っぽい」を1つ渡す、②相談が使う「自分の動き方」を正しくする（直せる）、③見せたくなる単位を渡す、④喧嘩の夜に戻る道を作る。主役は相談（U2）なので、②と④が本筋で、①と③はその入口
- 3案：**案1「一枚から、めくる」**（結果を1枚＋横にめくる4枚にして、短く・見せやすく）、**案2「夜に引く結果」**（昼は喧嘩の流れで読み、夜は「いま、どこ？」から1行と相談への近道だけ）、**案3「合ってる？で仕上げる結果」**（結果を下書きとして渡し、本人が「自分っぽい／ちがう」で仕上げ、仕上げた一言が表紙になり、直した軸が相談に効く）
- 推奨：**案3 を骨にして、案1 の「表紙の1枚」と「カード単位の共有」を取り込む。案2 の「夜の顔」は、相談の新しい画面（案D）ができたときに相談側へ足す**。理由は §10
- A〜F は見た目の案として良くできているが、6つとも同じ骨組み（表紙 → 4カード → 8軸 → 注記 → 相談）で、「違ったら直す」「夜に戻る」「何を共有するか」が設計されていない。F の「2軸の二連」、C/F の「違うところがある」の問い、B/E の「流れ順」は3案に取り込んだ。批評は §11

## 1. 前提の整理

### 1.1 結果画面は何のためにあるか

決定 U2「主役は相談。診断は相談を良くする材料」、U3「診断は普段の時間、相談は喧嘩の夜」から、結果画面の仕事を4つに分ける。

| # | 仕事 | 誰のため | 失敗するとどうなるか |
| --- | --- | --- | --- |
| ① | **10分（64〜80問）かけた人に、最初の1画面で「それ、自分っぽい」を1つ渡す** | 初回の全員 | 長さの不満が、そのまま結果の不満になる（テスター6人全員が「長い」。`docs/test-results.md` §1） |
| ② | **相談が使う「自分の動き方」（8領域の向き・確かさ）を、本人が確かめて直せる形で渡す** | 相談に進む人、夜に戻る人 | 外れた結果のまま一手が出る（自己評価との一致は厳しめで57%、D5 の理由） |
| ③ | **見せたくなる単位（1行＋1枚）を渡す** | SNS から来た人、相手に送りたい人 | 結果が1人で終わり、広がらない（`docs/marketing-plan.md` §1.1） |
| ④ | **喧嘩の夜に戻る道を作り、戻ったとき最初に効くものが見える** | P1・P2・P4 のような夜の利用者 | 診断と相談が別のアプリのように切れる（今の結果画面には相談へのボタンが無い。§1.2） |

①と③は「入口」、②と④が「本筋」。見た目の案（A〜F）は①と③を主に考えていて、②と④が薄い。この文書の3案は②と④で差を出す。

### 1.2 今の結果画面（確認した事実）

`js/ui/three.js` の `resultView()`（530行目〜）の並びは次のとおり。

1. `resHeader`：「診断結果」＋「72問に回答／問題を変えた n回・答えずに進んだ n問」
2. `typeHero`：主軸の傾向の絵1枚（`heroTendency`。準備中なら「あなたのほかの傾向の絵」と注記）
3. 「あなたを表す解釈」：2〜4本のパターンカード（役割の札、見出し、一言、詳細、場面例、独自の点、誤解しやすい点）
4. `typeTiles`：「8つの軸の絵」（領域ごとに優勢側の絵。準備中は灰色の枠、拮抗は「場面によって変わる」の枠、「弱め」の札）
5. 「8領域の左右と16傾向の強さ」：領域ごとの W の数の帯と、X の強さの**バー2本**（目盛りつき）
6. 「回答の様子」：左を選んだ割合、問題を変えた回数、答えずに進んだ数
7. 「結果を持ち出す」：AI統合用テキストのコピー、結果JSONの保存

分かったこと：

- **相談へのボタンが無い**。相談へはヘッダーのリンクだけ（`js/app.js` の冒頭コメント）。相談側は `js/ui/consult_self.js` が `localStorage` の `seikaku16:three:v1` から結果を読む（`deviceResult`）。つなぎは「裏で読む」だけで、画面には出ていない
- **D5（本人が領域ごとに直す）は、相談画面の「あなたのタイプ」の中にある**（`consult.js` の `corrections`、`consult_state.js` の `consult-form-v1` に保存）。結果画面には「これは違う」が無い
- **共有の仕組みは無い**（画像の生成、相手に送るリンク、シェアボタンのどれも未実装。`docs/marketing-plan.md` §1.3 は計画）
- **スコアとバーが出ている**（5の節）。`docs/ui-ux.md` §3 の「避けるもの：スコア、ゲージ」とぶつかる。利用者向けの表示でも残っている（`docs/ui-audit.md` §6 の残った課題）
- 長さは利用者向け・v2 で**画面9.5枚分**、目標6枚以下（`docs/ui-audit.md` §5・§6）
- 結果は端末の `localStorage` だけに保存され、どこにも送らない（`three_store.js` の `persist`）。URL は `#three` で、結果の深いリンクは無い（`setSub("result")` で切り替え）
- テスト協力モード（`?fb=1`）は、ブラインド比較に絵を出さない決まり（`docs/type-images.md`）。新しい結果画面も `fbResultTop`／`fbResultTail` の差し込み口を残す必要がある

### 2.3 見えてきたこと

1. **最初の1画面は「ご褒美」**。10分の後なので、ここで「それ、自分っぽい」が1つ出ないと、長さの不満が結果の評価に移る（仕事①）
2. **「いちばん出やすい」は、言い過ぎかもしれない**。テスター6人のうち、主軸を「喧嘩の中心だ」と感じた人は0人（`docs/test-results.md` §1）。ブラインド比較で自分の結果を選べた人は5/6、カードの当てはまり度は平均3.67なので、**4本の中身は当たっているが、どれが「中心」かは機械が決めると外れやすい**。主軸を「あなたはこれ」と出すより、「4つの読み方のうち、答えにいちばんよく当てはまったもの」として出し、どれが自分の中心かは本人に任せる余地がほしい
3. **夜は読まない**。夜に結果画面を開いて4本を読み返す人は、たぶんいない（仮説）。夜に欲しいのは「いまの自分に効く1行」と「相談へ」の2つ。結果画面の夜の役割は、相談に正しい材料を渡すこと
4. **見せる単位は「1行＋1枚」**。SNS から来た人は、見せることが目的の一部。「私は『〇〇』でした。あなたは？」の形なら、相手への評価が入らず、相手にも受ける理由ができる（`docs/marketing-plan.md` §1.2）
5. **「違う」と思ったときの出口が無いと、決めつけに変わる**。D5 の仕組みは相談側にあるが、結果画面には無い。違うと思った瞬間に直せると、「味方」と「確か」の両方になる
6. **相手（彼氏）は警戒して開く**。送られたものに「あなたはこういう人」の匂いがあると閉じる。送るのは自分のことだけ、相手には問いだけ

## 5. 3案に共通する決めごと（提案）

3案で繰り返さないため、共通の部品をここにまとめる。すべて提案で、持ち主の確認が要る。

### 5.1 言葉

- 強さの言い方は **「はっきり」「やや」「場面による」** の3語（キャンバス A〜F が既に使っている。コードの内部名「優勢（弱）」「W と X の向きが逆」は `?dev=1` だけ）
  - 対応（提案）：`domainFlags3` の `lead` があり `weak`・`conflict` ともに無し → **はっきり**。`weak` → **やや**。`conflict`（左右と強さの向きが逆）→ **やや**＋1行「この軸は答えが少し割れていました」。`tie` → **場面による**
- 主軸の呼び方は「いちばん出やすい」をやめ、**「答えに、いちばんよく当てはまった読み方」**か、ただ「1つ目」にする（§2.3 の2）。役割の札「主軸・補強・矛盾」は利用者には見せず、「1つ目」「あわせて出やすいこと」「もう一つの面」にする（A〜F と同じ）
- 受け止めの1行を最初に置く：「72問、おつかれさまでした。」（U7 の流儀。長くしない）
- 「タイプに当てはめていません」の1行は、どの案でも8軸の近くに置く。文例：「8つの軸をそれぞれ確かめ、156ある読み方から、答えに当てはまりやすいものを選んでいます。答えが割れた軸は「やや」「場面による」と書いています」

### 5.2 絵の使い方（16枚）

| 場面 | 使い方 | 根拠 |
| --- | --- | --- |
| 1つ目（主軸）の表紙 | パターンが語る傾向のうち、本人が優勢なものの先頭1枚（今の `heroTendency` と同じ） | P1 なら 1A 向き合う |
| クロスのカード（補強・矛盾） | **二連**：2つの傾向の絵を並べ、間に「×」。片方が「やや」でも絵は同じで、札で示す | 案F の二連。X34-2 なら 3A と 4B |

### 5.3 根拠の見せ方（数字なし）

- バー・％・点数は出さない（`docs/ui-ux.md` §3）。今の「8領域の左右と16傾向の強さ」の節は `?dev=1` へ
- 代わりに「どうやって決めたか」の引き出し（開閉）に、**回数を文で**書く。文例（P1 の領域1。`r.states[1]` の a:b から作れる）：「同じ場面で2つの動き方を比べる問に、6回答えました。そのうち5回で「その場で話を続ける」側を選んでいます」
  - 回数は点数ではないので持ち主の決まりに反しない、と私は考えるが、**「6回中5回」も数字には違いない**。心配なら「ほとんどの問で」「半分ずつ」の3段階の言葉だけにする。テスターに「点数をつけられた感じがしたか」を聞いて決めたい
- 「決まらなかった」ことは正直に：「この軸は、答えが3回ずつに割れました。場面によって変わるのかもしれません」

### 5.4 相談へのつなぎ

- 主ボタンは1画面に1つ（`ui-audit` §3.5）。結果画面の主ボタンは**「この結果で相談する」**。文の下に小さく1行：「相談では、この結果に合わせて次の一手を出します。違うところは直せます」
- 押すと `#consult`（新しい相談画面ができたら、そちら）。相談側は既に `deviceResult()` で結果を読むので、受け渡しの実装は「ボタンを置く」だけで始められる。直した軸（D5）を結果側で持つ案3 は、`consult_self.js` の `resolveSelf` に結果側の直しを混ぜる（§8.11）
- 夜の入口は**トップの「いま喧嘩中」→ 相談**が本線（U12）。結果画面は夜の入口にはしない。ただし結果画面を夜に開いた人のために、表紙の主ボタンが最初の画面に入っていること（3案とも）

### 5.5 共有（相手を評価・操作するように見えない作り）

- 共有の中身は**自分の結果だけ**。文例：「私は『気づいたその場で、話を始める。』でした。あなたは？ #16次元診断」。相手の結果・相手への助言は入れない（D4）
- 画像は端末の中で作る（`canvas`）。正方形（X・LINE）と縦長（ストーリーズ）の2種（`marketing-plan` §1.3）。中身は、絵（1枚か二連）＋見出し＋「16次元診断」＋URL。**8軸の一覧は入れない**（軸の一覧は「性格の表」に見え、相手に送ると「分析された」感が出る）
- **共有の前に、送る中身を必ず見せる**（プレビュー）。何が外に出るかが見えることが「確か」
- 「相手に送る」は**問いの形**：「あなたは、喧嘩のとき、まず話す？ いったん離れる？」＋診断のリンク。自分の結果を見せるかは本人が選ぶ（既定は見せる文を入れない）
- ボタン：保存（画像）、X、LINE、リンクをコピー。`navigator.share` が使える端末は1つにまとめる
- 自虐・弱みを含む見出しほど共有されやすい（`marketing-plan` §1.1）。矛盾カード（「言わないのに、分かってほしい。」）が共有の中心になる可能性が高い。だから**どのカードからも共有できる**ようにする（案1・3）

### 5.6 アクセシビリティとダーク

- 見出しの構造：h1「診断結果」→ h2 各カード・8軸。絵の `alt` は `type_images.js` の `alt`（16件そろえる）
- 押せる物は 44px 以上（`ui-audit` 目標）。開閉は `<details>` か `button aria-expanded`
- 動きは 150〜250ms・ease-out、`prefers-reduced-motion` では即切替。点滅・はねる動きはしない
- ダークは本命（`ui-ux` §3）。トークンは `css/tokens.css` の役割の値をそのまま使う。絵は紺のマットで囲い、明るさは変えない
- 読み上げ：強さの札「やや」は `aria-label="やや（答えが少し割れていました）"` のように意味を補う

### 5.7 短い版（W だけ）への耐性

W だけの結果は、8領域の向きと「はっきり／やや」だけで、パターンがほぼ出ない。3案の耐性は §9 の表に書く。共通の方針：**8軸が結果の骨になる形**にしておき、パターンは「あれば出る」ものとして扱う。

**結果に、昼の顔と夜の顔がある。** 昼は、喧嘩の始まりから仲直りまでの流れで人物像を読む。夜は「いま、どこ？」の4択から入り、その場面の自分の1行と、相談への近道だけを見る。結果を「人物像」ではなく「喧嘩の場面ごとの自分の動き方の索引」として作る。

一番効く人と瞬間：**P1 美咲（返事を待つ夜）、P2 結衣（「もういい」の夜）、P4 真由（返したくない）**。昼は P6 さき（流れで理解したい）。

### 7.2 体験の流れ（昼・初回）

| 段階 | 画面に出るもの | 利用者がすること |
| --- | --- | --- |
| 最後の問に答える | 受け止め1行 → 表紙（見出し・絵）→「喧嘩の始まりから仲直りまで、あなたの動き方を起きる順に並べました」 | 読む |
| 場面の段（アンカー） | ① 引っかかった瞬間　② 返事を待つあいだ　③ 話し合い　④ 仲直り（横に4つ。現在地が分かる） | 押すとその場面へ |

### 7.3 体験の流れ（夜・再訪）

入口は3つ。

- (a) **トップ「いま喧嘩中」→ 相談**（U12 の本線）。結果画面は通らず、相談が裏で結果を読む
- (b) **結果の画面を夜に開く**：最初に「いま、どこ？」の4つの大きなチップ（① 引っかかった直後　② 返事を待っている　③ 話し合いの前・最中　④ 仲直りしたけど）。選ぶと、その場面だけが開き、1行「返事を待つあいだのあなたは、連絡はする。でも、不安だとは言わない。が出やすい、という答えでした」＋［この場面で相談する］。ほかの場面は畳まれる
- (c) **相談のカードの「確かさ」から戻る**：「この一手は、あなたの『追う・はっきり』を見て決めました」→ 押すと結果の該当場面へ

**「夜」をどう決めるか**：時刻（22〜5時）や `prefers-color-scheme: dark` で切り替えるのは危うい（昼に喧嘩する人もいる。夜に落ち着いて読み返す人もいる）。提案は、**チップは常に出し、入口で並びを変える**だけにする：トップや相談から来たとき（`store3` に `entry: "consult"` のような印を持つ）はチップを最初に、診断の直後は表紙を最初に。時刻は使わない。

### 7.4 最初の画面（390×844）

昼：受け止め1行 → 見出し → 絵 → 「流れで読む」の段（4つ）→ ①の小見出しが始まる。
夜（相談から来たとき）：「いま、どこ？」→ チップ4つ（各 56px、1列）→ 下に表紙を小さく。

### 7.5 情報の階層と長さ

| すぐ見える | 開くと見える | 別画面 |
| --- | --- | --- |
| 場面ごとの見出し・一言・絵、場面チップ | 詳細・誤解しやすい点・どうやって決めたか | 相談、共有、`?dev=1` の節 |

長さ：昼 **4〜5画面**（4場面 × 約1画面＋8軸）。夜 **1画面＋選んだ場面1画面**。

### 7.6 操作と動き

- 場面チップ（radio の意味。1つ選ぶ）、段のアンカー、縦スクロール、「詳しく」
- 夜：チップを選ぶとほかの場面が畳まれる（200ms。reduced-motion は即）
- 文字は夜向けに本文 18px、チップの文字 18px

### 7.7 絵の使い方

- 場面ごとに**主従**：主の軸の絵1枚（大）＋脇に小さく1枚。二連ではなく主従にするのは、夜は1枚で十分で、2枚並ぶと読む物が増えるから
- 拮抗の軸（P1 の領域7）は③の中で2枚を小さく、「場面による」
- 夜は絵1枚だけ（チップで選んだ場面の主の軸）。マット付き

### 7.8 「確か」の作り方

- 場面ごとの「どうやって決めたか」（§5.3）
- **相談との往復**：相談のカードの「確かさ」が結果の場面を指し、結果の場面が相談を指す。同じ事実が2か所で同じ言葉で見えると「確か」になる
- D5：場面の中の軸の行に「これは違う」

### 7.9 共有

昼だけ。単位は「場面カード」：「返事を待つあいだの私：『連絡はする。でも、不安だとは言わない。』」。相手に送る問いも場面で：「あなたは、返事を待つあいだ、どうしてる？」（§5.5）

### 7.10 相談へのつなぎと夜の再訪

- ［この場面で相談する］で、**場面のヒント**を相談に渡す（提案）：`sessionStorage` に `{ sceneHint: "waiting" }` のような小さな値。相談（案D）の読み取りに「場面の候補」として渡すが、**確定はさせない**。「返事を待っている」でも、最後に送ったのが自分とは限らない（相手が「もういい」と送って来て、それに返していない人も「待っている」と感じる）ので、`lastSender` を決め打ちしない。U26 の「受け止めと状況の整理」の1文に「返事を待っているところ、とのことですね」と出し、違えば直せる形
- 夜の再訪は §7.3 のとおり。ただし**新しい相談画面（案D）がまだ無い**ので、受け渡しの実装は相談画面と一緒に進める

### 7.11 アクセシビリティとダーク

- チップは `fieldset`＋`legend`「いま、どこ？」の radio。高さ 56px。選択は色だけでなくチェック印
- 場面の段は `nav` で、現在地は `aria-current`
- 夜の画面はダークが本命。主ボタンはまぶしくない塗り（`tokens.css` のダークの Primary）

### 7.13 リスクと弱いところ

- **クロスのパターンを1つの場面に割り当てると意味が欠ける**。X18-2「話し合うのは、早く仲直りしたいから。」は①（向き合う）と④（関係を戻す）の両方。1か所に置くと片方の軸が消える。「関係する場面」を複数持たせ、主の場面に本文、ほかの場面には1行だけ出す、で補えるが、作りが重くなる
- 結果画面の顔が2つになり、保守が重い。段階3（結果画面）の範囲を超える
- **夜に結果画面を開く人がそもそも少ないかもしれない**。U12 でトップから相談に直行する設計なので、「夜の顔」は結果画面より**相談側**（相談の「あなたのタイプ」の見せ方）に置いた方が効く可能性がある。これは正直に書いておく
- 昼の読者には「人物像」でなく「説明書」に見えるおそれ（流れに切ると一人の人の話に見えにくい）
- W だけの結果：場面ごとに軸の向きだけが出る。成り立つが、各場面の見出し（パターン）が無くなる

### 7.14 テスターで確かめる方法

- 夜の場面（P1〜P4 のどれか）を渡し、結果の画面から **20秒以内に「自分の場面の1行」に到達できるか**
- 場面チップで迷ったか。P4（待たせる側）が自分の入口を見つけられたか（「返事を待っている」でも「話し合いの前」でもない、と感じないか）
- 昼の読者が「ひとりの人物として読めた」と感じたか、「説明書みたい」と感じたか
- 相談に進んだあと、「結果が使われている」と感じたか（往復の実感）

## 8. 案3「合ってる？で仕上げる結果」

### 8.1 名前とコンセプト

**結果は下書き。本人が「自分っぽい／ちがう」で仕上げる。** 仕上げた一言が表紙になり、直した軸が相談に効く。「決めつけない」を言葉で約束するのではなく、**操作で見せる**。

一番効く人と瞬間：**初回の全員**、特に P2 結衣（根拠と筋）、P3 彩花（静かに確かめたい）、P6 さき（理解したい）。そして**「違う」と感じた瞬間**の全員。テスターにも向く（今のテスト協力モードの評価欄 `fbCard` と同じ発想で、本番の形にしたもの）。

### 8.2 体験の流れ

| 段階 | 画面に出るもの | 利用者がすること |
| --- | --- | --- |
| 最後の問に答える | 「72問、おつかれさまでした。4つの読み方が選ばれました。合っているか、一緒に確かめましょう」＋［見る］（1画面。急かさない） | 押す |
| カード1（1つ目） | 小さく「1つ目」→ 見出し → 絵 → 一言 →「たとえば」1つ →「詳しく」→ 下に2つの大きなチップ **［自分っぽい］［ちがう］**（対等。既定なし）と小さく「あとで」→［次へ］ | 読んで選ぶ。選ばなくても次へ行ける |
| カード2〜4 | 同じ形。補強・矛盾は絵の二連 | 同じ |
| 8軸の確認 | 「8つの軸」：各軸1行（絵の小さなタイル＋傾向名＋はっきり／やや／場面による）＋［これは違う］。**拮抗・やや・確度低の軸を先頭に**「ここは答えが割れました。どちらが近い？」の2択（P1 なら領域7・5・8） | 直す、または飛ばす |
| 表紙ができる | 「あなたが『自分っぽい』と言った一言」（複数なら最初に押したもの。無ければ1つ目）＋その絵。「あなたが直した軸：2つ」の小さな行。主［この結果で相談する］、副［見せる］ | 相談へ、見せる |
| 再訪 | 表紙から。「まだ確かめていないカードが2つあります」「もう一度確かめる」 | — |

カードを進む形（1画面ずつ）にするか、縦に全部並べてチップだけ付けるかは、どちらもあり得る。**初回は進む形**（1画面1つのこと。U7 の原則と同じ）、**再訪は縦に並べる**（全体を見渡す）を提案。

### 8.3 最初の画面（390×844）：カード1

1. 「72問、おつかれさまでした。」（前の画面から続く小さな行）
2. 小さく「1つ目　4つのうち、答えにいちばんよく当てはまった読み方」
3. **見出し**「気づいたその場で、話を始める。」
4. **絵**（1A）
5. 一言「引っかかった瞬間に、持ち帰らず相手に向かいやすい。」
6. 「たとえば：デート中に引っかかる一言があると、帰り道ではなくその場で「今の、どういう意味？」と聞く。」
7. ［詳しく］（開くと詳細・誤解しやすい点・どうやって決めたか）
8. 「この読み方は？」　［自分っぽい］［ちがう］　（小さく）あとで
9. ［次へ］　「1 / 4」

### 8.4 情報の階層と長さ

| すぐ見える | 開くと見える | 別画面 |
| --- | --- | --- |
| 見出し・絵・一言・たとえば・チップ | 詳細・誤解しやすい点・どうやって決めたか | 表紙、共有、`?dev=1` の節 |

長さ：1カード ≈ 1画面 × 4 ＋ 8軸 1〜1.5画面 ＋ 表紙 1画面 ＝ **6〜7画面分**だが、進む形なので一度に見るのは1画面。再訪の縦並びは表紙＋4カード（畳んだ状態）＋8軸で約4画面。

### 8.5 操作と動き

- チップ：押すと塗り＋チェック印。押し直せる。「ちがう」を押しても説明や確認は出さない（「本当に？」は決めつけの裏返し）
- ［次へ］で進む。自動では進まない（選んだ直後に画面が変わると、押し間違いが直せない）
- 8軸の［これは違う］：押すと反対側の文に変わり、絵も反対側に差し替わる（150ms のフェード。reduced-motion は即）。「あなたが直しました」の札
- 表紙の見出しは、本人が選んだ一言。1つも選ばなければ1つ目のまま（注記なし）

### 8.6 絵の使い方

§5.2 のとおり。この案だけの点：**「これは違う」で絵が反対側に変わる**。16枚そろったからできることで、「自分で仕上げた」実感がいちばん強く出る場面。「ちがう」と押したカードの絵は薄くしない（札「ちがう、と答えました」だけ）。

### 8.7 「確か」の作り方

- 「どうやって決めたか」（§5.3）
- **直した内容が相談に効く**ことを明記：「相談では、あなたが直した内容で考えます」（D5：直した領域は重み 1.0）
- 「ちがう」が多いときの文（説教しない）：「4つのうち3つが「ちがう」、とのことでした。喧嘩の相手や、その日の気分で変わることもあります。相談では、あなたが直した内容を優先します」
- 元の結果は消さず、「診断では〜でした」として「詳しく」の中に残す（直したことが隠れない）

### 8.8 共有

単位は**「私が選んだ一言」**。「診断の一言を、私が選びました」の作りなので、SNS に出しても「診断に決めつけられた」ではなく「私が選んだ」になる（§2.3 の4）。「ちがう」の記録や直した軸は共有に入れない（自分の端末の中だけ）。

### 8.9 相談へのつなぎと夜の再訪

- 表紙の主ボタン。文の下に「直した2つの軸も、相談で使います」
- 夜の再訪：表紙（一言・絵・相談ボタン）の1画面で足りる
- 相談側の「あなたのタイプ」は、結果側の直しを読んで「結果画面で直した内容を使っています」と出す

### 8.10 アクセシビリティとダーク

- チップは `fieldset`＋`legend`「この読み方は？」の radio（自分っぽい／ちがう／あとで）。44px 以上。色だけに頼らずチェック印
- 進み具合「1 / 4」は文字で（バーにしない）
- ［これは違う］は `button aria-pressed`。直した直後に `aria-live="polite"` で「反対側に直しました」
- ダークは §5.6

### 8.11 作るのに要るもの

| 何 | 中身 | 既存との関係 |
| --- | --- | --- |
| 結果側の保存 | `store3` に `review: { patterns: { [id]: "fit"\|"no"\|null }, corrections: { [d]: "A"\|"B" }, cover: id\|null }` を持ち、`persist` で保存 | `three_store.js` に数行。診断をやり直したら消す |

| 共有 | 案1 と同じ部品 | — |

手間：**中〜大**（状態の保存と相談側の読み込みが増える。画面そのものは案1 より単純）。

### 8.12 リスクと弱いところ

- **72問の直後に、さらに8〜12タップ**を求める。疲れている人は押さない → 任意にし、「あとで」を置き、押さなくても表紙は出る
- 全部「ちがう」を押す人がいると診断の意味が消える → 直した内容を「本人の言葉」として扱い、元も残す。相談では D5 の決まりどおり本人の修正を重み 1.0 にする（それが設計）
- 「自分っぽい」を押させたい誘導に見えると、「合っていると言わせる」操作になる → 2択を対等に、既定なし、色も同じ
- 保存はこの端末だけ。Website の保存・ログインの決まり（U19）とは別。Website に移すときは置き換え
- W だけの結果：**むしろ向く**。8軸の確認が骨で、パターンが無くても「8つの軸を確かめる」として成り立つ

### 8.13 テスターで確かめる方法

- 「自分っぽい」の割合（今の当てはまり度 3.67／5 と見比べられる）
- 「ちがう」を押したカードと軸、そのあと相談で一手が変わったか（判定は決定論なので、変わる・変わらないが追える）
- 表紙を自分で選んだ人が「見せる」を押す割合（案1 の表紙と比べる）
- 途中でやめた割合と、どのカードでやめたか（疲れの位置）
- 「決めつけられた感じ」の有無（はい／いいえ＋一言）。これは3案の中でいちばん下がるはず

## 10. 推奨

**案3 を骨にして、案1 の「表紙の1枚」と「カード単位の共有」を取り込む。案2 の「夜の顔」は、相談の新しい画面（案D）ができたときに、結果画面でなく相談側へ足す。**

理由：

1. 主役は相談（U2）なので、結果画面の本筋は仕事②（相談が使う自分の動き方を正しくする）。案3 だけが D5 を本体に持ち、**確かめられた2つの事実（主軸を中心と感じた人0/6、自己評価との一致57%）に直接答える**
2. 「決めつけない」を言葉でなく操作で見せるのが、世界観「味方・確か」にいちばん近い
3. 短い版（W だけ）が来ても、8軸の確認が骨なので作り直しが要らない
4. 案1 の表紙と共有は、仕事①③の答えとして優れていて、案3 と矛盾しない（表紙＝本人が選んだ一言、共有＝カード単位）
5. 案2 の肝（場面で引く・場面を相談へ持っていく）は、受け取る側の相談画面がまだ無い。先に作ると二度手間になる。昼の「流れ順」は、案3 のカードの小見出し（不安なとき／仲直りのとき）として薄く取り込める

**疲れのリスクへの答え**：案3 のチップは任意、「あとで」あり、押さなくても表紙は出る。テスターで「途中でやめた位置」を見て、4カードすべてに聞くか、1つ目と8軸だけに聞くかを決める。

### 最初に作る小さな試作（1〜2画面、`?ui=v2` の中、サンプル P1）

1. **表紙**（案1 の1枚）：受け止め1行、「4つのうち、答えにいちばんよく当てはまった読み方」、見出し、絵（1A）、組み合わせの行、主［この結果で相談する］、副［見せる］。スマホ 390×844 で、絵と帯が同時に入るかを確かめる。ライトとダーク
2. **カード1枚**（案3）：1つ目のカードに［自分っぽい］［ちがう］と「詳しく」（詳細・誤解しやすい点・どうやって決めたか）。「ちがう」を押したときの見た目。8軸の1行に［これは違う］を押すと絵が反対側に変わる、を1軸だけ

この2画面だけで、「それ、自分っぽい」（仕事①）と「直せる」（仕事②）の手応えをテスターに聞ける。共有の画像生成と相談側の読み込みは、その次。

## 11. キャンバスの案A〜F との関係と批評

### 11.1 6案に共通していること（確認した事実）

- 6案とも同じ骨組み：題 → 「いちばん出やすい動き方」の見出し → 絵 → 絵の一言 → 相談／共有のボタン → 4カード → 8軸 → 「タイプに当てはめていません」 → 相談のボタン → もう一度 → 「結果はこの端末の中だけに保存されます」
- 高さ（`canvas.json`）：A 4000・B 3700・C 3400・D 4250・E 4000・F 3950px。844 で割ると **4.0〜5.0画面分**。今の9.5枚分より短く、目標6枚以下に入っている
- 言葉は統一されている：「はっきり／やや／場面による」、「タイプに当てはめず、156ある読み方から」、「結果はこの端末の中だけに保存されます」。良い
- D・E・F は見出しに明朝（Zen Old Mincho）を使っている（D は12か所）。決定 U9「明朝はやめてゴシック1つ、例外を作るなら結果の一言の引用だけ」とぶつかる
- どの案にも、違ったら直す手段、夜の再訪の入口、共有のプレビュー、「直した」状態は無い（C・F の「違うところがある」を除く）

### 11.2 案ごとの批評

| 案 | 良いところ | 気になるところ | 3案との相性 |
| --- | --- | --- | --- |
| A 絵と一言 | 素直。表紙の作りが分かりやすい | 「8つの軸の絵」に「絵は準備中」が残っている（16枚で解消） | 案1・3 の表紙の土台 |
| B 喧嘩の流れで読む | 流れ順と、場面の中の「吹き出し」（今の、どういう意味？）が具体的で、人物像が場面で見える | 4場面への割り当て規則が無い（クロスは2場面にまたがる）。8軸の「見取り図」は左右に塗り分けていて、ゲージに見えないか確かめたい | 案2 の昼の顔 |

### 11.3 まとめ

A〜F は「見た目と1画面の並び」の案として十分に良く、特に F の二連とマット、B の場面の吹き出し、C/F の問いは3案に取り込んだ。足りないのは**状態**（初回／再訪／直した）、**操作**（直す・めくる・場面で引く）、**共有の中身の見せ方**、**相談との受け渡し**で、この文書の3案はそこで差を出している。見た目は、案1・3 なら A＋F（ゴシックで）、案2 なら B＋F が合う。
