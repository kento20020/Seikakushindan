# 三択のスワイプの形（案の比べ方）

- 状態：**試作（2026-10-17）**。既定は今の形のまま。持ち主が触って比べてから、どれを既定にするかを決める（決定 U27）
- きっかけ：持ち主の依頼「今は質問文も左右の回答も一緒に動くので、質問文はそのままにして、左右の回答だけが1枚のカードとして動くようにしてほしい。別案として、左へスワイプするときは左のカードだけ、右へスワイプするときは右のカードだけが動く形も」
- 関わる文書：[ui-audit.md](ui-audit.md)（質問画面の改善 段階2）、[design-tokens.md](design-tokens.md)（`?ui=` `?dev=` の仕組み）

## 1. 4つの形

| `?sw=` | 名前 | 左右のスワイプで動くもの | ねらい |
| --- | --- | --- | --- |
| `card`（既定。付けなくても同じ） | 今の形 | 質問カード全体（質問文＋回答2枚） | — |
| `a` | 回答をまとめて | 回答2枚がひとまとまりで動く。質問文は動かない | 答える間も質問文が読めるまま。「カードの束を1枚ずつめくる」感じは今と同じ |
| `b` | 向きの側だけ | 左へ → 左の回答だけが左へ。右へ → 右の回答だけが右へ。指を置いた場所は関係ない | 「どちらを選んだか」が、動く回答そのもので分かる |
| `c` | 触った回答だけ | 指を置いた回答だけが動く。左の回答は左へだけ、右の回答は右へだけ（逆へは抵抗がかかって戻る）。回答の外（質問文など）から始めたときは b と同じ | 指の下にある物が動く（直接さわる感じ）。b の弱いところ（下の回答をさわって左へ動かすと、上の回答が動く）をなくす |

c は持ち主の依頼にはない、メインが足した案。b を作るときに「向きで決めるか、さわった回答で決めるか」が分かれたので、両方を作って触り比べられるようにした（§3 の1）。

### 開き方

| 形 | 公開ページ | 手元（`python3 -m http.server`） |
| --- | --- | --- |
| 今の形 | https://kento20020.github.io/Seikakushindan/#three | `http://127.0.0.1:8000/#three` |
| a | https://kento20020.github.io/Seikakushindan/?sw=a#three | `http://127.0.0.1:8000/?sw=a#three` |
| b | https://kento20020.github.io/Seikakushindan/?sw=b#three | `http://127.0.0.1:8000/?sw=b#three` |
| c | https://kento20020.github.io/Seikakushindan/?sw=c#three | `http://127.0.0.1:8000/?sw=c#three` |

- 公開ページで開けるのは、main に入って Pages に公開されたあと
- `?ui=v2`（新しい見た目）、`?dev=1`、`?qv=`、`?fb=1` と組み合わせられる（例：`?ui=v2&sw=b#three`）
- `?dev=1` の開始画面に「スワイプの形（比べる用）」の欄があり、4つの形へのリンクから切り替えられる。質問画面では、今の形以外のとき「スワイプ A」などの小さな印が出る
- URL だけで決まり、どこにも保存しない（`?ui=` と同じ）

## 2. どの形でも同じこと

- **上（問題を変える／使い切ったら答えずに進む）と下（戻る）は、どの形でもカード全体が動く。** 質問そのものが入れ替わるので、質問文も一緒に動かす。「答える＝回答が動く」「問題を変える・戻る＝カードごと動く」で、動く物が「入れ替わる物」と同じになる
- スワイプを始められるのは、今と同じくカード全体（質問文の上からでも始められる）
- タップ・ボタン・キーボード（← → Space）は変わらない
- 練習カードにも同じ形が効く
- 動きを減らす設定（prefers-reduced-motion）のときは、今と同じく指に付いてくる動きだけで、飛ばす・戻す・滑り込むアニメーションはしない
- スマホ幅では回答が縦に並ぶ（左の回答が上、右の回答が下）。b・c でもそのまま、上の回答は左へ、下の回答は右へ動く
- 傾きは、今の形が 8°、a・b・c は動く物が小さいので 5°。回転の中心は下寄り
- カードの下のヒント（「カードをドラッグ／スワイプでも回答できます」など）とつまみ（「スワイプで回答」）の文は、どの形でも同じ。一度だけ出る操作説明の箱の文だけを形ごとに変えた

### 答えたあとの次の設問の出し方（a・b・c）

| | 質問文 | 回答 |
| --- | --- | --- |
| a | その場で短くフェードイン（質問が変わったと気づけるように） | 回答2枚が、飛ばした向きの反対側から滑り込む |
| b・c | 同上 | 新しい回答2枚が、少し下からフェードイン |
| 上・下で確定（全部の形） | カード全体が滑り込む（今と同じ） | ← |

### 最初の設問で一度だけ見せる見本の動き

- 今の形：カード全体が右・左へ軽く動く（今と同じ）
- a：回答2枚が右・左へ軽く動く
- b・c：前半で右の回答が右へ、後半で左の回答が左へ軽く動く

## 3. 触って比べるときに見るところ

1. **スマホの縦並びで、b に違和感がないか。** b では、下（右）の回答に指を置いたまま左へスワイプすると、上（左）の回答が動く。指の下の物と動く物がずれる。気になるなら c、気にならないなら b（b は指の位置を気にせずに済む）
2. **質問文が読めるまま答えられるか。** 今の形は、ドラッグすると質問文も傾いて流れる。a・b・c は質問文が止まっている。迷いながら指を動かす人ほど差が出るはず
3. **「どちらを選んだか」が分かるか。** a は回答2枚が一緒に動くので、選んだ側は色（強調）と上のラベルで示す。b・c は動く回答そのものが選んだ側
4. **選び間違い。** c は逆向きに動かせないので、つかんだ回答と逆を選んでしまうことがない。代わりに、つかんだ回答を逆へ動かしても何も起きない（戸惑わないか）
5. **64〜80問くり返して疲れないか。** 1問ごとの動きが小さいほど速く感じる。a・b・c は動く物が小さい
6. **片手で親指が届くか**（スマホ）。どの形も、カードのどこからでも始められる

## 4. 仕組み（ファイル）

| 何 | ファイル |
| --- | --- |
| `?sw=` の判定（`SWIPE_VARIANTS`・`DEFAULT_SWIPE`・`resolveUiFlags` の `sw`） | `js/ui_flags.js` |
| 形ごとの「何を動かすか」「どの向きを許すか」（DOM なしの関数） | `js/ui/swipe_variants.js`（テスト `tests/swipe_variants.test.mjs`） |
| スワイプの操作（`target`＝動かす要素、`allow`＝許す向き、のオプション。渡さなければ今と同じ） | `js/ui/swipe.js` |
| 質問カード・練習カードへの取り付け、見本の動き、説明の文 | `js/ui/three.js` |
| 滑り込み・フェード・回転の中心 | `css/style.css` の「質問カードのスワイプ」の節（`.t3-qcard[data-sw]`） |

- 今の形（`card`）のときは、カードに `data-sw` を付けない。DOM も動きも今までと同じ
- **既定を変えるとき**は、`js/ui_flags.js` の `DEFAULT_SWIPE` を `"a"` などにする（`?sw=card` で今の形に戻せる）
