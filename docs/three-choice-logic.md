# 三択版（左／右／問題を変える）の判定ロジック仕様 v1（2026-10-08）

5択（1〜5）の「どちらともいえない」をなくし、各設問の選択肢を **左の文に近い／右の文に近い／問題を変える** の3つだけにした版。
5択版（`js/engine.js`・`js/adaptive.js`・`js/data/questions.js`）には手を入れず、別タブ「三択診断」として動かす。
可変質問の考え方（曖昧な枠だけ追加で聞く、途中の回答で後の設問が変わる、最大数が可変）は5択版と同じ。

## 1. なぜ2種類の設問が要るか

左右の2択だけだと、1領域の中では「Aが多いかBが多いか」しか分からない。
156本のパターンは「両方強い」「両方弱い」「ねじれ（別領域の2傾向が高い）」など **傾向ごとの強さ** も使うので、強さを別の方法で測る。

| 種類 | 形 | 測るもの | 本数（基本） |
| --- | --- | --- | --- |
| W（左右） | 同じ場面で A側の行動 vs B側の行動 | 領域内の優勢（どちらが多いか、どれだけ偏るか） | 8領域×4＝32 |
| X（比較） | 別領域の行動文 vs 行動文（「より自分らしいのは」） | 傾向ごとの相対的な強さ 0〜100 | 16傾向×4／2＝32 |

X は「自分の中でどの傾向が強いか」の順位づけなので、**全員の平均が50付近に固定される**（個人内中心化と同じ性質）。
黙従バイアス（全部に同意）は構造的に消えるが、「全体的に高い／低い」は測れなくなる（→ S16・S17 は三択版では判定しない）。

設問バンクは `js/data/questions3.js`。W は各領域6場面（base 4＋alt 2）＋5択版の対決 Q73〜80（2言い換え）＋D1x〜D8x を差し替え候補に使う。
X の行動文は各傾向4本、組み合わせは `xRounds`（8領域の総当たり7ラウンド：1〜4 基本、5〜6 追加、7 差し替え用）。

## 2. 集計

- 領域 d：`a` = A側を選んだ数、`b` = B側を選んだ数、`n = a + b`（「答えずに進む」は数えない）。
  - `share_t = cnt_t / n`（t の取り分）、`dcnt_t = cnt_t − cnt_other`
- 傾向 t：`m_t` = t を含む X 設問のうち回答した数、`wins_t` = t の文が選ばれた数。
  - `level_t = m_t > 0 ? wins_t / m_t × 100 : 50`（基本4問なら 0/25/50/75/100、追加後は 6分の1刻み）
- エンジンに渡すプロファイル：`{ levels: {t: level_t}, w: {d: {a, b, n}}, quality }`

## 3. 判定（engine3）

閾値 `TH3 = { high: 67, low: 39, domShare: 0.6, domDiff: 2, levelFloor: 37.5, tieScale: 12.5 }`。
高・低の閾値は5択版と同じ値にして、0〜100の level にそのまま当てる（75 は高、50 は中、25 は低）。

### 3.1 優勢の余裕 `wMargin(d, t)`

```
if n < 2:                 return -100            // 未測定
mW = (share_t − 0.6) × 125                      // 3:1 → 18.75, 4:0 → 50, 4:2 → 8.3, 5:1 → 29.2
if dcnt_t < 2:  mW = min(mW, (dcnt_t − 2) × 12.5) // 2:2 → −25, 3:2 → −12.5
return mW
```

優勢の条件は「差が2以上 かつ 取り分0.6以上」。

### 3.2 クロス・特殊で使う優勢 `domMargin3(t)`

```
domMargin3(t) = min( wMargin(d, t), level_t − 37.5 )
```

優勢かつ level が 50 以上（基本4問で 2勝以上）で成立。優勢だが level が低い場合は基本解釈の「弱い版」（B?-1w／3w）だけが成立する。
5択版の「対決で補完」は無い（W 自体が対決なので）。

### 3.3 基本7状態（領域 d、LA = level_A、LB = level_B）

```
mWA = wMargin(d, A), mWB = wMargin(d, B)
tie   = −max(mWA, mWB)                 // 2:2 → 25、3:1 → −18.75
mid(L) = min(L − 40, 66 − L)
1  Aが明確に優勢         min(mWA, LA − 67, 40 − LB)
2  Aが優勢だがBも強い     min(mWA, LA − 67, LB − 40)
1w Aが優勢（弱）          min(mWA, 66 − LA)
3, 4, 3w                 A と B を入れ替えたもの
5  両方強い              min(tie, LA − 67, LB − 67)
6  両方弱い              min(tie, 40 − LA, 40 − LB)
7  場面による            min(tie, −min(LA − 67, LB − 67), −min(40 − LA, 40 − LB), max(mid(LA), mid(LB)))
```

重要度・scale・矛盾枠は `PATTERN_META` の値をそのまま使う。

### 3.4 クロス・特殊

- クロス X??-q：`min(domMargin3(ta), domMargin3(tb))`
- 特殊A（優勢×3）：各 `domMargin3`
- 特殊B（ねじれ）：`高:t` → `min(level_t − 67, level_t − level_pair)`、`中:t` → `mid(level_t)`、`優勢:t` → `domMargin3(t)`
- 特殊C（両方強いの重なり）：`高` 4つに加えて、両領域とも `tie ≥ 0`
- 特殊D（形状）
  - S16 全体的に低い・S17 全体的に高い：三択版では常に不成立（余裕 −1、理由「相対評価のため全体水準は測れない」）
  - S18 相手次第で別人：`tie ≥ 0` の領域数 − 5（8領域中5領域以上が左右拮抗で成立）、scale 2
  - S19／S20：全領域で A側／B側の `domMargin3` の最小値

### 3.5 選択

5択版の `select`（主軸1＋補強1〜2＋矛盾0〜1、同領域の基本は1本、被覆×0.5、包含除外、重なり×0.8、混雑×0.6、矛盾枠2本まで、採用下限0.35）をそのまま使う。
`engine.js` の `select(profile, opts)` に省略可能な `opts.evaluate`（評価関数の差し替え）を足すだけで共用する。既定値は従来の `evaluateAll` なので5択版の挙動は変わらない。

### 3.6 回答品質（三択版）

- `leftRate`：回答したうち左を選んだ割合。0.85 以上または 0.15 以下で位置バイアス警告
- `swapCount`／`skipCount`
- `qualityOk = !(leftRate ≥ 0.85 || leftRate ≤ 0.15)`。三択版では形状判定に使わず、結果画面の注意表示だけに使う

### 3.7 確度

- 領域：`n` と `|a − b|`（2以上なら優勢が確定）
- 傾向：`m_t` と、level が 50 ちょうど（基本4問で2勝2敗）かどうか

## 4. 可変質問（adaptive3）

| 段階 | 内容 | 出す条件 | 上限 |
| --- | --- | --- | --- |
| 1 W基本 | 32問。領域を順繰りに（W1-1, W2-1, …, W8-1, W1-2, …） | 全員 | 32 |
| 2 X基本 | ラウンド1〜4の32問、ラウンド順 | 全員 | 32 |
| 3 W追加 | 左右が拮抗した領域（`dcnt < 2` または `share < 0.6`）に alt → 対決設問の順で追加。1問答えるごとに再集計し、優勢が決まったらその領域は打ち切り | 拮抗した領域 | 領域あたり2、全体16 |
| 4 X追加 | level が 40〜60 の傾向、または `m_t < 3` の傾向を含むラウンド5〜6の組を追加。優勢が決まった領域の傾向（状態1／2／弱の判定に効く）を優先 | 曖昧な傾向 | 傾向あたり2、全体16 |

最大 32＋32＋16＋16＝96問。固定モード（`adaptive=false`）は段階1・2の64問だけ。

「問題を変える」：同じ枠を別の設問に差し替える（W：未使用の alt → Q7x の言い換え → D?x、X：ラウンド7 → 未使用のラウンド5〜6 から同じ傾向を含む組）。
1枠あたり最大2回、その後は「答えずに進む」（未回答として数えない）。差し替え前の設問は集計に入れない。

## 5. 5択回答からの推定（石原・別宮・P1〜P5 を一瞬で見るため）

実回答は5択なので、三択の回答に変換して流す。画面には「5択回答からの推定」と明記する。

- W の base k（k＝1〜4）：領域の A側 k番目の設問と B側 k番目の設問（`questions.js` の傾向ごとの出現順）の回答を比べ、大きい方を選ぶ。同点なら対決 Q7x の向き（3 以外）、それも 3 なら「問題を変える」扱いで alt に進む。alt は対決 Q7x／D?x の回答の向きで決め、無ければ未回答
- X（t vs u、行動文番号 s）：t の s番目と u の s番目の回答を比べ、大きい方。同点なら傾向の4問平均が高い方、それも同点なら左
- P1〜P5（スコアだけ）：W は `scoreA − scoreB ≥ 10` なら a、`≤ −10` なら b、それ以外は a,b,a,b で拮抗にする。X は score の高い方

結果画面では 5択版の選択（`tests/expected_v2.json`）と三択版の選択を並べて、一致・不一致を見られるようにする。

## 6. 設問文の修正点（5択版からの変更）

- W は全て同一場面で A行動／B行動を並べる形に書き下ろした（5択版の A項目と B項目は場面が違うため、そのまま左右に並べられない）
- X の行動文は表現B（行動形）を基本にし、要修正だった Q40（主導寄り）→「そのままにせず自分から再開する」、Q19（分析スタイル）→「話題を今回の出来事だけに絞る」、Q67（二重質問）→「相手の反応が見えないと、連絡して状態を確かめる」、Q32 →「話し合いを終えずに続ける」、Q61 →「その場で顔や言葉に出る」に修正
- 5択版の「一貫性」8問は三択版では使わない（W と X の整合で代替：優勢側の level が対側より低い領域を「要確認」として表示）
