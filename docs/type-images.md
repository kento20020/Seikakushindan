# 傾向の絵（たたき台）

三択診断（`#three`）の結果画面に出す、傾向ごとのイラストの仕組みです。**絵・一言・どの傾向に絵があるかは、`js/data/type_images.js` の1ファイルだけで決まります。**
画面側（`js/ui/type_images.js`）にも、テストにも、絵の数や中身は書いていません（注記の文言は画面側）。絵や文言を直すときに触るのは、`img/types/` の画像と `js/data/type_images.js` の1件だけです。

- 絵は 16傾向（8領域 × 左右）に1枚ずつ。いまは 8枚がそろっていて、残り8傾向は「準備中」（たたき台）
- 結果画面には2か所に出ます。①結果の上の「あなたの傾向の絵」1枚、②「あなたを表す解釈」の下の「8つの軸の絵」（領域ごとに1枚）
- 判定（どの傾向が優勢か、どのパターンが選ばれるか）には一切関わりません。`engine3.js` の結果を読んで、絵を選ぶだけです
- 5択版の画面は変えていません

## 1件のデータ（`TYPE_IMAGES["1A"]`）

| 項目 | 内容 |
| --- | --- |
| `key` / `domain` / `side` / `tendency` | 傾向の識別。`tendency` は `DOMAINS` の名前と同じにする（テストで照合） |
| `motif` | 絵のモチーフ。結果画面で絵の下に小さく出る。未作成は `null` |
| `caption` | 絵に添える一言。未作成は `null` |
| `alt` | 画像が見えない人向けの説明（`<img alt>`）。未作成は `null` |
| `file` | サイトのルートからの相対パス（例 `img/types/1A.jpg`）。未作成は `null` |
| `status` | `"ready"`（`file` があり画面に出せる）／`"pending"`（準備中） |
| `note` | 管理用のメモ（画面には出さない）。例：4B は「前作」 |

画面に出すかどうかは `status === "ready"` かつ `file` があるか（`isReady`）だけで決まります。

## 結果の上の1枚（ヒーロー）の選び方

`heroTendency(profile3, 選ばれたパターン)` が `{ key, reason }` か `null` を返します（`js/data/type_images.js`。画面に依存しない純粋な関数）。`reason` は次の3つです。

| reason | 意味 | 絵の下の注記 |
| --- | --- | --- |
| `"主軸"` | 主軸のパターンが語る傾向の絵 | なし |
| `"代わり"` | 主軸のパターンが語る傾向はあるが、どれも絵が準備中。あなたのほかの傾向の絵 | 「主軸の傾向の絵は準備中のため、あなたのほかの傾向の絵を表示しています」 |
| `"主軸なし"` | 主軸のパターンが特定の傾向を語らない（左右が拮抗する基本パターン・形状）。あなたのほかの傾向の絵 | 「主軸の絵はまだないため、あなたのほかの傾向の絵を表示しています」 |

1. **主軸のパターン**（役割が「主軸」の1本）が語っている傾向を探します（`patternTendencyKeys`）。
   - 基本パターン `B{領域}-{状態}`：状態 1・2・1w は A側、3・4・3w は B側。5・6・7（左右が拮抗する状態）は「その領域のあなたの優勢側」ですが、拮抗なので決まらず、傾向なしになります
   - クロス・特殊パターン：`js/data/patterns_meta.js` の条件に出てくる傾向（クロスは `traits`、特殊は「優勢:」「高:」「中:」の傾向）を、書いてある順に（重複なし）
   - 形状（S16〜S20）は特定の傾向を指さないので、傾向なし
2. 語られた傾向のうち、**あなたが実際に優勢なもの**（左右 W で優勢）を、パターンの順に先頭から見て、**最初に絵があるもの**を出します（`reason: "主軸"`）。先頭の傾向の絵が準備中でも、次の優勢な傾向に絵があればそれを出します（例：主軸が 即応 2A × 追う 3A で、2A の絵が準備中なら 3A）。優勢なものが1つもなければ、語られる傾向すべてを同じ順に見ます。あなたが優勢でない傾向は、優勢な傾向に絵がないからといって「主軸」にはしません
3. 絵がなければ、**あなたの優勢な傾向のうち絵があるもの**から1つ選びます。語られる傾向があるのにどれも準備中なら `reason: "代わり"`、語られる傾向が1つもなければ `reason: "主軸なし"`。順番は次のとおりです
   1. 「弱め」でないもの（優勢（弱）でも、強さの向きが逆でもないもの）が先
   2. 選ばれたパターンが触れている本数が多い領域が先（形状は全領域に触れるので数えません）
   3. 領域番号が小さい方が先
4. 代わりの絵もなければ（あなたの優勢な傾向に、絵があるものが1つもない）、**ヒーローは出しません**（`null`）。主軸のパターンがそもそも無いときも出しません

**準備中の傾向の絵を、ほかの傾向の絵で置き換えて「主軸」とは言いません**（ほかの傾向の絵のときは、注記で分かるようにします）。

### 例（いまのデータ。設問の版 v2 の既定、サンプルは5択回答からの推定）

| サンプル | 主軸のパターン | 語られる傾向 | ヒーロー | reason と理由 |
| --- | --- | --- | --- | --- |
| 石原 | S03 | 2A・4A・7B（あなたは3つとも優勢。どれも準備中） | 8B | 代わり：優勢で絵があるのは 3A・5A・6B（いずれも弱め）と 8B（弱めでない）。弱めでない 8B が先 |
| 別宮 | X38-1 | 3A・8A（どちらも優勢） | 3A | 主軸：先頭の 3A に絵がある |
| P2 | B6-6（領域6が拮抗） | なし | 4B | 主軸なし：優勢で絵があるのは 4B（弱めでない）と 7A（弱め）。4B が先 |

絵が増えると結果は変わります（準備中の傾向に絵が入ると、「代わり」が「主軸」になります）。

## 8つの軸の絵

結果の「あなたを表す解釈」の下に、領域ごと（8領域）に1枠ずつ出ます。`domainTendencies3(profile3)` が、領域ごとのあなたの優勢な傾向のキーと「弱め」の印を返します。

- 絵がある傾向：絵のサムネイルと傾向名
- 絵が準備中の傾向：**同じ大きさの、やわらかい灰色の枠**に「絵は準備中」。傾向名は枠の下に出ます
- 左右が拮抗している領域：「場面によって変わる」の枠（優勢な傾向が1つに決まらないので、どちらの絵も出しません）
- 「弱め」：優勢だが強さがやや弱い領域、または強さの向きが逆の領域（`engine3.js` の `domainFlags3` の `weak` か `conflict`）。傾向名の横に小さく添えます
- 選ばれた解釈が触れている領域の枠は、少し濃い線で囲みます（形状は全領域に触れるので数えません）
- 並び：スマートフォンは2列、画面が広いときは4列

## 出さない場所

テスト協力モード（`?fb=1`）のブラインド比較（「どちらが自分に近い？」）には、絵を出しません。2つの結果のうち、どちらが自分の結果かが絵で分かってしまうためです。
絵が出るのは、結果の本番の画面（`resultView`）だけです。結果のカードを評価する段階（ブラインド比較のあと）では出ます。

## 絵を差し替える・足す

1. 絵を用意する。**960×960 の JPEG（品質84前後・sRGB・メタデータなし、目安150KB以下）** にして `img/types/<キー>.jpg` に置く（例 `img/types/1B.jpg`）。同じキーのファイルがあれば上書き
   ```sh
   # ImageMagick の場合（元画像 1B.png → 960×960 の JPEG）
   convert 1B.png -resize 960x960 -strip -colorspace sRGB -quality 84 img/types/1B.jpg
   ```
   絵の背景は灰色（いまの8枚はほぼ `#c6c1bb`）。枠の色は `css/style.css` の `--ti-bg` で、絵が読み込まれる前や角の丸めで、ほかの色が見えないための色です。背景の灰色を変えたら、この値も合わせてください
2. `js/data/type_images.js` の該当する1件を書き換える
   ```js
   "1B": {
     key: "1B", domain: 1, side: "B", tendency: "距離を取る",
     motif: "…", caption: "…", alt: "…",
     file: "img/types/1B.jpg", status: "ready", note: "",
   },
   ```
   - `motif`・`caption`・`alt` は空にしない（テストで確認します）
   - `file` と `status` の両方を直す（`file` が `null` のまま `status` だけ `"ready"` にしても出ません）
3. `node tests/type_images.test.mjs` を実行する（キーが16個そろっているか、`ready` の絵のファイルが実在するか、文言が空でないか、`pending` の `file` が `null` か）
4. 絵を外すときは、`file: null`・`status: "pending"` に戻す（画像ファイルは消してもよい）

文言だけ直すときは、1の手順は要りません（2のデータの書き換えだけ）。
