## 2. 改善点（重要度順）

### 最重要（商用水準に届かない一番の原因）

**P0-1　開発・検証用の情報が、利用者の画面に出ている**
- 開始：設問の版（v3／v2／v1 と `3choice-2026-10-16` などの内部名）、可変モードの説明、テスト協力のチェック、「サンプルで試す」（80問シートのサンプル2件・P1〜P5）、JSON 読み込み、「5択版との違い」。始めるボタンは画面2枚目の途中にある
- 質問：「W基本 1/32」「X基本」「W追加 あとで決定」などの内部の段階名、「設問 v3」の印、キーボード操作の説明（スマホでも出る）
- 結果：「（サンプルの名前）（5択回答からの推定）」、5択版との比較、各カードの「なぜ選ばれたか：重要度5×充足度1.00（余裕+50…）」、確度低の領域の説明、W追加・X追加の表。結果が画面15.6枚分になっている主な原因
- 相談：「回答：文型」「AI はまだつないでいません」「サンプル：（サンプル2件の名前）」「（試作）」
- 影響：何をすればいいか、自分の結果が何かが一目で分からない。研究ツールの見た目になり、「確か」ではなく「難しそう」に見える
- 直し方：**利用者向けの表示（既定）と開発者向けの表示（`?dev=1`）を分ける**。機能は消さず、開発者向けの表示に移す

**P0-2　視線誘導：いちばん大事なものが最初に見えない**
- 結果：一番上の大きな絵は「関係を戻す」だが、主軸のパターンは「その場で爆発して、その場で終わる」（即応×表に出す×切り分け）。「主軸の傾向の絵は準備中のため、ほかの傾向の絵を表示しています」という注記で補っており、要点がつかめない
- 相談：「次の一手を出す」の前に、あなたのタイプ（4択）→ 相手のタイプ（8問）→ 状況（文章＋9項目）→ 危ないサイン（7項目）が1枚に並ぶ。危ないサインは一番下にあり、「毎回最初に確かめる」（決定 K2）と順番が逆
- 直し方：結果は「主軸の見出し・一言・それに合う絵」を最初の画面に置き、詳しい説明は「詳しく」で開く形にする。相談は危ないサインを先頭へ移す（相談の流れを1画面1問にする作り直しは [ui-ux.md](ui-ux.md) §4 の構造の決定後に行う）

### 高（統一感と使いやすさの土台）

**P1-1　デザインのルール（トークン）がない**
- 実測：文字サイズ49種類（.8rem・.78rem・.82rem・.84rem・.85rem・.86rem…のように細かくずれている）、角丸19種類、色の値40個、余白・間隔186種類
- 直し方：工程2のトークン（下の §3）に置き換える。文字は6段階、余白は7段階、角丸は3段階＋丸

**P1-2　押せる部品が小さい（目標は高さ44px以上）**
- 実測（スマホ）：開始 25個中16個、質問 17個中12個、相談 **103個中63個**が44px未満。例：ヘッダーのリンク 35〜36px、タブ 43px、「← 三択診断へ」17px、相談のチップ 36〜42px
- 喧嘩の夜に片手で操作する想定（U3）では、押し間違いがそのままストレスになる

**P1-3　押せる部品の枠が薄い**
- 実測：区切り線 `--line` が背景に対して 1.27:1、選択肢カードの枠 `--line-strong` が 1.82:1（ダークでは 1.40:1・1.86:1）。WCAG 2.2 では、部品を見分けるのに必要な枠は 3:1 以上
- 相談のチップ、相手のタイプの A／B／分からない、入力欄が、特にダークで背景に溶ける

**P1-4　画像の統一感**
- 8つの軸の絵のうち半分が「絵は準備中」の灰色の枠（決定 D6 のとおりだが、見た目は未完成に見える）
- 絵は `loading="lazy"` で、読み込み中は無地の灰色の四角になる（読み込み中だと分からない）
- 絵の背景（暖かい灰色・生成り）と、UI の背景（紫がかった薄い灰色 `#f4f2f7`）の色味が合っていない
- 直し方：UI の背景を暖かい中立色に寄せて絵となじませる。準備中の枠は、空の灰色ではなく「傾向の名前と短い一言」を置いた統一したカードにする。読み込み中は同じ比率の淡い背景を先に出す

**P1-5　ブランドの見え方が世界観（味方・落ち着き・確か）と合っていない**
- 「16次元診断」「8つの軸の両側から測る」「（試作）」が前に出て、分析ツールの印象が強い
- 相談の答えのカードの見出しに薄いグラデーションの背景がある（不要な装飾）
- 名前そのものは別に決める（ここでは見せ方だけを直す）

### 中

**P2-1　質問画面の情報が重なる**
- 「スワイプで回答」「↑変える」のつまみ、「カードをドラッグ／スワイプでも回答できます」、操作説明の箱、キーボード説明、「この設問の狙い」が同じ画面に重なる。練習のあとの案内（トースト）が操作説明の箱の上に重なって見えた
- 直し方：進み具合は「33 / 約70問」と細いバー1本にする。操作の説明は練習カードで1回だけ出す

**P2-2　PC 幅でヘッダーと本文の左端がそろっていない**
- ヘッダーのロゴは左端66px、本文は276px から始まる。ヘッダーも本文と同じ最大幅にそろえる

**P2-3　アイコンが文字の矢印（← → ↑）で、形がそろっていない**
- 1種類の線のアイコン（線の太さ1.5px、20／24px）にそろえる。SVG をサイトに直接置き、外部の部品は増やさない

**P2-4　ダークモードは使えるが、夜向けに作り込まれていない**
- 主ボタンが明るい塗り（白に近い）で、暗い部屋ではまぶしい。夜は彩度を下げた明るさの控えめな主ボタンにする

### 低

- 足元のリンク（GitHub・テスト集計・旧版）は利用者には不要。開発者向けの表示へ
- `admin.html`（集計ページ）は担当者用なので、トークンの反映だけにとどめる

## 3. デザイン方針（工程2）

### 3.1 方向性

[ui-ux.md](ui-ux.md) の U1〜U8 から：

- **味方**：評価しない言葉、角の丸い柔らかい形、急かさない動き
- **落ち着き**：色数を絞る（主色1・差し色1・意味の色）。暖かい中立の背景。夜のダークを本命として作る
- **確か**：整った余白のリズム、明快な文字の階層。理由や根拠を、決まった部品（「なぜ？」の開閉）で見せる
- 避けるもの：占いの記号、勝ち負けの表現、グラデーション、左の太線つきカード、絵文字

### 3.2 色（役割で定義。値は仮説で、実装時に画面で確かめる）

| 役割 | ライト | ダーク | 使いどころ |
| --- | --- | --- | --- |
| Primary（主要操作） | `#26304F` 夜の藍（文字は白 12.98:1） | `#C9D3F5`（文字は `#151A2E` 11.58:1） | 主ボタン、選択中、進み具合 |
| Accent（特別な強調） | `#A8466F` 紅梅（背景に対して 5.07:1） | `#E79BBA` | 「次の一手」などの見出しの小さな印。1画面に1か所まで |
| Surface（背景） | 紙 `#F6F4F0`／面 `#FFFFFF`／面2 `#EEEAE4` | `#121319`／`#1B1D25`／`#252833` | 背景、カード、入れ子の面 |
| Text | 本文 `#1F2230`（14.38:1）／補助 `#474C5E`（7.76:1）／控えめ `#5F6475`（5.36:1） | `#ECEDF2`／`#C5C8D4`／`#9EA2B2`（7.30:1） | 文字 |
| Border | 区切り `#E3DED6`（飾りの線だけ）／部品の枠 `#868A99`（白に対して 3.44:1） | `#2E313C`／`#7D8295`（4.40:1） | 部品の枠は 3:1 以上を守る |

文字色のコントラストはすべて 4.5:1 以上、部品の枠は 3:1 以上を計算で確認済み（上の数字。面2の上でも 4.5:1 以上）。

### 3.3 文字

- 書体：ゴシック1つ（`system-ui`、ヒラギノ角ゴ、Noto Sans JP の順）。明朝は使わない（例外を作るなら、結果の「一言」の引用だけ）
- 大きさ（スマホ）：12（注記）／14（補助）／16（本文）／18（小見出し）／22（見出し）／28（画面の題）の6段階。PC は見出しだけ一段大きく
- 行間：本文 1.7、見出し 1.4。太さは 400 と 700 の2つ

### 3.4 余白・形・影・動き

- 余白：4px を単位に 4／8／12／16／24／32／48 の7段階。画面の左右は16px（PC 24px）、本文の最大幅 720px（ヘッダーも同じ幅にそろえる）
- 角丸：8（タグ・小さな部品）／12（ボタン・入力欄）／16（カード）／丸（チップ）
- 影：基本は使わず、1px の枠で面を分ける。浮かせるのはトーストと下から出る面だけ（影1段）
- 動き：150〜250ms・ease-out。「動きを減らす」設定では止める。点滅・揺れ・はねる動きはしない

### 3.5 部品のルール

| 部品 | ルール |
| --- | --- |
| ボタン | 主（塗り・高さ52px）／副（枠1.5px・48px）／文字リンク（押せる範囲44px）。1画面に主ボタンは1つ |
| カード | 面の色＋枠1px＋角丸16＋内側16px（PC 24px）。種類は「ふつう」「強調（主色の枠1.5px）」「安全（安全の面）」の3つだけ。左の太線とグラデーションはやめる |
| チップ（選択肢） | 高さ44px以上、枠は部品の枠の色、選ぶと主色の塗り＋チェックの印（色だけに頼らない） |
| 入力欄 | 高さ48px以上（文章は120px以上）、枠は部品の枠の色、フォーカス時は主色の2px の輪 |
| 進み具合 | 細いバー1本＋「n / 約m問」 |
| アイコン | 線のアイコン1種類（線1.5px、20／24px）。サイトの中に SVG を置く |
| 画像 | 正方形の枠・角丸16。読み込み中は淡い面の色。準備中は「傾向の名前＋一言」の統一したカード |

### 3.6 トークンの管理

- **`css/tokens.css` を新しく作り、ここだけを正にする**（ビルドなしのまま）
  - 基本の値：`--c-indigo-900` など
  - 役割の値：`--color-primary`、`--color-surface`、`--space-4`、`--radius-card`、`--font-size-body` など。ライト／ダークは役割の値だけを切り替える
- 今の `css/style.css` などは、役割の値を参照するよう少しずつ置き換える（既存の変数名 `--paper` `--ink` なども、移行の間は役割の値に結び付けて残す）
- 一覧と使い方は `docs/design-tokens.md` に書く。Figma に変数として渡すことも、あとからできる
