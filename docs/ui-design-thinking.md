## 2. 定義：本当に解く問題

### 2.1 ペルソナごとの課題（〜には、〜が必要だ。なぜなら〜）

- P1 美咲には、**送らずに待てる根拠と期限**が必要だ。待つ期限が見えないと、不安が勝って追いLINE を送ってしまうから
- P2 結衣には、**いま動きたい気持ちを止めずに向きを変える一手**が必要だ。「落ち着いて」で止められると反発して電話してしまうから
- P3 彩花には、**読んですぐ使える自然な一言**が必要だ。考えすぎて返事が遅れ、関係を戻す機会を逃すから
- P4 真由には、**返さないことを相手に伝える短い言葉**が必要だ。黙っているのは自分を守るためなのに、相手には無視に見えるから
- P5 ひかりには、**謝る範囲と言葉**が必要だ。全部を背負う謝り方も、何もしないのも、関係を悪くするから
- P6 さきには、**一つに絞って切り出す段取り**が必要だ。繰り返しの不満が一度に出ると、話し合いが長引いて同じことが起きるから

### 2.2 問い（どうすれば〜できるか）

1. 喧嘩の夜、気持ちが高ぶっていても、**3タップ前後で**自分の状況を伝えられるようにするには？
2. 待つ側・待たせる側・自分の番・謝りたい、の**どの立場の人も最初の画面で自分の入口を見つけられる**ようにするには？
3. 文面をすぐ送りたい人に、**理由を読ませてから**送ってもらうには？
4. 「待つ」を**我慢ではなく、やることのある時間**にするには？
5. 診断していない人にも**外れにくい一手**を出し、あとで診断したくなるようにするには？
6. 危ないサインのある人を、**相手を責める気持ちにさせずに**安全の案内へ導くには？

### 2.3 ここから決める設計の原則

- **気持ち → 状況 → 一手** の順。最初に受け止め、次に状況、最後に一手
- **1画面に1つのこと**。選択肢は1画面に最大5つ（ヒックの法則）。それ以上は「ほかの場面」にまとめる
- **理由は短く、文面の前に**。1行目は気持ちを受け止める一文
- **待つ一手には必ず、期限と、手を動かすこと**
- **いつでも直せる**。答えた内容を一手の画面で見せ、1タップで直して出し直せる（決めつけない）
- **安全は最初、傾向と関係なく**

## 6. 案D「書いて、足りない分だけ聞く」（2026-10-17 採用。決定 U14）

持ち主の案：自由記述を最初に出し、その文から項目を機械的に埋め、**項目が足りないときだけ**追加で聞く。案A（場面から）を土台にして、書いた分だけ質問を飛ばす形になる。書かなかった人・短すぎる文の人には、案A と同じく場面から聞く。

### 6.1 流れ

1. **書く**（最初の画面の主役）
2. **安全の確認**（~~毎回~~ → **2026-10-17 の U22 で、危ない兆しがあるときだけ聞く形に変更**。毎回の点検は AI〔Website の安全チェック〕と規則〔端末の中の言葉〕で行い、どの画面にも「危ないときは」のリンクを置く。止め方は Website の決まり〔U19〕。以下の10件の試作は、安全の問を数えていない）
3. **読み取り**：書いた文から、決まった規則で項目を埋める（端末の中だけで処理し、どこにも送らない）
4. **「こう読み取りました」を必ず見せる**：読み取った項目をチップで並べ、違うところは1タップで直せる（読み違いへの備えと、決めつけない決まりのため）
   - **2026-10-17 の U26 で「受け止めと状況の整理」の1画面に変更**：感情の整理（共感。気持ちとどうしたいかを1〜2行）→ 状況の整理（事実だけ。誰が最後に何を送ったか・どれくらいたったか など最大3行）→「ちがうところを直す」（開くと項目ごとに直せる）→［次へ］
5. **足りない項目だけ聞く**：埋まらなかった項目のうち、一手を決めるのに要るものだけ。**場面の問も含めて合計3問まで**。誰が最後に送ったか・言い合いの最中か・意図のどれも分からないときは、まず「場面」（§3.1 の I4）を1タップで聞く
6. **一手のカード**

「いまの気持ち」「どうしたいか」も、**書いた文から分からず、一手に要るときだけ**聞く（書いた文に「謝りたい」とあるのに聞き直すと、「読んでもらえていない」と感じさせるため）。§3.2 の T3（場面＋場面ごとの1問＋気持ち）は、足りないときに聞く問の一覧になる。

### 6.2 「要る項目」の決め方

人が決めるのではなく、判定で確かめる。判定は同じ入力なら同じ一手を出す（決定論）ので、

1. 埋まらなかった項目に、ありうる値をすべて入れて判定を回す
2. 一手が変わるなら「要る」→ いちばん絞れる問から聞く
3. どの値でも一手が同じなら「要らない」→ 聞かない
4. 3問で決まりきらなければ打ち切り、埋まった項目と既定値で判定する

総当たりは遅い（試作で最大2秒強、スマホではもっと遅い）。本番は**局面ごとに要る項目の表**で決め、総当たりはテストの側で「表が正しいか」を確かめるのに使う。

### 6.5 作るときの形（案）

- `js/consult/extract.js`：書いた文 → 項目の一部と、根拠になった言葉（確認の画面で見せる）。正規表現と言葉の一覧。決定論で、DOM なし（node でテストできる）
- `js/consult/needed.js`：埋まった項目 → 次に聞く問（なければ空）。局面ごとに要る項目の表。合計3問まで
- テスト：上の10件と、お手本の相談の文で、読み取り・聞く問・一手を確かめる。総当たりで表が正しいかも確かめる
- 画面：今の相談画面は残し、新しい流れは別の版で足す（CLAUDE.md §3.2）
- AI がつながったら：読み取りを AI に置き換え、失敗したら規則に戻る（`respond.js` が文型に戻るのと同じ考え方）。AI に送るのは書いた文だけで、送ることを画面で伝える

### 6.6 読み取りは「規則＋Clef」（2026-10-17。決定 U17）

- Clef（Cloudflare の決めるためのモデル。`@cf/cloudflare/clef`）に、案D の項目を選択肢つきの質問として約10問、1回で聞く。返ってくる確率が高い項目だけ埋める（基準は仮に 0.8）
- 質問の例（形は公式の例をもとにした目安。各質問に「文からは分からない」を必ず入れる）：
  - `lastSender`（choice）：最後にメッセージを送ったのは誰か → 本人／相手／どちらも送っていない／文からは分からない
  - `elapsed`（choice）：最後のやりとりからどれくらいか → 3時間未満／3〜12時間／半日〜2日／3日以上／書かれていない
  - `partnerLast`（choice）：相手の最後の連絡の種類 → 普通の話題／説明・言い返し／責める・もういい／話し合いの提案／謝ってきた／距離を置きたい／別れ話／来ていない／分からない
  - `ongoing`・`wantApologize`・`wantTell`・`repeat`・`afterMakeup`（noul）、`selfTemp`・`goal`・`cause`（choice）
- 規則と Clef が食い違った項目は埋めずに「分からない」扱いにする。安全の言葉は規則で毎回見る。Clef が使えないときは規則だけで続ける
- 採用はテストのあと（U17）。テストの仕組みは Cloudflare の鍵（環境変数 `CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID`。持ち主が環境の設定で入れる。チャットには貼らない）が届いてから動かす
- 比べた候補（規則／Workers AI の言語モデル／埋め込み／Haiku 5.5／Clef／Clef-flash）の費用・速さ・形の保証・日本語の表は、2026-10-17 の会話の記録（[session-log-2026-10-16.md](session-log-2026-10-16.md) §9）

### 7.1 共感：カードを開いた瞬間に、それぞれが最初に欲しいもの

見えたこと：
1. **最初の画面で要るのは「結論・止める1行・文面（または待つ間）」**。ここまでがスクロールなしで見えないと、P1・P2 が先に送り、P3 が閉じる（U16 の目標のまま）
2. **「伝えたいこと」は P2・P6 に強く効く**が、独立した大きな欄にすると P1・P3 の行動が下に押される
3. **予想とその後は同じ問い（このあとどうなる？）への答え**。分けると欄が増えるだけ
4. **待つ一手の冷たさは、タイマー・預ける・予想で消える**。無料の範囲でも「見通し」が無いと冷たい「待て」になる（Website の検討でも同じ指摘）
5. **危険の兆しがあるときは、軸の欄（伝えたいこと・道のり）を出さない**方が安全

### 7.2 問題の定義

- 慌てている人が、**スクロールせずに**「やること1つ」と「止める1行」と「文面（または待つ間）」を受け取るには？
- 「聞いてもらえた」（伝えたいこと）を、**行動を遅らせずに**見せるには？
- 「待つ」を**選んだ一手**にし、有料の欄が無くても冷たくしないには？
- 危険のある関係で、軸（伝わるまで）が害にならないようにするには？

原則：行動が先、受け止めは短く（U7）。1画面目は4つまで。予想とその後は1つにまとめる。安全は軸より上。押せる物は少なく（コピー・預けるが主、ほかは小さく）。

- **統合3 を推奨**。伝えたいことを独立の欄にせず、見出しの上の小さな1行にすると、P2・P6 の「分かってもらえた」を残したまま、行動の位置は C6 と同じになる。予想とその後を「このあと」1つにまとめ、欄の数を減らす
- **危険の兆しがあるとき（U22 で助言を続ける場合）**は、伝えたいこと・道のりを出さず、カードの一番上に「危ないときは」と窓口を1行置く
- 有料の範囲で予想・［なぜ？］が出ないときも、結論・理由1行・文面／待つ間・その後の場合分けは出るので、カードは成り立つ。予想が有料のときは「このあと」の見出しの位置に、無料の見通しの半行を置けるかを Website の料金の決まりと合わせて決める
- AI をつながない試作では、伝えたいことを「どうしたいか」（仲直りしたい・分かってほしい・決着・距離）と場面から決まった文型で作る（例：「このままは嫌だ、ということ」）。［ちがう］で直せる
