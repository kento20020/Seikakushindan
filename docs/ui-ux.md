## 1. 戦略（誰の、どんな問題を解くか）

| 項目 | 決めたこと | 理由・根拠 |
| --- | --- | --- |
| 中心の利用者 | **恋人がいる20代前後の女性**（U1） | 「彼氏診断」という名前、TikTok・Instagram 中心の集客計画（[marketing-plan.md](marketing-plan.md)）と合う。18歳未満の扱いは未決（公開前に決める。CLAUDE.md §7 の9） |
| 解く問題 | 彼氏との喧嘩の最中・直後に「送る？待つ？何て送る？」が分からず、感情のまま動いてこじらせてしまう | 相談モードの構想（[consult-mode.md](consult-mode.md)）。待つのがいちばんつらいのは追う派・即応派 |
| 主役 | **相談**（U2）。今の状況から次の一手を1つ、理由・文面・待つ時間つきで示す。診断は、その一手を「自分たちに合わせる」ための材料 | 将来の段階拡張でも「Phase 2 AI相談を最初に出す」と決めている |
| 使う場面 | **入口は普段の時間、本番は喧嘩の夜**（U3）。診断は SNS から普段の時間に来て受ける。相談は喧嘩の最中・直後に、夜、片手でスマホを持ち、気持ちが高ぶった状態で開く | 持ち主の回答（選択肢1と2の両方）。気分が違う2つの場面に、それぞれ合う画面が要る |
| 避けたい印象 | **決めつけ・説教される感じ**、**占いのような根拠のない軽さ**（U4）。あわせて「相手を操る・勝つためのアプリ」に見せない（決定 D3・D4 のまま） | 決めつけない文言の決まり（CLAUDE.md §3.2）。相談の助言は根拠がないと信じてもらえない |

### 成功の物差し（案。計測は回答の中身を送らない形で、あとで決める）

- 相談：最後まで進んで一手が出た割合、一手を「やってみる」と答えた割合（[consult-mode.md](consult-mode.md) の「この一手、やる？」）、出るまでの時間
- 診断：最後まで答えた割合、所要時間（いまは6人全員が「長い」）
- 満足：結果やカードの「当てはまり度」、「決めつけられた」と感じた人の割合

## 2. 体験（どんな流れで、どんな気持ちで使うか）

| 項目 | 決めたこと | 理由 |
| --- | --- | --- |
| 入口 | **入口を2つ並べる**（U5）。「いま喧嘩中」→すぐ相談、「自分のタイプを知る」→診断。診断していなくても相談は使え、診断するとあとで一手が自分たち向けになる | 喧嘩中の人に診断（いまは64〜80問）を先にさせるのは遠回り。主役が相談なのに入口が診断だけ、という今のずれを直す |
| 相談の入力 | **まず書いてもらい、足りないところをタップで補う**（U6）。最初に状況を自由に書く欄、そのあと必要なことだけを1画面1問のタップで聞く | 気持ちを吐き出せることが「味方」の第一歩。タップで補えば、判定（同じ入力なら同じ一手）に要る情報もそろう |
| 最初の一言 | **短く受け止めてから本題へ**（U7）。評価しない一言（例：「しんどいですよね。一緒に次の一手を決めましょう」）を出して、すぐ質問に入る。待つときは「待つ間にやること」で支える | 受け止めがないと冷たく、長い受け止めや深呼吸の時間は説教っぽさ・カウンセリングの重さが出る |

### U6 の注意点（AI がつながるまで）

いまの相談は AI につないでいないので、書いた文から状況を読み取れない（読み取るのは危ないサインの言葉だけ。決定 A7）。書いたのにタップでまた聞かれると、「書いた意味がない」と感じさせるおそれがある。対策の案：

1. 書く欄は任意にし、「書くと、あとで読み返せます」「AI がつながると、書いた内容から読み取ります」と、書く理由を正直に出す
2. タップは一手に効くものだけ（最後に送ったのはどちらか、どれくらいたったか、相手の最後の様子、自分の今の気持ち、ゴール）に絞り、残りは「詳しく」にしまう
3. AI がつながったら、書いた文から読み取った答えを先に入れておき、「こう読み取りました。違えば直してください」と見せる（決めつけないため、必ず直せる形にする）

### 画面ごとの気分（想定）

| 場面 | 利用者の状態 | 画面で大事にすること（仮説） |
| --- | --- | --- |
| 普段の時間・診断 | 興味、ひまつぶし、相手との話のネタ | 短く感じる、結果を人に見せたくなる |
| 喧嘩の夜・相談 | 焦り、不安、怒り。片手、暗い部屋 | 1画面に1つのこと、大きく押しやすいボタン、文字入力は最小限、まぶしくない画面、次に何をすればいいかがすぐ分かる |

## 3. 世界観（ブランドの3語）

**味方・落ち着き・確か**（U8）

| 語 | 意味 | 何から守るか |
| --- | --- | --- |
| 味方 | あなたの側に立つ。評価しない、責めない | 決めつけ・説教 |
| 落ち着き | 喧嘩の夜に開いても刺激が少ない。急かさない | 焦りのまま送ってしまうこと |
| 確か | どの一手にも理由がある。根拠と仕組みが見える | 占いのような軽さ |

### 表現の仮説（試作で確かめる。まだ決まりではない）

- 色：落ち着いた藍〜青紫を主にし、あたたかい紅梅を差し色に少しだけ（今の A＝藍・B＝紅梅の2色を活かす）。原色・キラキラは使わない
- 文字：読みやすいゴシックが中心。明朝の見出しは控えめに
- 形：角丸は大きめ（12〜16px）、影は薄く、線で区切る
- 動き：ゆっくり小さく（200〜300ms）。点滅や振動はしない。`prefers-reduced-motion` では止める
- 夜：ダークモードを「おまけ」ではなく本命として作る
- 避けるもの：星座・水晶・タロットのような占いの記号、勝ち負けを思わせる表現（スコア、ゲージ、勝率）

## 4. 構造（決めているところ）

- **トップ**（U12）：案B（相談を大きな1ボタンで主役に、診断は下に控えめ）＋案C の「送ったけど返事が来ない」。骨組みはデザインキャンバス（https://claude.ai/artifact/Ms4NvmoBVorYa17DHvXn4q）
- **安全の確認**（U13）：相談のタップの1問目
- **返事待ち**（[session-log-2026-10-16.md](session-log-2026-10-16.md) §4）
  - 相談の流れ：案A「場面から」（書く（任意）→ 安全 → 場面を選ぶ → その場面に要る1問 → いまの気持ち・どうしたいか）を推奨。案B・C と比べた表は [ui-design-thinking.md](ui-design-thinking.md) §3・§4
  - タップで聞く問：持ち主は「いまの気持ち・どうしたいか」を選んだ。判定には「最後に送ったのはどちらか」「どれくらいたったか」も要るので、場面の選択で補う形（T3）を提案中
  - 次の一手カードの順番：ペルソナで比べて C4（結論 → 理由 → 文面、待つ一手は文面の場所に「待つ間にやること」→ 避けたい言葉 → その後 → 確かさ）を推奨
- まだ決めていないこと：サイト全体の地図（ふたり診断・シェアの置き場所）、結果報告（「送った → 返事が来ない」の続き）の入り方、診断とのつなぎ方（D3「一手のあとに見せる」を推奨）

## 5. 骨格・表層・デザインシステム（未着手）

構造が決まったら、画面の配置（骨格）→ 色・文字・余白・形・動き（表層）→ デザイントークンと部品（ボタン、カード、チップ、入力欄、進み具合）の順に決める。今の `css/style.css` の変数（`--paper` `--surface` `--ink` `--a` `--b` など）を出発点にし、役割（Primary・Secondary・Accent・Surface・Text・Border・Error）に当てはめ直す。

## 6. 検証

- 試作：claude.ai のデザインキャンバスで画面ごとに2〜3案を並べ、方向を決める → 実際のコードに別の版（既存の画面は残す）として入れ、スマホ幅 390×844 と PC 幅 1280×900 で確かめる
- テスト：テスター（20代前後の女性を中心に）に、喧嘩の場面を想定してもらい相談を最後まで使ってもらう。迷った箇所、かかった時間、「決めつけられた」「軽い」と感じたかを聞く
- 品質チェック（毎回）：主な目的がすぐ分かるか、次の操作が明確か、大事なボタンが目立つか、情報が多すぎないか、関連する情報がまとまっているか、統一されているか、スマホで快適か、読み込み中・エラーが分かるか、キーボード操作とコントラスト
